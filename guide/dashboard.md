# 平台总览

“平台总览”是平台管理员和运维的首页，用一页回答三个问题：平台管理的资源用了多少、哪个资源区还有空闲、谁在用。普通用户和项目管理员的首页是“我的总览”。

## 使用信息

| 项目 | 说明 |
| --- | --- |
| 适用角色 | 平台管理员（页面名“平台总览”）、运维（页面名“运维资源概览”） |
| 界面路径 | 左侧导航 **平台运维 › 平台总览**；运维视图为 **运维 › 运维资源概览** |
| 统计范围 | 只统计平台管理的资源；仅监控的资源不计入 |

::: tip 平台管理与仅监控
平台管理：由平台分配和操作的资源，即平台新建、位于“纳管资源”中登记的队列、资源池或区域里的开发机。仅监控：厂商账号里其余可以看到、但平台不能操作的资源。
:::

运维视图与平台管理员视图是同一页面，只是不显示发版状态、超额用户和待审批扩容这三项管理员数据。

## 工具栏

- **站点状态**：“站点：正常”或“站点：维护中”，点击进入[站点维护](/admin/platform#站点维护)。
- **发版状态**（仅平台管理员视图）：“发版：空闲”“发版：部署中”或“发版：状态未知”，点击进入[发版管理](/admin/platform#发版管理)。
- **更新于 hh:mm** 与 **刷新**：“更新于”是页面上最旧一份厂商数据（容量、存储）的采集时间。点“刷新”会重新读取页面上的全部区块，并请平台尽快重新采集各资源区的容量；按钮只在手动刷新时转圈。

厂商数据（容量、存储）由平台定时采集，页面只读取平台已保存的数据，打开页面或点刷新不会直接查询厂商，也就不会因为多人同时查看而拖慢页面。资源区5 的容量约每 15 秒采集一次，其他资源区约每分钟一次。

点“刷新”后，资源区容量右上角显示“采集中”，新数据到达后自动更新，最长等待约 1 分钟。刚请求过采集时“刷新”会暂时禁用，鼠标悬停可以看到原因和剩余秒数；请求过于频繁时也会提示稍后再试。

页面可见时每 30 秒在后台静默更新一次，切到其他标签页时暂停。后台更新保留已有数据，不会清空表格或遮挡页面。

## 指标

| 指标 | 含义 | 点击后 |
| --- | --- | --- |
| 运行中开发机 | 状态为运行中的平台开发机台数；下方显示总台数和异常台数 | 开发机管理（运行中） |
| GPU 占用 / 上限 | 运行中开发机占用的卡数 / 平台管理的队列和资源池上限合计，与队列管理一致 | 队列管理 |
| 训练任务 运行 / 排队 | 运行中与排队中的平台训练任务数；下方显示运行中占用的卡数 | 训练任务管理 |
| 队列任务占用 | 纳管队列和资源池上，运行中的平台开发机与训练任务占用的卡数；下方分开显示开发机和训练各占多少 | 队列管理 |
| 低优先级占用 | 运行中的低优开发机与低优训练任务占用的卡数；下方分开显示开发机和训练 | — |
| 接入节点 在线 / 已配置 | 各资源区接入节点的连接情况 | 平台状态（仅平台管理员） |

六个指标分两行排列，每行三个。“队列任务占用”和“低优先级占用”按平台台账统计，不查询厂商：

- **队列任务**：开发机按它所在的纳管队列或资源池计入；训练任务按平台记录的实际队列计入。只登记了区域的开发机、没有上报队列或队列未纳管的训练任务不计入，鼠标悬停 ⓘ 可以看到这部分卡数。“GPU 占用 / 上限”只统计开发机，和上限比较时请看“队列任务占用”。
- **低优先级**：调度类型为“低优”的开发机和训练任务，不论在哪个队列。低优负载借用队列的空闲卡，需要时会被回收。
- 训练任务的卡数暂时未知时只计任务数，不计卡数；悬停 ⓘ 会写明有几个。
- 平台还没有升级到提供这两项数据的版本时，这两个指标不显示，页面保持原来的四个指标。

读不到的数值显示“—”，不会显示成 0。页面顶部会提示哪些数据暂时无法加载，点“重试”重新读取。训练任务的数据源离线或暂不支持统计时，指标下方会写明原因。

## 资源区容量

每个在“纳管资源”中登记的队列、资源池或区域占一行：

| 列 | 含义 |
| --- | --- |
| 上限 | 厂商上报的 GPU 总量 |
| 厂商已用 | 厂商上报的已用量，包含平台以外的占用 |
| 平台运行 | 平台开发机正在占用的卡数 |
| 空闲 | 上限减去厂商已用 |

读不到容量时，“上限”列写明原因，例如“接入节点离线”“不支持容量查询”“资源不存在”“容量更新中”或“采集中”（平台刚重启、首次采集还没完成，通常几秒后出现数据）。

表格右上角显示容量数据的状态：

| 显示 | 含义 |
| --- | --- |
| 更新于 hh:mm · N 秒前 | 平台最近一次采集到容量的时间 |
| 采集中 | 首次采集尚未完成，或你刚点了“刷新”，新数据还没到达 |
| 数据可能过期 | 超过两个采集周期没有更新，数字仅供参考 |
| 接入节点离线 / 采集失败 | 显示的是最后一次成功采集的数据；鼠标悬停可看到数据时间 |

有多个资源区时，鼠标悬停可以看到每个资源区各自的数据时间。

- 可以按资源区、名称或 GPU 型号搜索，表格分页显示。
- **新建开发机**：打开新建向导，并预选这一行的资源区和队列或资源池。只做汇总的资源池不能直接新建，按钮会禁用。
- **查看开发机**：打开开发机管理，筛选到这一行的资源。

空闲是观察值，不是预留。新建时仍会检查库存、规格、配额和卡时。

## 分配与用量

按“项目”“用户”或“队列”分组，查看平台开发机的运行台数、运行中 GPU 和近 1、7、14 或 30 天的卡时。

- 卡时是按运行记录估算的用量，不是额度扣减；额度见“卡时监控”。
- 可以搜索名称，表格分页显示。
- 点击一行：项目进入项目详情；用户和队列进入开发机管理，并带上对应的搜索或筛选条件。

## 存储

存储只显示一行摘要，明细在“存储管理”：

- **已用合计**：各文件存储已知用量之和，共用的存储只计一次。
- **超额用户**、**待审批扩容**（仅平台管理员视图）：分别进入存储管理 › 个人存储、工单受理 › 云盘扩容审批。
- **存储桶**：按资源区列出桶数，点击进入存储管理 › 对象存储，并筛选到该资源区。

部分资源区数据没有更新时，摘要后面会提示“部分资源区数据未更新”。点 **进入存储管理** 查看完整信息。

## 不在总览里的内容

以下内容在 **平台状态**（仅平台管理员）：

- 接入节点的版本、心跳和权限检查；
- 最近事件；
- 各资源区账户余额；
- 接口监测。

## 常见问题

### 为什么“厂商已用”比“平台运行”大？

厂商已用包含同一资源上平台以外的占用，例如直接在厂商控制台新建的开发机和训练任务。平台运行只统计平台开发机。

### 为什么空闲有卡，新建仍然失败？

空闲只是观察值。规格库存、个人和项目配额、卡时余额以及厂商侧限制都可能拦住新建。失败原因以新建向导的提示为准。

### “队列任务占用”和“GPU 占用”“训练任务”的卡数有什么关系？

“GPU 占用”是运行中开发机的卡数，“训练任务”下方是运行中训练任务的卡数。“队列任务占用”是这两者中落在纳管队列和资源池上的部分，所以通常接近两者之和；差额是只登记了区域的开发机和没有上报队列的训练任务。

### 运维为什么看不到发版状态和超额用户？

发版管理、个人存储超额和云盘扩容审批只对平台管理员开放，运维视图不显示这些数据，也不会读取它们。
