# 项目配额、卡时与费用

::: info 学生新制度与当前功能的区别
已确认的三档学生周额度、成员同意上交、8 卡整节点预付和跨周规则见
[学生卡时与整节点预留](/projects/student-resource-policy)。这些能力已提供实现，需要部署对应版本、启用学生制度并登记整机资源池；
本页说明额度与扣费方式。新开发机默认按「个人卡时 → 项目分配给我 → 项目池待分配」扣费；普通项目训练的项目优先、个人补足不能直接当作预付预留的扣费规则。
:::

项目配额用于限制新的资源请求，卡时用于按 GPU 数量和时间汇总使用量，预算与费用用于观察消耗趋势。三者用途不同，不能互相替代。

## 使用信息

| 项目 | 说明 |
| --- | --- |
| 适用角色 | 项目成员可查看项目用量；项目的负责人和管理员可配置项目双水位配额并分配项目池；平台管理员在「额度策略」设置组织、项目和个人月度额度 |
| 界面路径 | **项目 → 项目详情 → 卡时 / 设置**；个人视图为 **我的总览** 与 **我的用量**；平台管理员在 **卡时 → 额度策略 / 额外卡时审核 / 卡时监控** |
| 前置条件 | 资源已经正确关联到用户或项目；用量采集可用；需要设置配额时具备项目管理权限 |

## 配额、卡时、预算和费用的区别

| 名称 | 用途 | 会不会自动停止已有资源 |
| --- | --- | --- |
| 双水位配额 | 限制新的实例、GPU 或任务请求 | 不会 |
| 周期卡时额度 | 按组织成员或项目池范围限制创建和启动 | 使用项目卡时的开发机余额耗尽会停机 |
| 月度卡时额度 | 兼容按明确月份配置的额度与个人下月借用 | 不会 |
| 月度预算 | 展示估算花费与预算进度，并产生提醒 | 不会 |
| 费用估算 | 帮助比较时间段、成员和 GPU 类型的消耗趋势 | 不会 |

达到预算并不等于达到配额；反过来，配额被拒绝时也不一定已经达到预算。

## 包内、按量和账户余额

实例和存储行上的计费徽标与项目配额是两套口径：

| 你在页面上看到的 | 实际含义 |
| --- | --- |
| 包内 | 包月/专属池资源，不产生现金消耗，也不会触发“余额不足”提示 |
| 按量 | 将产生现金消耗；资源区6 的 SPOT/ELASTIC 档属于此类 |
| 计费未知 | 厂商没有可信计费数据。页面不会把它猜成包内或按量 |
| 账户余额偏低 | 只影响明确的按量操作。资源区1–4、资源区5、资源区6 的包内开发机和包内存储仍然可用 |

平台总览或账单页上的余额可能显示“不支持”“获取失败”或具体金额，这三种状态不要混用。低余额、接口不支持和包内资源售罄是不同问题。

创建向导默认优先包内档位；只有选到按量档时，才会出现“将产生现金消耗”提示。各资源区的计费差异见[厂商与能力差异](/reference/vendors)。

## 理解双水位配额

项目配额同时检查“运行中”和“总提交”两个水位：

- **运行中：** 当前正在占用资源的实例或 GPU。
- **总提交：** 运行中，加上启动中、创建中或排队中的请求。

可以为项目总量和单个成员分别设置以下字段：

| 字段 | 限制内容 |
| --- | --- |
| 运行实例上限 | 同时处于运行状态的实例数 |
| 总提交实例上限 | 运行中及尚未完成启动的实例总数 |
| 运行 GPU 上限 | 运行实例当前占用的 GPU 数 |
| 总提交 GPU 上限 | 运行及待启动请求合计的 GPU 数 |

留空表示不在该字段上限制；填写 `0` 表示不允许产生对应用量。

## 设置项目配额

1. 进入 **项目 → 项目详情 → 设置 › 配额**。
2. 查看当前“项目总量”和“我在本项目”的运行、总提交水位。
3. 点击“设置配额”。
4. 选择适用范围：项目总量或某位成员。
5. 填写需要限制的实例数和 GPU 数，其余字段留空。
6. 点击“保存”。
7. 等待“配额已保存”提示，并在列表中核对新值。

项目请求要同时通过以下检查：

1. 当前用户的个人配额；
2. 项目总量配额；
3. 项目中的成员配额；
4. 已配置时的组织成员和项目周期卡时额度；没有周期策略时再使用兼容月度额度。

任意一项超限，都可能拒绝创建实例、启动实例、重建实例或创建训练任务。停止或释放不再需要的资源后，等待用量刷新再重试。

## 组织与项目周期卡时

普通用户在 **我的总览 → 我的卡时与项目** 或 **我的用量 → 个人额度** 查看当前周期（两处使用同一规则：有组织周期额度时按周期额度，否则按个人月度额度，都没有时显示「未设个人额度（不限）」）：

- 组织额度按成员独立扣减，例如每位成员每周 672 卡时；
- 项目额度由项目成员共享，例如一个项目每半年 20,000 卡时；
- 平台管理员也可选择“按天数”，填写 1–3650 的整数；该周期从保存当天的 00:00（北京时间）起滚动；
- 页面同时显示本期已扣、剩余、进度和下次重置时间；
- 所有周期都在北京时间 00:00 重置。

平台管理员在 **卡时 → 额度策略** 的「组织额度」「项目额度」「个人月度额度」三个页签设置额度；新建时默认为空，开启「不限额」即不限制卡时。组织额度优先于同一用户的个人月度额度，不会重复扣限。

平台管理员可在 **卡时 → 卡时监控** 比较当前用户和项目额度消耗，并设置全局或
项目单独的低消耗提醒。观察天数在当前额度周期内计算，短周期无法完成较长观察时会明确
提示。详见[卡时监控](/admin/platform#gpu-卡时使用监控)。

## 项目详情 › 卡时：上交、分配与收回


项目池中有两部分：**待分配**供项目成员共同使用，**已分配未用**只供指定成员在本项目使用。
成员上交、项目额度和项目额外卡时都进入项目池，可由项目管理员分配。在 **项目 → 项目详情 → 卡时** 点击 **分配**（或成员行的 **分配**），在同一个抽屉里选择成员、执行方式（一次 / 按周期 N 期）、数量和必填的**原因说明**，核对确认摘要后提交。**收回** 也在同一抽屉：一次收回会列出该成员未用的分配批次。原因说明最多 512 字，会保存在记录中。
平台管理员账号不做卡时发放：它不会出现在成员卡时表中，也不能被选为分配对象，周期自动分配会跳过它。平台管理员仍可以给项目组分配卡时。此前已经分配给平台管理员、尚未使用的额度会在下次读取项目池或分配时自动退回项目池；已经用掉的部分不会退回。
「记录」中分配行的 **收回** 只退回尚未使用的部分，随后可分给其他成员；原到期时间不延长，已用卡时不会退回。
项目额外卡时在卡时页的 **申请额外卡时** 提交，由平台管理员在 **额外卡时审核** 核验；这与成员本人确认上交是两个不同的来源。

成员在 **项目详情 → 卡时 → 上交** 填写数量和必填的**原因说明**（1–512 字），原因会保存在记录中。
界面会显示当前可上交余额和北京时间到期时间，提交前会弹出确认摘要。只有项目的负责人、管理员和成员可以上交；项目角色为「只读」的成员和只读账号不可以。

项目管理员在 **项目详情 → 卡时 → 请求上交** 指定成员、数量和必填的**原因说明**（1–512 字）。
**发送请求不会扣款**，平台管理员也不能替成员同意。成员在我的总览看到「有 N 条上交请求待你确认」，
进入项目详情 › 卡时，在「记录」中点击 **同意上交**，核对确认摘要（数量和到期时间）后确认；也可以 **拒绝**。
项目管理员可以撤回尚未确认的请求。拒绝和撤回同样需要确认。

- 状态包括待成员确认、已上交、已拒绝、已撤回、已过期。已处理的请求不会重复扣减。
- 确认时会再次检查成员身份、个人余额和原周期。余额不足时不会上交；项目管理员应重新请求合适的数量。
- 跨周后不能用旧申请扣新一周额度。来源组织或周期发生变化时，应重新发起申请。
- 上交的卡时进入项目池的**待分配**部分，供项目共同使用，不是某位成员的专属余额。
- 个人少多少，项目池就增加多少；不能上交已经用掉或已经上交的卡时。页面保留来源周期、到期时间、已用、已预付占用、已退回和处理记录。
- 上交的卡时最晚在北京时间周一 00:00 到期；来源周期更早结束时，按更早时间到期。
  已过期卡时不结转。当前入口只支持组织发放的个人额度，不能上交项目分配给你的卡时。
- 退出项目、转为只读或项目结项时，未使用、未被预付占用、尚未到期的部分自动退回本人原周期。
  已消费、已预付占用、已到期部分不退；重复修改成员关系不会重复退款。

例如本周个人总额度 672，已用 600，最多上交 72 卡时。上交 60 后个人剩余 12，项目池待分配增加 60。
如果项目用了其中 20 后该成员退出，未到期且未预付占用的 40 会退回，个人剩余变为 52，仍在原周末到期。

项目管理员不能直接扣成员的个人额度，必须由成员本人确认上交。撤回待确认请求不等于取消预留；
[整节点预留制度](/projects/student-resource-policy)中，预留确认后不允许取消退款。

## 项目额外卡时（申请额外卡时 / 额外卡时审核）

原「入账」，即为项目申请额外的卡时。

Zenith 只记录卡时，**不收付款、不处理真实金额或经费，也不向云厂商下单**。
项目的负责人或管理员在 **项目详情 → 卡时 → 更多 → 申请额外卡时** 填写所需卡时和用途，提交申请；提交后不会立即增加余额。
申请本身不增加余额。基础培育项目不会自动获得额外免费项目卡时，成员个人的周额度仍按资格发放。

平台管理员在 **卡时 → 额外卡时审核** 查看待处理申请（可按项目搜索、按状态筛选）。完成线下核验后，填写实际发放卡时、
该笔卡时明确的到期时间、外部核验记录编号或引用、处理说明，再勾选核对确认并提交。
不得在说明中填写真实金额、银行卡或支付信息。实际核验数量可以与申请不同，两者都会保留。
平台管理员也可拒绝申请；项目管理员可撤回尚未确认的申请。被拒绝或撤回后需重新申请。

- 每笔卡时有独立有效期，不因周一到来自动到期；到期未使用部分不可继续消费，历史记录保留。
- 页面分别显示额外卡时、成员上交和项目额度的剩余，并列出每笔已用、已预付、更正扣回和到期时间。
- **确认记录不能直接修改。** 平台管理员通过“追加更正”填写原因和核验引用；增加卡时会生成有新有效期的批次，扣回须选择原批次。
- 只能扣回该笔尚未使用、未被预付占用、尚未到期的余额，不能扣成员上交或其他申请的卡时。
- 例如原确认 100 卡时、更正扣回 10，原记录仍显示 100，新增一条 −10 的更正，未消费时可用余额为 90。
- 重复确认不会再次发放。若提交时网络中断，请先刷新核对已有处理结果。

撤回待核验申请或更正记账，不是取消已确认预留或退款。预留确认后不允许取消退款。
整节点预约须在项目内完成预付确认；已有核验余额不代表取得整节点预约保障。
预留确认后，即使没有运行任务，负责人和项目管理员也会从到期前 8 小时开始每小时收到站内提醒，
到期另发一次通知。提醒不自动续订或退款，也不会为未运行的任务产生欠款。

### 如何理解欠款与抵扣

余额页面已支持显示已记录的欠款和还款结果。个人周期余额、月度余额、成员上交及项目额外卡时
都会先处理该账户的欠款。页面上的可用余额已扣除还款；“实际运行已用”不会再次加上这笔还款。
成员上交和额外卡时批次的“已用”包含还款，明细会单列其中用于还款的数量。

- 例如个人欠 200 卡时，本周获得 168，全部用于还款，仍欠 32；下周再获得 168，先还 32，可用 136。
- 项目欠 50，成员上交 60 后，项目可用 10；若成员随后退出，最多退回尚未到期且未被占用的 10，已经还款的 50 不退。
- 项目欠款由项目后续有效卡时偿还，不改扣成员个人账户。
- 欠款未清偿时暂停该账户新增支出，平台管理员或取消额度配置也不能跳过；已生效预付预约不因此失效。
- 月度兼容额度中的下月借用不能用于提前还欠款，未来月份也不会因被查看而提前发放。

训练的提醒、3 小时宽限及停止流程已接入。普通训练须启用运行区间计量并配置个人额度；预付任务直接使用预约的计量约定。旧计量任务不会自动转换。

## 卡时如何计量

一个 GPU 处于运行状态一小时，记为一个卡时。月度额度按实际 GPU 卡数 × 运行时长扣减，不使用峰谷倍率。创建动作本身不扣卡时，也没有“每次创建至少 1 卡时”的起步单位；删除后重建的两台开发机分别只累计各自实际处于运行状态的时间。

平台管理员启用运行区间计量后，新建训练任务按平台确认的运行区间计量，通常每分钟刷新；结束时按实际起止时间补齐遗漏时段，
跨小时或跨周会分别记入对应时段。缓存中的“运行中”状态不会自行延长这类任务的计费时间。
旧任务保留原计量方式。缺少必要的结束信息或结算失败时，平台继续重试，用量明细可能稍后补齐。
采用运行区间计量的任务，会分别处理同一小时内项目卡时的到账和到期：例如 10:15 到账、10:45
到期的卡时，只能支付这半小时内尚未结算的用量。后来到账的卡时不会改扣已经结算的个人用量。
预付预约期间只统计运行量，不再次扣卡时。普通训练的可用资金耗尽后，从平台确认时开始 3 小时宽限；预付任务则从预约到期开始。

采用新计量方式、配置了个人卡时的运行中训练任务，预计余额在 8 小时内耗尽时会收到站内提醒，
之后每小时提醒一次。同一账号的并发任务合并计算；同账号正在运行的无项目开发机也会计入预测。
实际可用余额为零时会另发一次紧急提醒。补充卡时后会重新计算，不会因为重复查询或平台重启重复发出同一轮提醒。
提醒会显示在右上角通知铃铛，在线时新提醒会自动展开；离线时请在下次登录后查看通知。

预测会随任务数量和卡时变化，不是保证可继续运行的时长。它依据当前周期的余额，不会把未来周额度
或兼容月度透支当作已到账卡时。项目优先任务的预测还会核对其当前项目余额、逐笔到期时间和共用余额的训练占用；
同时存在不同付款方式时采用保守估算，不会把一个项目的余额变成其他任务可花的钱。
已停止、排队或观测过期的任务不用于预测。预付任务另按预约到期时间提醒。
宽限期的实际用量计为欠款，超过宽限截止的用量单独保留核对；后续有效额度先偿还欠款。
个人及项目回退到个人的普通训练欠款由个人承担，项目预付预约到期后的欠款由项目承担。

卡时随实例**启动 / 关机精细结算**：平台约每 5 秒把已观测为运行中的开发机与旧版训练任务按实际运行时长累计到用量中，开机 30 分钟的 4 卡实例记 2 卡时。平台观测到停止状态后便停止累计；实例快照通常约 30 秒一次，训练任务轮询通常约 60 秒一次，因此启停边沿可能有状态同步延迟。页面上的已用卡时可能是小数，并会随结算平滑增长。

所有卡时记录统一按已记账的 GPU 毫秒值汇总。新观测从 0 开始累计，创建、删除或重建本身不会自动记满 1 卡时。

### 先扣项目还是个人

卡时分为三种：**个人卡时**、**项目分配给我**、**项目池待分配**。
新建开发机默认依次使用这三种余额；没有选择项目时，只使用个人卡时。

新建开发机时可以在 **扣费顺序** 选择先扣哪个来源，并勾选或取消 **余额不足时按顺序继续扣减**：

- 勾选：优先使用所选来源，再按个人卡时、项目分配给我、项目池待分配的顺序使用其余来源。
- 不勾选：只用所选来源。余额不足时拒绝开机，运行中耗尽会请求停机，不会扣其他余额。
- 这些设置随开发机保存，后续启动沿用；旧开发机保持原有扣费设置。

**我的总览 › 我的卡时与项目** 为每个项目显示一行「分配给我」和「项目池待分配」；**项目详情 › 卡时** 的「我在本项目」
显示两者之和。已分配给其他成员的额度不计入你的可用合计；项目池已经包含项目额度，不能重复相加。
「分配给我 0」表示你在该项目没有可用的分配额度，可能是尚未分配、已使用、到期或被收回。

成员可以主动上交自己的卡时；项目管理员也可以发起请求上交，但必须由该成员本人同意。
待确认的请求不占用余额。上交后先进入项目池待分配，分配后成为该成员在本项目的专属额度，保留原到期时间。

普通项目训练和旧开发机已有代付授权的扣费规则保持各自口径：

1. 项目分配给本人的卡时。
2. 项目池中成员上交或额外卡时的卡时，优先使用较早到期的部分。
3. 项目额度（周期或月度）。
4. 不足部分自动扣个人卡时。

未选择项目的开发机和标准训练任务，只使用个人卡时。低优训练不扣个人或项目卡时，本周期已用的低优卡时显示在
**我的总览 › 我的卡时与项目** 的个人额度下方。同一份用量只扣一次，不会同时扣个人和项目；
也不会自动使用其他项目或其他成员的专属余额。

例如一笔普通项目训练用量共 2 卡时，分配给我的有 0.5、项目池可用 0.75，则分别扣 0.5、0.75 和
个人 0.75 卡时。项目余额不足不会单独阻止启动，只要个人余额能补足本次检查需求即可。

项目分配给指定成员的卡时（含历史上成员之间的分配），归接收人在该项目的专属余额，**不增加个人余额**。这部分只供本人在该项目
使用，在来源额度周期结束时失效。我的总览和项目详情 › 卡时会单独展示分配给我的余额。
用量趋势展示实际用量；个人额度的「已扣」只包含实际由个人承担的部分。

### 不同 GPU 型号是否使用不同倍率

当前卡时额度使用原始卡时，所有 GPU 型号的额度倍率都是 `1.0×`：1 张 H100、A100、A800 或其他已开放型号运行 1 小时，都扣 1 卡时。GPU 型号的采购价格、包内/按量属性和厂商现金账单是另一套口径，不会改变这里的卡时额度。页面出现的 `1.5×` / `2×` 只表示个人借用下月额度的成本，不是 GPU 型号倍率。

| GPU 型号 | 卡时额度倍率 | 1 张卡运行 1 小时的额度扣减 |
|---|---|---|
| H100 | 1.0× | 1 卡时 |
| A100 | 1.0× | 1 卡时 |
| A800 | 1.0× | 1 卡时 |
| 其他已开放型号 | 1.0× | 1 卡时 |

此表只说明平台额度，不是厂商现金报价；型号是否可选以当前规格目录为准。

每台开发机详情页的状态日志同步记录这笔账：开始计费（含当时剩余额度）、停止计费（本次会话消耗与结算后余量）、以及额度不足导致的启动拒绝，方便逐台核对扣减明细。

### 查看项目卡时

1. 进入 **项目 → 项目详情 → 卡时**。
2. 「项目池」显示待分配、已分配未用和来源分解（成员上交、项目额度剩余）；「我在本项目」显示分配给我和可用共享。
3. 「成员卡时」与「记录」列出每位成员的分配和全部分配、上交、周期计划、额外卡时与历史代付记录，可搜索和筛选。
4. 项目额度显示「未配置」时，项目池只有成员上交和额外卡时；不足部分扣个人卡时。

项目额度不支持透支。项目卡时耗尽后自动使用个人卡时；合计可用额度不足时限制新的受控请求，不会因卡时规则停止正在运行的资源。

### 查看个人卡时

1. 在侧栏进入 **我的用量**。
2. 选择本周期、近 7、30 或 90 天，查看用量趋势和按开发机、训练任务汇总的明细。
3. 「个人额度」与我的总览使用同一规则；若生效的是个人月度额度，会显示有效额度、剩余值和可能的下月透支。

用量趋势按 **UTC 日期**展示，无用量日期保留并显示为 `0`。查询窗口是近若干天的小时范围，首尾日期可能不完整，因此近 30 天可能覆盖 31 个日期。查询失败时显示错误，不会把失败当成零用量。

同类 A100 的厂商名称会统一显示为 **A100**，卡时合计保留原始记录；该显示归一不会修改实例规格或计量口径。

个人额度只有在平台管理员同时配置相邻下月额度并允许透支时，才可能按 1.5 倍或 2 倍成本借用。是否允许及倍率以页面为准，不要把透支视为默认可用能力。

## 查看项目费用和预算

1. 进入项目详情的“概览”，查看“当月花费（估算）”和“月度预算”。
2. 打开“卡时”页签，查看「用量趋势」与「成员卡时」。
3. 选择本周期、近 7、30 或 90 天。
4. 查看按 GPU 类型的趋势和成员用量明细。
5. 当预算进度达到提醒水位时，关注站内通知和项目 Webhook。

预算是观察和提醒工具。超过预算不会自动停止或释放资源，也不保证自动拒绝新请求；真正的准入限制来自配额和卡时额度。

## 费用为什么只能作为估算

Zenith 根据可归属、可采样的 GPU 用量和平台配置的静态价表计算趋势。它可能与最终账单不同，原因包括：

- 用量按周期采集，不是逐秒计费。
- 部分资源类型、厂商指标或历史数据可能无法完整归集。
- 折扣、包年包月、抢占式价格、停机仍收费项目和厂商优惠不一定进入估算。
- 项目标签变更前后的用量可能分别归入不同范围。

::: warning 最终结算以正式口径为准
页面中的“花费（估算）”、预算进度和每日存储估算只用于运营判断。报销、结算和对账应使用平台管理员公布的正式规则或云厂商账单。
:::

## 成功判断与刷新

- 保存配额后，列表出现正确的适用范围和四项上限。
- 发起资源请求前，页面水位低于上限；提交后水位可能短暂延迟更新。
- 卡时页的项目池与「我在本项目」显示最新剩余值。
- 切换用量趋势的时间范围后，趋势和成员表的项目池消耗重新加载。
- 停止或释放资源后，等待页面刷新，再判断配额是否已经释放。

## 风险与常见问题

### 为什么页面预估未超限，提交时仍被拒绝？

页面展示和正式准入检查之间可能存在短暂时间差，也可能有个人、项目总量、项目成员和卡时多层限制。阅读错误提示中的限制范围，再到相应页面处理。

### 为什么停止实例后仍显示占用？

状态和用量是周期更新的。确认实例已停止后，等待片刻并刷新；不要连续重复停止。

### 删除配额行会怎样？

删除后，该范围恢复为未设置限制，而不是继承一个隐藏的零值。个人或其他项目层级的限制仍可能继续生效。

### 项目标签修改会影响历史费用吗？

项目标签用于聚合视图，不转移实例所有权。标签变化后，新采集的用量会按新范围归集；历史展示是否立即变化以页面数据为准。

### 项目结束后如何避免继续产生费用？

归档或删除项目都不会停止资源。请逐项停止或释放不再需要的实例和任务，再检查费用与卡时是否停止增长。项目边界详见[项目协作概览](/projects/overview)。


## 固定周期分配给成员

项目管理员在 **项目详情 → 卡时 → 自动分配**（展开后编辑）：

1. 勾选启用，选择每周、每月或每隔若干天重置。
2. 添加接收成员，填写每人每周期固定获得的卡时数。
3. 选择余额不足时按配置比例分配，或跳过本周期整批分配。
4. 点击 **保存** 并确认，核对显示的下次重置时间（北京时间）。未保存的修改会标记「未保存」，刷新前会提示放弃。

配置从下次重置生效；需要现在分配的，使用 **分配**。每轮先收回上一轮自动分配
中未用的卡时，再从项目池待分配发放新额度。手动分配不受周期设置影响，已消费的不会退回。
自动分配最晚在下次重置时到期；来源余额更早到期的仍按原期限到期。

不足时不会扣个人卡时，也不会自动要求成员上交。离组、停用及只读的成员会跳过。
**最近自动分配结果**显示每位成员的配置数、实际分配数和不足/跳过原因。
部分分配或跳过后，本周期不会因补充余额而反复发放；可手动补分，或等待下次重置。
停用周期设置后不再发新额度，当前轮次的未用部分仍按期收回。


### 按指定结算周期分配、回收或上交

需要“每期 100 卡时，执行 4 期”时，可以使用指定期数：

- 项目管理员：在 **卡时 → 分配** 或 **收回** 的抽屉中选择执行方式“按周期 N 期”；收回只将此前分配给该成员、尚未使用且未到期的项目额度退回项目池。
- 普通成员：在 **卡时 → 上交** 的抽屉中选择执行方式“按周期 N 期”。

填写每期额度和期数（1–52 期），选择包含当前周期或从下期开始，预览每期日期并确认。
分配、回收可选成员或项目的结算周期；个人上交固定使用本人的结算周期。
例如 **100 卡时 × 4 期** 总计划 400 卡时，每期到达时才执行，不提前扣除未来额度。
选择当前周期时，保存后约 5 秒执行第一期。

余额不足时，上交和分配会跳过当期；回收只处理成员在本项目内尚未使用、尚未到期的
分配，不足时按实际可回收量处理。已过期或已消费的额度不能恢复。来源更早到期的仍
保留原到期时间。平台停机错过的历史周期不会补扣。

在 **卡时 → 记录** 查看逐期日期、实际数量和未执行原因，或 **取消剩余期数**。
上交或分配计划从首期开始到末期结束**超过 4 周（28 天）**时，预览会显示警告，
项目管理员和平台管理员在 **卡时 → 记录**（类型「周期计划」）也会看到执行中计划的提示、覆盖天数和起止日期，并可 **取消剩余期数**。
按实际起止时间判断，正好 4 周不提示；1 个 31 天的月度周期也会提示。警告不阻止提交，
请核对原因说明、每期卡时和结束日期。计划取消或结束后，不再显示执行中的超期警告。
在 **卡时 → 记录** 中，单次分配从发放到到期超过 28 天且仍有未用额度时，也会在到期时间旁标记警告。
取消不撤销已执行的账目。成员离组、权限失效或结算周期被修改后，剩余操作会取消，
需要重新预览和确认。按结算周期操作也必须填写原因说明，并在操作记录中保留。个人未来上交必须本人同意，项目管理员和平台管理员都不能代替授权。
