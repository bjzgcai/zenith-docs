# 如何选择合适的镜像

镜像是开发机和训练任务运行环境的基础。选错镜像通常会导致创建失败、训练代码无法运行或性能不达标。本文介绍如何根据代码需求、厂商能力和资源区约束选择合适的镜像。

## 镜像类型与可见范围

Zenith 的镜像按来源分为三类：

| 类型     | 来源                       | 可见范围       | 适用场景                 |
| -------- | -------------------------- | -------------- | ------------------------ |
| 平台镜像 | 平台管理员导入             | 组织内所有用户 | 官方推荐环境，优先使用   |
| 项目镜像 | 项目成员登记               | 当前项目成员   | 团队统一环境，保证一致性 |
| 个人镜像 | 用户自己登记或从开发机保存 | 仅本人         | 个人实验环境、临时测试   |

不同资源区的镜像不互通。新建开发机或训练任务时，只会列出当前选择资源区中已启用的镜像。

## 读懂镜像标签

镜像名称或原生地址通常包含以下信息：

```text
pytorch:2.6.0-cuda12.4-cudnn9-ubuntu24.04
```

| 字段            | 含义              | 注意                               |
| --------------- | ----------------- | ---------------------------------- |
| `pytorch:2.6.0` | PyTorch 版本      | 训练代码应兼容该版本               |
| `cuda12.4`      | CUDA Toolkit 版本 | GPU 驱动需支持该版本；一般向下兼容 |
| `cudnn9`        | cuDNN 版本        | 深度学习框架通常依赖 cuDNN         |
| `ubuntu24.04`   | 操作系统版本      | 影响系统工具和 glibc 版本          |

常见标签模式：

- `devel`：包含编译工具、头文件，适合需要编译 CUDA 扩展的场景。
- `runtime`：仅包含运行环境，体积较小。
- `ubuntu22.04` / `ubuntu24.04`：决定基础系统版本。
- `python3.10` / `python3.11`：部分镜像会标注 Python 版本。

## 匹配 CUDA 与 GPU 驱动

### CUDA 兼容性原则

- 镜像中的 CUDA 版本 **不应高于** 目标 GPU 节点支持的最新 CUDA 版本。
- 通常 CUDA 向后兼容：CUDA 12.x 的镜像可以在支持 CUDA 12.x 的驱动上运行；但 CUDA 11.x 的镜像通常无法在只支持 CUDA 12 的驱动上运行。
- 如果不确定，优先选择较新但稳定的 CUDA 版本，例如 CUDA 12.1、12.4。

### 常见 GPU 与推荐 CUDA

| GPU 型号         | 常见驱动支持             | 推荐 CUDA 版本          |
| ---------------- | ------------------------ | ----------------------- |
| NVIDIA A100      | CUDA 11.0+ / 12.x        | CUDA 11.8 / 12.1 / 12.4 |
| NVIDIA A100 80GB | CUDA 11.0+ / 12.x        | CUDA 11.8 / 12.1 / 12.4 |
| NVIDIA H100      | CUDA 11.8+ / 12.x        | CUDA 12.1 / 12.4        |
| NVIDIA V100      | CUDA 10.2+ / 11.x / 12.x | CUDA 11.8               |

具体支持以页面提示和厂商文档为准。

## 匹配框架与依赖

### PyTorch

- 代码使用 `torch.compile`、`torch.distributed` 等新特性时，选择较新的 PyTorch 版本（如 2.4+）。
- 使用 `DistributedDataParallel` 时，确保镜像中的 PyTorch 与 CUDA 版本匹配。
- 如果代码依赖特定 PyTorch 版本（例如某些模型库只支持 2.1），请选择对应版本。

### 其他框架

| 框架          | 镜像选择建议                                                       |
| ------------- | ------------------------------------------------------------------ |
| TensorFlow    | 选择标注 `tf` 或 `tensorflow` 的镜像，并匹配 CUDA 版本             |
| JAX / Flax    | 选择标注 `jax` 或 `jaxlib` 的镜像，注意 JAX 对 CUDA 版本要求较严格 |
| DeepSpeed     | 选择预装 DeepSpeed 的镜像，或自行在开发机中安装后保存为镜像        |
| vLLM / SGLang | 选择对应推理框架镜像，注意 Python 和 PyTorch 版本                  |

### Python 包管理

- 如果镜像缺少某些包，可以在开发机中安装并保存为镜像。
- 不要把 `pip install` 放在训练任务的入口命令中：每次启动都重新安装会浪费时间和带宽，且容易因网络失败导致任务异常。

## 资源区约束

- 每个资源区只能使用在该资源区登记的镜像。
- 选择某资源区专属镜像后，平台会按该镜像所属资源区路由。
- 如果某个资源区没有可用镜像，可在 **镜像** 页登记个人或项目镜像（资源区5、资源区10），或提交工单请平台管理员导入平台镜像。

## 选择流程

```
确定训练代码/开发需求
    │
    ▼
确定框架版本（PyTorch/TensorFlow/JAX 等）
    │
    ▼
确定 CUDA 版本要求
    │
    ▼
打开镜像页面，选择目标资源区
    │
    ▼
按来源查看：平台 → 项目 → 我的
    │
    ▼
核对标签中的 PyTorch/CUDA/cuDNN/Ubuntu/Python 版本
    │
    ▼
在开发机中验证镜像可用性
    │
    ▼
用于训练任务或保存为团队镜像
```

## 验证镜像可用性

在正式用于训练任务前，建议按以下步骤验证：

1. **创建开发机时选择目标镜像**。
2. **检查关键命令是否存在**：
   ```bash
   python --version
   python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
   nvidia-smi
   ```
3. **运行一次简化版训练脚本**，确认数据路径、依赖和 GPU 访问都正常。
4. **如需调整环境**，安装依赖后保存为镜像，而不是在每次训练任务中重复安装。

## 何时保存为镜像

建议在以下情况保存开发机为镜像：

- 安装了较多非标准依赖或自定义 CUDA 扩展。
- 团队需要统一环境，可以保存为项目镜像。
- 某个官方镜像缺少关键依赖，且需要多次复用。

不建议为了保存少量数据或配置文件而保存镜像。挂载存储中的数据应单独管理。

## 常见错误与排查

### 镜像拉取失败

- 检查镜像地址是否完整，包含仓库域名和标签或 sha256 摘要。
- 确认目标资源区有权限拉取该仓库。
- 私有仓库需由平台管理员提前在云端配置凭据，登记镜像时不需要填写用户名密码。

### 新建时提示镜像不可用

- 镜像可能在该资源区未登记或已被停用。
- 镜像可能属于其他资源区，不能跨区使用。
- 刷新镜像列表，仍不可用时提交工单确认。

### 训练代码报 CUDA 错误

- 检查镜像 CUDA 版本是否高于节点驱动支持。
- 检查 PyTorch 是否编译为对应 CUDA 版本。
- 在开发机中运行 `nvidia-smi` 和 `torch.cuda.is_available()` 确认。

### 镜像中缺少依赖

- 优先在开发机中安装并保存为新镜像。
- 避免在训练任务入口命令中动态安装依赖。

## 团队协作建议

- **统一项目镜像**：由项目管理员或核心成员维护一个项目镜像，所有成员使用同一镜像。
- **版本命名规范**：为镜像标签使用语义化版本，例如 `project-env:v1.2.0`、`team-llama:v20261010`。
- **记录镜像变更**：在 README 中记录镜像地址、包含的依赖版本和适用场景。
- **定期更新**：框架和 CUDA 有新版本时，评估是否升级团队镜像。
