# 通知与公告

通知中心集中展示平台公告、版本发布、发给你的个人事件和所在项目的预算提醒。它适合了解状态变化和风险提醒，但不会代替资源详情页中的最终状态。

## 使用信息

| 项目 | 说明 |
| --- | --- |
| 适用角色 | 所有登录用户；平台管理员还可发布和维护公告；项目的负责人和管理员可配置项目 Webhook |
| 界面路径 | 页面右上角的铃铛图标；铃铛底部“查看全部公告”进入 **公告**；公告管理位于 **服务台 → 公告管理**；项目外部通知位于 **项目 → 项目详情 → 设置** |
| 前置条件 | 正常登录；项目预算提醒需要你是对应项目成员；浏览器允许保存本地站点数据才能记住已读时间 |

## 通知类型

| 类型 | 可能包含的内容 |
| --- | --- |
| 公告 | 平台管理员发布的服务提示、维护提醒或重要说明 |
| 版本更新 | 平台的版本更新记录；普通用户只看到“平台已更新到某版本” |
| 项目动态 | 发给你的开发机、配额、训练任务、迁移审批或文件分享事件，以及所在项目的预算提醒 |
| 卡时提醒 | 训练卡时即将耗尽等个人提醒；平台管理员另可看到当前周期卡时低消耗提醒（需先启用监控设置） |

个人事件有明确的相关用户：开发机新建和配额拒绝对应申请人，开机、关机和删除对应开发机所有者，任务结果对应创建者，迁移审批对应申请人，分享事件对应分享所有者。

- 项目角色为成员或只读的用户只看自己的个人通知，不能查看同项目其他人的创建或任务通知。
- 项目的负责人和管理员还可查看所管理项目内的成员通知，通知中会显示“相关用户”。学生同时加入其他项目时，其在其他项目发生的事件不会因此开放。
- 平台管理员可查看全部事件。项目预算提醒仍由当前项目成员共享。

项目的负责人或管理员被降级或移出项目后，重新打开铃铛会按当前权限读取；原来管理范围内的他人通知不再显示。公告和版本发布仍面向所有登录用户。

通知可能带有“警告”或“严重”标签。看到高等级提醒时，应打开相关项目或资源页面核实，不要只根据通知标题采取破坏性操作。

## 查看通知

1. 点击页面右上角的铃铛。
2. 打开面板时，系统会在后台刷新最近的通知；刷新期间列表保持不变，不会闪空。
3. 查看类型、等级、标题、相关用户、正文摘要和时间（北京时间）。
4. 点击条目直接打开相关资源：开发机回收提醒进入开发机详情，训练任务提醒进入训练任务列表，卡时提醒进入“我的用量”，公告进入公告页并定位到该条。打开的条目会标为已读。
5. 修复问题后，再次打开通知面板检查是否有后续消息。

通知中心最多展示最近一批记录，不能替代长期审计或完整资源历史。刷新失败时面板保留上次的内容并显示“重试”。

平台管理员收到卡时低消耗提醒后，可进入 **卡时 → 卡时监控** 查看当前额度周期、
观察设置和实际消耗。它不会改变额度、停止工作负载或触发项目 Webhook。配置方法见
[卡时监控](/admin/platform#gpu-卡时使用监控)。

## 未读数量和“全部已读”

铃铛上的数字表示当前浏览器认为尚未阅读的通知数量。铃铛的“全部已读”覆盖所有类型（含公告）；公告页的“全部已读”只标记公告，不影响开发机回收和卡时提醒。两边的已读状态实时同步，同一浏览器的其他标签页也会跟着更新。点击“全部已读”后：

- 当前列表的未读样式会清除。
- 通知本身不会被删除。
- 项目事件和公告仍可在列表中看到。
- 资源状态不会发生任何改变。

::: info 已读状态只保存在当前浏览器
已读时间按当前账号分别保存，同一浏览器切换账号不会共用已读状态。退出或切换账号时，通知面板会清空并关闭。已读时间不会同步到其他电脑、其他浏览器或隐私窗口。首次升级到按账号记录已读状态的版本时，或清除浏览器站点数据后，旧通知可能再次显示为未读；在另一台设备上点击“全部已读”也不会影响当前设备。
:::

## 如何处理项目通知

1. 先确认通知所属项目和发生时间。
2. 打开 **项目 → 项目详情**。
3. 对预算或卡时提醒，查看“概览”和“卡时”标签；配额在“设置”标签中。
4. 对开发机或训练任务事件，进入对应资源页检查最终状态。
5. 对迁移审批或失败，进入[文件迁移](/data/file-migrations)查看完整状态和原因。
6. 对分享事件，进入[文件分享](/data/file-shares)核对对象、接收用途和有效期。

项目预算和费用均为估算，处理方式见[项目配额、卡时与费用](/projects/quotas-billing)。

## 平台管理员发布公告

公告页只读，所有人看到的都是已发布的公告；可按标题或正文搜索、按级别（通知 / 警告 / 严重）筛选，正文超出四行时可“展开全文”。平台管理员在公告页右上角点击“管理公告”进入 **服务台 → 公告管理**：

1. 点击“新建公告”。
2. 填写标题、正文和级别。
3. 状态选“已发布”或“草稿”。发布前会再确认一次，因为所有用户会立即看到。
4. 发布后在铃铛或公告页确认公告已出现；表格中的“预览”显示用户看到的样子。
5. 需要撤回时点击“撤回为草稿”或“删除”（均需确认）。

公告正文应避免包含密码、Token、内部访问地址或用户隐私信息。撤回为草稿会阻止继续出现在通知和公告页，但不能撤回用户已经复制或截图的内容。

## 站内通知与项目 Webhook

两者用途不同：

- **站内通知**按个人接收者、项目管理权限或项目预算范围展示，已读状态按浏览器中的账号保存。
- **项目 Webhook**按项目订阅把选定事件发送到外部接收系统，由项目的负责人或管理员配置；个人铃铛的可见范围不会改变已有 Webhook 订阅。

项目 Webhook 属于尽力发送，单次失败后不保证自动重试。接收端应记录事件、验证签名并按事件标识去重。配置方法见[项目协作概览](/projects/overview)。

## 如何判断通知功能正常

- 新通知出现后，铃铛显示未读数字。
- 打开面板能看到通知标题、类型和时间。
- 点击“全部已读”后，当前浏览器的未读数字消失。
- 平台管理员发布公告后，普通用户重新打开铃铛或公告页可以看到该公告。
- Webhook 测试显示成功，外部接收端也确实收到测试事件。

## 风险与常见问题

### 为什么另一台电脑仍显示未读？

已读状态不跨设备同步。请在每个浏览器中分别标记已读。

### 为什么看不到某个项目事件？

普通成员只看自己的个人通知；项目的负责人和管理员可看所管理项目的成员通知。预算提醒需要你仍是项目成员或负责人。升级前无法可靠确认接收者的旧个人通知仅平台管理员可见，项目管理员也不能查看。部分事件还取决于项目是否正确关联资源；重新打开铃铛刷新，最终结果应以资源详情为准。

### 为什么通知说失败，但资源后来成功了？

通知记录的是某一时刻的事件。资源可能随后重试或状态更新，应打开对应资源页查看当前最终状态。

### 点击“全部已读”会关闭告警或停止资源吗？

不会。它只更新当前浏览器的显示状态，不会确认外部告警、改变项目设置或操作任何资源。

### 为什么 Webhook 测试成功，后来事件仍可能丢失？

测试只验证当次发送。接收端临时不可用时，项目事件不保证自动重试，因此应由接收系统提供可用性监控和必要的补偿机制。
