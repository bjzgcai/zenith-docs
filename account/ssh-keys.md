# SSH 密钥

SSH 密钥用于以公钥方式登录支持 SSH 的开发机。Zenith 只保存公钥；私钥必须由你本人安全保管。

## 使用信息

| 项目 | 说明 |
| --- | --- |
| 适用角色 | 使用个人账号登录的所有用户；对已有开发机执行“补注入公钥”还需要相应的开发机操作权限 |
| 界面路径 | 右上角头像菜单 **账号设置 → SSH 密钥**；已有开发机的补注入入口位于 **开发机详情 → 连接** |
| 前置条件 | 账号具有个人身份；需要连接的开发机支持 SSH；网络、开发机状态和密钥登录条件已经满足 |

每个用户最多登记 10 把 SSH 密钥。建议为不同设备分别命名，不要多人共用同一私钥。

## 导入已有公钥

1. 打开 **账号设置 → SSH 密钥**。
2. 点击“导入公钥”。已登记 10 把时按钮不可用，请先删除不用的密钥。
3. 填写可选名称，例如“工作电脑”或“实验室终端”。
4. 粘贴 OpenSSH 单行公钥。
5. 确认内容以 `ssh-ed25519`、`ssh-rsa` 或 `ecdsa-` 开头，而不是私钥头。
6. 点击“导入”。
7. 在列表中核对名称、类型和 SHA256 指纹（点击指纹即可复制）。

公钥格式示意：

```text
ssh-ed25519 <公钥内容> <可选注释>
```

通常应从本机以 `.pub` 结尾的文件复制。**绝对不要粘贴没有 `.pub` 后缀的私钥文件内容。**

## 由 Zenith 生成密钥对

1. 打开 **账号设置 → SSH 密钥**，点击“生成密钥对”。
2. 填写一个能识别用途的名称（留空则命名为 zenith-generated）。
3. 点击“生成”。
4. 立即复制或下载私钥，并记录页面显示的指纹。
5. 把私钥保存在仅本人可访问的位置；在常见系统中应限制文件权限。
6. 确认已经安全保存后，再点击“我已保存，关闭”。私钥窗口不能用 × 或 Esc 关闭，避免误关丢失。

::: danger 私钥只显示一次
Zenith 不保存生成的私钥。关闭生成窗口后无法再次查看，也无法由平台管理员恢复。若没有保存，只能删除该公钥并重新生成一对新密钥。
:::

## 设置默认密钥

第一把登记的密钥通常会显示为“默认”。需要更换时，在目标密钥右侧点击“设为默认”。

默认标记只用于连接命令中的私钥路径提示（对平台生成的密钥生效），不影响公钥注入：Zenith 会注入你当前登记的全部公钥。设为默认不会删除其他公钥，也不会修改已经运行的开发机。

## 密钥何时生效

### 之后新建的开发机

新建开发机后，Zenith 会在开发机进入可连接状态时尝试加入你当前登记的公钥。是否成功还取决于厂商能力、网络可达性、开发机初始化方式和当前资源队列。

不要只根据“开发机新建成功”判断 SSH 已可用。请等待开发机进入运行状态，并在开发机详情中确认出现有效的 SSH 连接信息。

### 已经运行的开发机

新增公钥不会自动写入所有已有开发机。要补充已有开发机：

1. 打开 **我的开发机** 并进入你有权操作的开发机详情。
2. 在“连接”中找到“补注入公钥”。
3. 确认开发机正在运行并具备 SSH 连接条件。
4. 提交后查看注入状态或错误提示。
5. 使用私钥进行一次实际连接测试。

如果按钮不可见，说明当前账号没有操作权限，或该开发机不满足平台 SSH 条件。请联系开发机所有者或平台管理员。

### 停止后重新启动的开发机

通过 Zenith 启动已有开发机后，平台会重新排队注入开发机所有者当前登记的公钥，等待开发机运行后执行。即使 SSH 地址和端口没有变化，也会重新检查并补充公钥；由他人代为启动时使用的仍是所有者的公钥。

请打开 **连接详情 → 我的公钥** 查看状态，或点击该区域的刷新按钮。等待注入成功后再使用个人私钥连接；排队或注入中不代表 SSH 已经可用。如果注入失败，请根据错误提示排查，必要时使用“补注入公钥”。

此机制针对 Zenith 中的启动操作。直接在资源区控制台启动或使用独立的“重启”操作时，仍需确认实际连接和注入状态。

## 删除密钥

1. 在 **SSH 密钥** 列表中确认名称和指纹。
2. 点击“删除”。确认框会写明：之后新建的开发机不再注入它；已有开发机上的公钥需在机内删除。
3. 确认后列表自动刷新，记录消失。
4. 对已经注入该公钥的开发机，登录开发机并从 `~/.ssh/authorized_keys` 中单独移除对应公钥。

::: warning 删除平台记录不会从开发机中撤回公钥
删除只会阻止该密钥参与之后的注入。已经写入开发机的公钥仍可能继续登录，必须在每个相关开发机中清理后才能真正收回访问权限。
:::

## 如何判断配置成功

- 导入或生成后，列表显示正确名称、类型和指纹。
- 设置默认后，目标行显示“默认”。
- 对新开发机或补注入操作，开发机详情显示成功状态。
- 使用对应私钥连接时，不再要求开发机密码，并进入预期账号。

## 风险与安全建议

- 一台设备使用一把独立私钥，设备丢失时更容易精确撤销。
- 私钥不得上传到代码仓库、公开网盘、聊天群或工单附件。
- 生成或导入后核对 SHA256 指纹，防止复制错密钥。
- 不再使用的密钥应同时从 Zenith 和所有相关开发机中删除。
- SSH 是否可用还取决于开发机网络和厂商支持；登记公钥不等于任何开发机都能连接。

## 常见问题

### 为什么导入时提示格式无效？

请确认粘贴的是一整行 OpenSSH 公钥，开头包含密钥类型，中间没有换行，也不是 PEM 私钥内容。

### 为什么新公钥不能登录已有开发机？

已有开发机不会因新增平台公钥自动变化。请使用开发机详情中的“补注入公钥”，或由开发机所有者在机内手工更新授权文件。

### 为什么补注入失败？

常见原因包括开发机未运行、没有可用 SSH 地址、网络不可达、当前资源不支持平台 SSH，或开发机尚未信任平台的连接密钥。根据页面提示处理，必要时提交工单。

### 私钥丢失了怎么办？

私钥无法恢复。请删除对应公钥、重新生成密钥对，并对已有开发机补注入新公钥；确认新密钥可用后，再从开发机中清理旧公钥。

The development CLI supports local public-key import, injection status and interactive OpenSSH connection. See the [CLI SSH workflow](/reference/personal-api#cli-ssh-keys-and-connection) for commands, required token scopes and host-fingerprint verification.

如需通过程序自动操作 Zenith，而不是登录开发机，请阅读[API Token](/account/api-tokens)。
