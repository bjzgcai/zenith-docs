# API Token

API Token 用于让脚本、命令行工具或持续集成任务以你的身份访问 Zenith。Token 按当前保存的权限范围工作，并始终受当前账号和项目权限限制。

## 使用信息

| 项目 | 说明 |
| --- | --- |
| 适用角色 | 使用个人账号登录的所有用户 |
| 界面路径 | 右上角头像菜单 **账号设置 → API Token** |
| 前置条件 | 使用正常登录会话进入页面；准备好安全的凭据存储位置；明确 Token 的用途和所需有效期 |

每位用户最多新建 10 个 Token。默认只读，有效期 90 天，最长 365 天。可按用途选择开发机创建、训练任务提交、启停、改配、SSH、公钥、已分配存储及已授权对象读取、对象上传等权限；手动新增、替换或卸载挂载仅限平台管理员控制台会话，个人 Token 不提供 `storage:mount` 权限。Token 不授予平台管理权限。

## 新建 Token

1. 打开 **账号设置 → API Token**。
2. 点击“新建 Token”。已有 10 个时按钮不可用，请先删除不用的 Token。
3. 填写名称。建议包含用途和使用位置，例如“数据同步”或“自动化构建”。
4. 选择权限和有效期（只能选今天到 365 天内的日期）。训练提交请选择 `jobs:create`，取消任务请选择 `jobs:cancel`，查询本人任务状态和日志请选择 `jobs:read`，跟进回执请选择 `operations:read`，读取已授权对象请选择 `storage:read`，上传对象需另选 `storage:write`。
5. 点击“新建”。
6. 立即复制 Token 明文，保存到密码管理器或自动化平台的加密凭据中。
7. 确认已经保存后，点击“我已保存，关闭”。明文窗口不能用 × 或 Esc 关闭，避免误关丢失。

::: danger Token 明文只显示一次
关闭明文窗口后，Zenith 只显示 Token 的前缀，不能再次查看完整内容。忘记保存时，请删除旧记录并新建 Token。
:::

## 调整权限

1. 使用本人账号登录，打开 **账号设置 → API Token**。
2. 按名称和前缀找到已有 Token，点击“调整权限”。
3. 勾选或移除权限，点击“保存”。至少保留一项；暂停全部访问请停用 Token。
4. 后续请求使用新权限，原 Token 可继续使用，无需更新脚本中的凭据。

例如，AI 助手读取数据集目录时返回缺少 `datasets:read`，可增加“共享数据集目录与文件读取”。上传或维护数据集还需 `datasets:write`，且账号当前具有相应数据集的维护权限。

调整权限不会重新显示明文，也不会改变有效期或自动启用已停用的 Token。Token 不能通过 API 为自己增加权限，必须由本人登录后操作。已受理任务和已签发的临时凭据不因移除范围而立即撤销。

## 在程序中使用

调用 Zenith 时，将 Token 放在标准授权请求头中：

```text
Authorization: Bearer <你的 Token>
```

不要把 Token 直接写入源代码、配置文件、文档或命令历史。优先使用自动化平台的 Secret、受限环境变量或系统凭据库。

Token 会按账号当前状态工作：

- 账号角色调整后，Token 使用新的角色权限。
- 账号被停用后，Token 也不能继续使用。
- Token 被停用、删除或到期后，后续请求会失败。
- 通过 Token 建立的会话不能管理 Token 本身；需要回到正常登录会话操作。

## 查看使用情况

列表中会显示：

| 字段 | 含义 |
| --- | --- |
| 名称 | 新建时填写的用途标识 |
| 权限 | 当前权限，可由本人登录后调整 |
| Token | 仅显示前缀，用于区分记录，不是完整凭据 |
| 状态 | 当前是否启用；已过期的显示为关闭并标注“已过期” |
| 过期时间 | 到期后凭据自动失效 |
| 最后使用 | 最近一次成功识别到使用的时间，可能有短暂刷新延迟 |
| 创建时间 | Token 创建时间 |

列表支持按名称搜索、按状态（启用 / 已停用 / 已过期）筛选。点击“刷新”可重新加载列表。第一次使用后，“最后使用”不一定立即变化，可稍后再刷新确认。

## 停用、重新启用或删除

### 临时停用

1. 找到目标 Token。
2. 关闭“状态”开关，在确认框中点击“停用”。
3. 等待“已停用”提示。
4. 使用该 Token 的新请求应立即失败。

需要恢复时重新打开开关。已过期的 Token 开关显示为关闭且不可操作，需要新建。停用期间不要新建同用途的重复 Token，除非确实需要轮换。

### 永久删除

1. 核对名称、前缀和最后使用时间。
2. 点击“删除”，在确认框中再次点击“删除”。
3. 刷新列表，确认记录已消失。
4. 同时从所有脚本、凭据库和自动化任务中删除旧值。

删除后不能恢复，使用该 Token 的调用会立即失效。

## 推荐的轮换方法

1. 先新建一枚有明确到期时间的新 Token。
2. 更新使用方的安全凭据。
3. 运行一次最小验证任务。
4. 在列表中确认新 Token 的“最后使用”已经更新。
5. 停用旧 Token 并观察相关任务。
6. 确认没有遗漏后删除旧 Token。

这种方法可以减少直接删除仍在使用的 Token 导致任务中断的风险。

## 风险提示

- Token 默认只读；写操作必须选择对应范围，并通过当前账号权限校验。
- `jobs:read` 包含本人训练任务日志，已有该范围的 Token 也可读取。日志可能含有程序打印的敏感信息；只向确实需要任务输出的工具提供此权限。
- `storage:read` 也包含当前项目/公共绑定内的对象列表和下载，已有该范围的 Token 同样获得这些读取能力。对象上传必须另选 `storage:write`，且账号不是只读账号，并具有可写存储授权。已签发的对象 URL 在到期前可能继续有效，撤销 Token 不会立即撤销这些 URL。
- 查看本人项目选择 `projects:read`。签发存储桶临时凭据还需同时选择 `storage:read`、`storage:write`、`storage:sts`，并已有整桶读写授权；默认 15 分钟，最长 12 小时。旧 Token 不会自动获得新增范围。
- 已有 Token 的权限由本人登录后通过“调整权限”修改；始终受账号、项目和资源授权限制。
- 不要在截图、日志、报错信息或聊天消息中展示完整 Token。
- 怀疑泄漏时应立即停用或删除，不要等待排查完成。
- Token 不能代替 SSH 私钥；连接开发机请使用[SSH 密钥](/account/ssh-keys)。

## 常见问题

### 为什么只能看到 Token 前缀？

完整明文只在创建成功时显示一次。前缀仅用于识别记录，不能用于调用。

### 为什么 Token 突然没有权限？

请检查 Token 的权限范围、账号角色、项目成员关系、状态和过期时间。已有 Token 不会自动获得新增权限范围；同一已授予范围可随接口扩展提供新功能，例如 `jobs:read` 现包含本人任务日志。需要新增范围时请登录后点击“调整权限”。完整接口见[个人 API 与 AI 接入](/reference/personal-api)。

### 为什么无法在脚本中创建或延长 Token？

使用 Token 认证时不能管理 Token 本身，这是为了避免泄漏凭据自我续期。请使用正常登录会话进入管理页面。

### 达到 10 个上限怎么办？

先按名称、最后使用时间和过期时间清理不再使用的记录。不要为了复用而把同一 Token 分发给多个无关系统。
