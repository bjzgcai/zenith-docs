# 认识 Zenith 中的资源

Zenith 把不同云厂商的资源放进统一控制台，但不会抹去它们原有的区域、容量、权限和产品边界。理解资源之间的关系，可以帮助你更快地完成创建、连接、训练和数据流转操作。

## 一张图理解资源关系

```text
云厂商
└── 地域 / 可用区
    ├── 资源组 / 队列 / GPU 卡池
    │   └── 规格（CPU、内存、GPU 型号与数量）
    │       ├── 开发机或计算实例
    │       ├── 训练任务
    │       └── 推理服务
    ├── 镜像与模型版本引用
    └── 对象存储 / 文件存储 / 个人文件

项目 ── 聚合成员、实例标签、训练任务、模板、配额、预算和用量
个人 ── 保持实例、模型、文件等资源的所有权与敏感操作边界
```

这是一张帮助理解的通用关系图。不是每个云厂商都会同时提供图中的所有资源类型，页面上的实际可选项和能力提示才是当前环境的准确信息。

## 核心资源名词

| 名词 | 它表示什么 | 使用时关注什么 |
| --- | --- | --- |
| 云厂商 | GPU 资源的实际提供方 | 厂商能力、账号权限、区域和网络条件可能不同 |
| 地域与可用区 | 资源所在的地理区域和基础设施分区 | 镜像、规格、存储和网络通常受地域约束 |
| 资源组 | 厂商侧组织一组计算容量的逻辑范围 | 只在部分厂商或产品模式中出现，关注状态、容量和到期时间 |
| 队列 | 可供任务或实例使用的计算配额池 | 关注 GPU 型号、可用区、余量、共享方式和适用负载 |
| GPU 卡池 | 按 GPU 型号或容量汇总的资源视图 | 余量会变化，且与实例占用、共享超卖等统计方式不同 |
| 规格 | 一份计算资源配置 | 核对 CPU、内存、GPU 型号、GPU 数量和计费徽标 |
| 实例 | 一台可运行开发环境或计算负载的云端资源 | 关注状态、**厂商实例 ID**、个人所有者、项目标签、连接方式、镜像和“包内 / 按量 / 计费未知” |
| 厂商实例 ID | 云厂商侧的稳定资源编号 | 启动、停止、SSH、监控、终端、镜像构建都用它；不要和 Zenith 台账内部编号混淆 |
| 训练任务 | 按参数提交并由平台或厂商执行的训练工作负载 | 关注项目、镜像、命令、资源、输出、日志入口和最终状态 |
| 推理服务 | 持续提供模型推理能力的部署资源 | 关注模型版本、实例数、状态和服务访问方式 |
| 镜像 | 创建实例或任务时使用的软件运行环境 | 按资源区分为个人、项目和平台镜像；创建时核对所有权、项目成员身份或平台启用状态，仓库拉取权限需要另行满足 |
| 模型 | 模型资产及版本的登记信息 | 模型只有“仅本人”和“平台共享”，当前不提供项目共享 |
| 存储与文件 | 保存数据、代码、模型或迁移中间文件的资源 | 关注地域、容量、挂载方式、权限和生命周期 |
| 项目 | 成员协作、预算、配额、模板和用量的聚合范围 | 项目标签不转移实例所有权，也不是租户隔离边界 |

## 创建计算资源时如何理解选项

在总览点击 GPU 型号，可查看对应开发机。型号只在一个资源区时会自动选中该区；
分布于多个资源区时显示全部相关资源。再次切换型号会同步资源区并清除上一次的队列、
状态等筛选，避免旧条件遮住新的查询结果。

普通用户在工作台只选择 GPU 型号、卡数和资源区，厂商、队列与资源组由平台按平台管理员配置的路由决定，
页面不会显示这些底层信息。下面按专业向导（**开发机管理**）的顺序说明，便于理解选项来源：

1. **选择云厂商。** 决定资源从哪里创建，也决定后续可用的地域、规格和功能。
2. **确认所属项目。** 项目用于聚合预算、配额、模板、通知和用量，不会替代创建者的资源所有权。
3. **选择地域或可用区。** 地域会约束可用规格、镜像、网络和存储。
4. **选择资源组或队列。** 仅专业向导会显示；普通用户看不到这一层，只需确认资源区。需要时核对状态、GPU 型号、可用区和剩余容量。
5. **选择规格。** 核对 CPU、内存、GPU 型号和数量，不要只看规格名称。
6. **选择镜像。** 从当前资源区本人可访问的个人、项目或平台清单中选择；仍需确认目标环境具有拉取权限。
7. **选择数据或存储。** 挂载路径、地域和访问权限必须与工作负载匹配。
8. **检查费用与限制。** 提交前确认计费方式、项目及个人配额、卡时额度和可能的不可逆操作。

不同厂商的页面可能省略其中一些步骤，也可能要求额外参数。请始终以当前页面展示的字段、能力提示和校验结果为准。

## 实例状态与数据新鲜度

实例列表是 Zenith 最近一次观察到的资源记录。不同资源类型使用的状态并不完全相同，常见含义包括等待中、创建中、运行中、停止中、已停止、释放中、成功、失败和未知。

请特别注意以下情况：

- **操作刚提交：** 云厂商正在处理时，状态不会立即变化。
- **陈旧：** Zenith 曾经观察到该资源，但最近没有再次确认；详情页会在“台账新鲜度”中提示，这不等于资源已经被自动删除。
- **厂商连接不可用：** 当前无法刷新对应厂商的数据，也可能无法执行操作。
- **能力不支持：** 当前厂商、产品模式或区域没有提供该功能。
- **权限不足：** 当前平台角色、项目关系、资源所有权或云端权限不满足要求。
- **获取失败：** 网络、厂商服务或参数错误导致本次请求失败，可以根据页面提示重试或联系平台管理员。

::: tip 避免重复操作
创建、启动、停止或释放后，请先观察提示和状态变化。连续重复点击可能产生多个请求；如果状态长时间没有更新，记录厂商、资源名称、资源 ID、操作时间和完整错误提示，再联系平台管理员排查。
:::

## 镜像与模型不是同一种资产

镜像提供运行环境，模型记录训练或推理使用的模型资产与版本。两者的可见范围与共享方式不同：

| 资产 | 仅本人 | 项目共享 | 平台共享 |
| --- | :---: | :---: | :---: |
| 资源区登记的镜像 | 支持个人登记 | 支持项目成员使用 | 平台管理员导入平台镜像 |
| 「模型」页的模型 | 支持 | 不支持 | 支持 |

资源区5 和资源区10 允许用户登记个人或项目镜像，平台镜像由平台管理员统一维护。项目镜像只对当前项目成员可用，移除登记后不能再通过此登记创建资源。模型共享范围只能扩大，通常不能撤回。“在 Zenith 中可见”不代表镜像仓库或底层存储已经授予读取权限。

详情见[镜像](/assets/images)和[模型](/assets/models)（公开模型在「模型」页按可见范围筛选）。

## 文件与存储

Zenith 中的文件入口可能对应不同底层资源：

- **个人存储 / 项目存储**属于文件存储，分别挂到 `/personal_fast_storage` 和 `/project_<identifier>`，不是存储桶。网页浏览需要平台服务或一台已挂载该存储的运行中开发机。
- **挂载盘**是平台管理员登记并分配的现有云端存储卷，新建时可勾选；资源区6 的开发机可在重启后追加。
- **对象存储**只显示平台管理员绑定到项目或公共范围的桶前缀；不能自己填写桶名。
- **文件存储**（管理侧统称）按文件系统和存储单元组织，平台管理员和运维在 **存储管理 → 文件存储** 查看。
- **文件分享**为符合条件的对象生成限时下载链接。删除分享记录后，已经发出的链接仍在原到期时间前有效。
- **跨区传输**（存储管理 → 跨区传输）用于在支持的资源区间迁移普通文件或目录树。
- **数据快传**生成临时上传地址和资源区6 下载命令，适合把本地单文件快速送入资源区6 开发机。

跨区传输支持普通文件和目录树；目录会保留相对路径，最多处理 1,000 个普通文件，符号链接会被跳过，大文件会自动分片。源路径和目标路径必须能够被当前环境的迁移服务直接访问，填写厂商实例 ID 不会自动把开发机内部目录暴露给迁移服务。提交前请确认相关存储已正确挂载、源文件可读且目标目录可写。

## 项目、配额与费用

项目不是云厂商的资源层级，也不是独立租户。它用于组织成员、实例标签、训练任务、模板、预算、配额、月度卡时和用量视图。

实例仍以个人所有者作为敏感操作边界。项目的负责人或管理员可以管理项目设置，并在具备平台操作权限时对项目内实例执行有限的启动、停止和重启；终端、文件迁移、删除、重建和规格变更不会仅因项目角色而开放。

配额通常限制可以创建或启动的资源规模。达到限制时，平台可能拒绝新的请求，但不会因此自动停止已经运行的资源。月度卡时额度也只影响新的创建或启动请求。

费用和用量页面用于帮助判断消耗情况。当前费用主要依据采样卡时和平台管理员维护的静态价表估算，不等同于云厂商账单或发票。实例上的“包内”徽标表示不产生现金消耗，也不看账号余额；“按量”才会烧现金；“计费未知”不要猜成免费或按量。最终结算以平台管理员公布的规则和云厂商账单为准。

::: warning 释放与共享前先确认影响
释放实例可能导致无法恢复的数据丢失；扩大模型的共享范围通常不可撤销。执行前请确认重要数据已经保存到持久存储，并仔细阅读页面确认信息。
:::

## 项目子队列

平台管理员可在 **队列管理 → 队列配置** 的「项目保障」中，为某个项目分配父队列的保留卡数。
例如父队列有 56 卡，给项目保留 8 卡：项目尚未使用时，其他项目的一般任务最多使用 48 卡；
低优工作负载可借用空闲的保留卡数。同一父队列的一般任务排队且空闲 GPU 不足时，平台会先向
低优开发机所有者发送站内回收预告，预留至少 **15 分钟**保存 checkpoint 和工作进度；配置和账号
绑定可用时也会尝试发送钉钉私信。请以预告中的最早关机时间为准，钉钉发送或阅读状态不会延长
宽限。到期再核对需求、容量和实例身份。需求消失、容量恢复或核对失败会取消本次回收，再次触发时重新预告。

**低优开发机即使正在运行训练，也可能在预告期结束后被停止。** 新建开发机默认选择“一般”，训练任务默认选择
“标准任务”；一般开发机不会因这项队列规则被回收。平台管理员另行开启的[低利用率规则](/compute/instances#低利用率自动关机)
有独立的监控与活动保护，监控未知不会成为关机依据。

资源区5 的低优训练任务由厂商执行原生抢占，**不享有平台 15 分钟预告保证**。需要持续运行的训练应
保持“标准任务”，并定期将输出与检查点写入已经确认可用的持久存储。

子队列只管理从本平台提交的任务。直接在云厂商控制台提交的任务不受平台准入限制。
保留的是算力使用额度，不会共享项目存储或改变文件权限，也不增加父队列的已购容量。
将保留卡数改为 0 可取消该项目的保留额度。
