# 训练任务

::: tip 新用户请先阅读快速开始和最佳实践
如果你是第一次提交训练任务，建议先阅读[训练任务快速开始](/workloads/training-quick-start)，了解从零准备数据、选择镜像、填写启动命令并提交任务的完整流程。日常使用和优化可参考[训练任务最佳实践](/workloads/training-best-practices)。
:::

::: info 学生训练与整机预留
组织启用学院学生周额度后，学生可以不选项目创建低优训练。当前正式项目成员还可以提交标准任务；低优训练不扣个人或项目卡时，仍可能被抢占。
整节点预约（实验性功能）、预付、宽限和欠款已提供实现，需要部署对应版本并由平台管理员登记整机预留池。使用步骤见[学生卡时与整节点预留](/projects/student-resource-policy)；加入项目不代表已经取得预约容量。
新计量的一般项目任务先使用项目卡时，再回退到个人卡时，两边额度均耗尽后从平台确认时进入 3 小时个人宽限。预付预约内不重复扣卡时，到期宽限的欠款由项目承担。
:::

“训练任务”用于提交批量训练工作负载，并查看任务状态、日志、监控、节点和诊断信息。训练能力只在当前厂商、计算模式和平台管理员配置支持时可用；页面上的能力提示是当前环境的准确信息。

## 任务名称

任务名称支持 1–128 个字符，可使用中文、英文字母、数字和常用标点；内部及末尾空格原样保留。名称不能以空白开头，也不能包含换行、制表符或其他控制字符。新任务使用平台独立生成的 16 位云端名称，仅含小写英文字母和数字；任务列表、详情和复制配置继续使用您填写的名称。已有任务保留原名称，重复名称不会改变任务归属或权限。

| 项目                           | 说明                                                                                             |

普通用户不选择厂商、队列、资源池、Flavor 或可用区，只选择平台管理员分配给组织的 GPU
型号与卡数。平台管理员视图和运维视图另可 **按厂商参数新建**，并使用高级控制字段。

## 创建前准备

在打开创建窗口前准备以下内容：

- 当前组织至少获得一个标记为可创建训练任务的逻辑算力规格。
- 所选资源区有本人可用的个人、项目或平台镜像，并满足训练任务的运行要求；平台镜像须保持启用。
- 启动命令已经在同一镜像中验证，不包含明文凭据。
- 未加入项目也可提交个人训练任务，无需先启用学生制度。选择项目时须有该项目的写入权限；启用学生制度的账号只有实际参加基础培育或自由探索项目时，才有标准任务资格。
- 有足够可用卡时和资源。学生训练不受开发机的每人 2 卡或成员并发限制；项目总量限制仍需满足。
- 训练数据和输出使用的对象存储或文件系统已经准备完成。

::: warning 创建任务会使用真实计算资源
非 仅校验 提交可能立即占用 GPU。标准任务消耗卡时；低优训练不扣个人或项目卡时，仍记录实际 GPU 用量。节点数和多角色配置会放大资源总量，提交前必须逐项核对。
:::

## 每人并发卡数与等待队列

百度和火山的纳管训练队列中，**标准任务**默认每人最多同时使用 **64 卡**，个人任务和项目任务合并计算。
云端正在创建、排队中的任务也会预留卡数，避免多个任务同时启动后超过上限。
超出上限仍可提交，会显示在 **等待提交** 标签页中；额度释放后自动提交到云端，无需重复创建。
单个任务超过上限时，需要平台管理员提高该队列的上限后才能启动。

平台管理员可在 **队列** 页面修改“每人标准训练 GPU 上限”，保存后对后续标准任务调度生效。调低上限不会停止已运行的标准任务。
等待期间可取消自己的任务；显示正在提交后，请等待云端任务出现再使用停止操作。
若账号、项目或镜像权限发生变化，平台会重新检查并展示不能启动的原因。

### 低优任务如何分享空闲资源

百度和火山纳管训练队列中的低优任务使用独立的份额规则，不受上述标准任务的 64 卡上限限制。
每个队列单独分配可供低优训练使用的容量；不同队列或资源区的卡数不会拼接。

- 只有一人有需求时，可以借用全部空闲卡数。有其他人加入后，按用户均分；某人需求较少时，将其用不完的部分分给其他仍有需求的人。
- 以每人 **32 卡**为基础份额；需求不足 32 卡时按实际需求，可分配容量本身不足 32 卡时按该容量。按顺序分配基础份额，不足以安排下一人时，后续用户等待。已经进入本轮分配的用户继续均分余量。
- 顺序按用户**本轮首次有低优任务需要运行的时间**确定。有运行或等待中的低优任务就保留本轮位置；全部结束或取消后退出，下次提交重新排到末尾。

例如，可分配容量为 320 卡且每人都有足够需求：A 独占时可用 320 卡；B 加入后各 160 卡；
10 人时各 32 卡；第 11 人等待前面的人结束或需求减少。

份额下降时，平台可以停止占用超额份额的**整个低优任务**，确认停止后按原 GPU 申请数自动重新排队。
例如，64 卡任务不会拆成两个 32 卡任务；当前份额只有 32 卡时，这个 64 卡任务需要继续等待。
分配份额不代表一定能立即启动，实际任务大小、节点可用性和资源释放进度仍会影响调度。

自动重新排队会再次执行原命令，并保留原申请卡数，**不等于自动从上次进度恢复**。
训练程序须自行把检查点写入持久存储，并在启动命令中处理恢复；尚未保存的进度会丢失。
在 **等待提交** 标签页中查看等待原因，或取消不再需要的任务。

## 取消提交

在 **等待提交** 标签页中，任务提交人或平台管理员可以取消不再需要的提交（标签页内可在 **等待提交 / 提交中** 之间切换）：

- **等待提交**：点击 **取消提交** 并确认。取消成功后，该任务退出等待列表，不再自动提交到云端。
- **提交中**（包括 **结果待确认**）：点击 **取消提交** 并确认。平台先保存取消请求，页面显示 **已申请取消，确认后自动停止**；云端任务身份确认后，平台会自动发起停止请求。

**已申请取消不等于云端任务已停止。** 创建结果仍未知时，记录和卡数预留会保留，刷新页面不会撤销取消申请，也不会重复创建任务。云端任务确认后，可在任务列表查看后续状态；如果长时间无法确认或提示取消请求失败，请提交工单核查。

## 提交失败后

**提交失败** 标签页里的记录不会自动重试，也不占用等待名额或卡数预留。打开该标签页可以查看失败反馈。提交人或平台管理员可以选择 **复制并重新配置**。保存过创建配置时，窗口会填入当时提交并失败的配置；没有保存完整配置时，窗口仍会打开，并显示失败记录里保留的名称、资源区、队列、卡数和调度，同时说明完整配置未保存。核对并补填后提交为一条新任务。

如果创建窗口当场拒绝提交，失败反馈会留在窗口里，已填写的配置不会被清空。按反馈修改后选择 **重新提交**。

## 查找和查看任务

页面从上到下依次是：工具栏（项目管理员的 `我的 / 项目` 范围切换；运维的 `平台任务 / 云端其他任务（只读）` 分段；右侧 **新建训练任务**）、状态概览条（**等待提交 · 排队中 · 运行中 · 失败**，点击即按该状态筛选）和标签页 **任务 | 等待提交 | 提交失败**。

任务列表支持：

- 按名称或任务 ID 搜索（服务端搜索全部任务），按资源区、状态筛选；平台管理员视图和运维视图另可按队列筛选，从队列页带入的队列会一直显示，可单独移除。
- 分页（每页 10 / 20 / 50 / 100 条，显示总数）。所有筛选、标签页和分段都写在页面地址里，可直接分享或刷新恢复。
- 有排队中、运行中或停止中的任务时，列表每 10 秒静默刷新（页面隐藏时暂停），刷新时保留当前行；也可随时选择 **刷新**。

每行的操作依次为：随状态变化的主按钮（运行中为 **停止**，排队或启动中为 **取消任务**，已结束为 **复制并重新配置**）、**日志**，以及 **更多**（详情、复制、运维的编辑任务 / 资源预约、删除）。桌面、手机卡片和详情抽屉使用同一套规则：只读账号能看到按钮但不可点击，并提示原因；只有提交人、项目管理员或平台管理员可以停止或删除；只有提交人或平台管理员可以复制。

停止、取消和删除都需要确认。确认后该行显示 **停止中… / 取消中… / 删除中…**，相关按钮保持禁用，直到列表观察到状态变化；超过约 90 秒仍未变化时会提示稍后刷新查看。已删除的任务不再提供删除和日志。

列表、手机卡片和任务详情均显示**提交人**，优先使用平台提交账号的姓名，姓名为空时显示登录名。
历史任务已有提交记录的也会显示；云平台外部提交的任务若只有云端账号记录，会标为
“云端账号”，不能据此判断具体使用者。没有可靠记录时显示“未记录提交人”。

列表显示名称（可复制任务 ID）、状态、资源区、GPU（型号 · 卡数 × 节点数）、调度类型、创建时间和运行时长；项目和全平台范围另显示提交人与项目。平台以厂商任务
ID 关联创建人和项目，同名任务不会因此混入“我的训练任务”；未归属当前账号或项目的
任务不会展示。平台管理员视图和运维视图另外提供厂商、队列和高级筛选。任务名称下方或详情中显示的
资源标识用于区分同名任务；提交工单时可以复制页面提供的标识，但不要自行猜测或修改。

常见状态包括：

| 状态       | 含义与建议                         |
| ---------- | ---------------------------------- |
| 创建中     | 配置已提交，正在准备任务资源       |
| 排队中     | 等待队列容量或调度条件满足         |
| 运行中     | 训练进程已经开始运行               |
| 已停止     | 任务被停止或已经结束运行           |
| 已完成     | 任务成功结束；继续核对输出和检查点 |
| 失败或异常 | 打开详情查看状态信息、日志和事件   |
| 已删除     | 任务记录已进入删除状态或不可再操作 |

状态文案可能包含厂商返回的补充信息。不要只看颜色判断结果，应打开详情确认结束原因。

## 普通用户创建训练任务

1. 选择页面右上角的 **新建训练任务**。创建窗口与开发机采用相同的分区布局，右侧显示配置预览；手机上预览位于表单下方。
2. 在 **算力配置** 中选择 GPU 型号、每个节点的卡数、资源区和 **节点数**，再选择调度类型。总 GPU 数 = 单节点 GPU 数 × 节点数；例如 8 卡 × 2 节点，共使用 16 张 GPU。选择 4 卡且节点数为偶数时，平台会合并为 8 卡节点并在卡数下方提示，可选择 **保持 4 卡**。
3. 展开 **查看各资源区余量** 查看容量快照。余量仅供参考，提交时会重新核对；不足时会排队。
4. 在 **运行环境** 中填写任务名称，按需选择所属项目，并选择当前规格和资源区已登记的训练镜像。镜像目录读取失败时可重试；标准项目任务可选择有效的整节点预约（实验性功能）。
5. 在 **训练参数** 中填写启动命令，按需选择分布式框架、环境变量、最长运行时间和描述。切换项目或镜像不会覆盖已填写的命令和环境变量。最长运行时间仅在资源区支持自动停止时可填写，百度资源区暂不支持。
6. 在 **存储与数据集** 中核对个人存储、项目存储和公共存储。普通用户可查看自动挂载状态及路径；平台管理员可调整本次挂载选择。无项目任务不会获得项目存储权限。
7. 分别在 **个人授权目录（可多选）** 和 **数据集（可多选，只读）** 中选择附加挂载。平台管理员视图中该选项显示为 **授权挂载目录**。两组选择互不覆盖，必须位于同一资源区。下方列出开发机或训练容器内的挂载路径和读写权限，可用于启动命令；训练容器只能读取数据集，输出和检查点应写入可写的个人存储或项目存储。
8. 核对配置预览中的总 GPU、节点数、镜像、项目及存储摘要，再选择底部 **新建**。预览是计划配置，仍需在任务运行后核对实际挂载。
9. 如果提示已受理或已进入 等待队列，表单会关闭，平台自动完成准备并等待额度。只有明确提示结果待确认时，才使用 **重试** 查询原操作，避免改名重复创建。

需要使用资源区5某个 Fileset 的已有子目录时，请平台管理员先完成[子目录个人授权](/data/fileset-access)，
再在“个人授权目录（可多选）”中选择。训练命令使用新建窗口显示的容器内路径，授权保存成功不代表云端挂载已验证。

有多个候选资源时，容量快照同时标明候选资源数量，并展示其中一个候选的样本，不会把多个队列或资源池的卡数相加。优先展示已知可容纳单个节点的最大余量；若没有已知足够的候选，但仍有候选余量未知，则显示未知。所选镜像可能使用不同候选资源，因此样本不保证该镜像可立即启动，也不会改变实际创建路由或预留 GPU。

百度任务不会因 Zenith 设置的时长上限自动停止。复制旧任务或切换资源区时，如果保留了原来的最长运行时间，页面会先阻止提交。确认可以不限时运行后，点击 **清除**；如果必须自动停止，请选择支持限时的资源区。已有失败任务不会自动重提。

复制百度 PyTorch 任务到火山时，平台会将框架名称 `PyTorchJob` 转为火山的 `PyTorch`，启动命令、环境变量和节点数仍保留供你核对。

### 必填和关键字段

| 字段        | 说明                                                                                                                                                                                                                                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 任务名称    | 用于列表识别；不要包含密码或数据访问凭据                                                                                                                                                                                                                                                                                        |
| 启动命令    | 容器启动后执行的训练命令；应自行处理工作目录和参数                                                                                                                                                                                                                                                                              |
| 型号 / 卡数 | 两个选择框只展示组织可用的 GPU 型号与卡数；选定后显示 CPU/内存参考范围，实际平台路由由平台管理员维护。平台管理员可为每个资源队列限定用途，因此部分卡数不会出现在这里：支持训练的火山开发机资源池可接收每节点 1 卡或 2 卡任务，并与开发机共享容量；大卡训练资源池接收每节点 4 卡或 8 卡任务，也可以进一步限定为每节点 8 卡。缺少某个卡数时请联系平台管理员核对队列用途，不要改用其他资源池猜测 |
| 节点数   | 同规格节点数量；总 GPU = 型号/卡数 × 节点数                                                                                                                                                                                                                                                                          |
| 镜像        | 当前规格可用的训练运行环境；可以选择标准镜像或目录中其他可用镜像                                                                                                                                                                                                                                                                |
| 框架        | 选择厂商侧的分布式训练模式（例如火山引擎的 PyTorch DDP、MPI、TensorFlow、Ray 或 Custom），不会变更运行镜像；实际运行镜像由上方镜像选项决定                                                                                                                                                                                      |
| 所属项目    | 可选；不选时归属个人；标准任务按个人额度付费，个人存储与公共存储按组织授权自动挂载；选择项目后用于项目配额、用量和通知，低优训练不扣个人或项目卡时                                                                                                                                                                                  |

平台按平台管理员启用的内部路由优先级选择实际厂商和队列；创建接口不会向普通用户返回这些路由字段。镜像带有平台归属时，只会选择相同平台的有效路由。

## 优先级、自动停止与训练保护

从常规新建入口创建训练任务时，调度类型默认选择**标准任务（一般）**。需要连续运行的正式训练应保持这个选项；复制任务会带入原任务的调度类型，从队列的低优入口创建也可能预选低优，请在提交前再次核对。选择
**低优任务**前，请阅读页面的抢占提示，确认自己能够接受任务中断，并做好定期保存 checkpoint 的准备。

火山低优训练任务使用厂商的可抢占调度，一般任务需要资源时可能被厂商停止，**没有 Zenith
开发机回收的 15 分钟预告保证**。其他资源区是否支持相同调度能力，以页面说明为准，不要只根据
“低优”名称推断行为。平台份额回收后的自动重新排队见上文；其他停止原因不因此承诺自动重试。
平台不能替训练程序保存检查点或恢复进度。

平台提交的训练任务**不参加开发机的低利用率自动关机**，不会因为两小时 GPU 平均利用率低或
开发机监控中断就被该规则停止。你设置的最长运行时间、手动停止、厂商故障或厂商原生抢占仍可能
结束任务；到时请查看任务状态、事件和日志确认原因。

在开发机里通过 SSH、网页终端或 `nohup` 启动训练，仍属于开发机上的程序：一般开发机受平台空闲
规则的活动保护，低优开发机还可能因同队列资源需求，在至少 15 分钟站内预告后让出资源。
详见[开发机的自动关机说明](/compute/instances#低利用率自动关机)。

提交训练前，请确认输出目录和 checkpoint 目录位于已验证可用的持久存储。停止会丢失尚未保存的
进度，不能假定所有厂商的系统盘或容器根目录都会保留。

## 火山多机多卡：框架与启动方式 {#mlp-framework-guides}

选择框架后，创建窗口会显示对应的**启动模板、环境变量来源和使用条件**。启动命令为空时可点击“填入”按钮；已有命令时可复制示例自行修改。切换框架、镜像或复制任务不会自动覆盖已有命令和环境变量。

| 框架 | 入口执行方式 | 关键配置 |
| --- | --- | --- |
| PyTorch DDP | 每个节点启动 torchrun | MLP 节点变量 → torchrun 进程变量 |
| MPI | 仅 worker0 执行入口，启动器负责启动各节点进程 | MLP_MPI_NP、MLP_MPI_HOSTS、MLP_MPI_HOSTFILE |
| TensorFlow | 各角色启动脚本，代码按角色执行 | TF_CONFIG；PS 训练需配置 ps 与 worker/chief |
| Ray | 火山初始化集群，将入口作为 Ray Job 的 driver | 连接已有集群，显式配置 Ray Train 的进程数 |
| Custom | 各节点执行命令，程序自行处理协作 | MLP_ROLE_INDEX、MLP_WORKER_NUM 等通用节点变量 |

框架选项不会安装依赖或修改镜像，也不会把普通单进程脚本自动改成分布式程序。所有节点应能访问同一路径的代码和所需数据；输出与检查点写入已挂载的持久目录。

下方“环境变量”填写业务参数。火山提供的 `MLP_*`、`TF_CONFIG` 无需手工填写，尤其不能为所有节点指定同一个编号。示例中的 `${变量:?}` 在**容器内**展开，缺少值会停止启动。多节点使用 HPC / RDMA 和 NCCL 时，保留火山注入的网络配置，勿照搬其他集群的网卡名或设置 `NCCL_IB_DISABLE=1`。参考 [MLP 通用环境变量](https://docs.volcengine.com/docs/ml-platform/common-environment-variables-list?lang=zh)、[RDMA 训练说明](https://docs.volcengine.com/docs/6459/96563?lang=zh)。

## 火山引擎 PyTorch DDP

在火山引擎 MLP 上选择 **PyTorch DDP**，并通过 **节点数** 设置训练节点数；型号的卡数是每个节点的 GPU 数。DDP 使用同构 `worker` 节点，不要添加 `ps` 等角色。镜像需包含兼容的 PyTorch、CUDA 和训练依赖，训练代码需支持 `DistributedDataParallel`。

选中后，页面会显示启动模板。启动命令为空时，可点击 **填入 DDP 启动模板**，再将 `train.py` 替换为实际脚本并补上训练参数；已有命令不会被覆盖。每个节点执行同一条命令：

```bash
torchrun \
  --nnodes="${MLP_WORKER_NUM:?}" \
  --nproc-per-node="${MLP_WORKER_GPU:?}" \
  --node-rank="${MLP_ROLE_INDEX:?}" \
  --master-addr="${MLP_WORKER_0_HOST:?}" \
  --master-port="${MLP_WORKER_0_PORT:?}" \
  train.py
```

MLP 在各节点注入上述变量：节点数、每节点 GPU 数、当前节点编号及主节点地址/端口。不要将节点编号或主节点地址手工写成所有节点共用的固定值，也不要在环境变量表中覆盖这些 `MLP_*` 变量。模板缺少必要节点信息时会直接报错，避免多个节点分别启动成独立的单机任务。

`torchrun` 为训练子进程设置 `RANK`、`LOCAL_RANK` 和 `WORLD_SIZE`。例如 2 个节点、每个 8 卡，总训练进程数为 16；训练代码通常使用 `env://` 初始化进程组，并按 `LOCAL_RANK` 绑定 GPU。仅选择框架不会把普通单进程脚本自动改造成 DDP，也不会更换镜像。

参考：[MLP PyTorch DDP 指南](https://www.volcengine.com/docs/6459/75222?lang=zh)、[PyTorch torchrun 文档](https://docs.pytorch.org/docs/stable/elastic/run.html)。

## 火山引擎 MPI：Horovod / DeepSpeed

MLP 的 MPI 模式由 **worker0 执行入口**，其他节点由启动器拉起进程。所有节点需有相同依赖和可访问的代码路径，并保留 MLP 配置的节点间 SSH。不要只在 worker0 临时安装依赖。

| 变量 | 来源与用途 |
| --- | --- |
| `MLP_MPI_NP` | 火山注入的总进程数；GPU 任务通常为节点数 × 每节点 GPU 数 |
| `MLP_MPI_HOSTS` | 火山注入的主机及 slots 列表，供 Horovod 使用 |
| `MLP_MPI_HOSTFILE` | 火山生成的 hostfile 路径，记录各节点和可用进程数 |
| `MLP_WORKER_0_HOST` / `MLP_WORKER_0_PORT` | 火山提供的主节点通信地址与端口 |
| `OMPI_COMM_WORLD_RANK` / `OMPI_COMM_WORLD_LOCAL_RANK` / `OMPI_COMM_WORLD_SIZE` | 使用 Open MPI 时，由启动器为子进程设置的全局编号、本地编号和总进程数 |

Horovod 示例；脚本需已集成 `hvd.init()` 和分布式优化器：

```bash
horovodrun -np "${MLP_MPI_NP:?}" -H "${MLP_MPI_HOSTS:?}" python -u /workspace/train.py
```

DeepSpeed 示例；脚本需已集成 DeepSpeed，并补充其需要的配置参数：

```bash
deepspeed --hostfile "${MLP_MPI_HOSTFILE:?}" --master_addr "${MLP_WORKER_0_HOST:?}" --master_port "${MLP_WORKER_0_PORT:?}" /workspace/train.py
```

将 `/workspace/train.py` 替换为各节点均能访问的实际路径。这种 MPI 入口由 worker0 启动，不要加入要求每节点各自执行的 `--no_ssh`。业务环境变量需要按照启动器的传播机制配置；例如直接使用 Open MPI 的 `mpirun` 时可用 `-x`，DeepSpeed 可使用 `.deepspeed_env` / `DS_ENV_FILE`。

参考：[MLP MPI](https://docs.volcengine.com/docs/ml-platform/launch-mpi-distributed-training?lang=zh)、[Horovod 启动](https://horovod.readthedocs.io/en/latest/running_include.html)、[DeepSpeed](https://www.deepspeed.ai/getting-started/)、[Open MPI 进程变量](https://docs.open-mpi.org/en/main/tuning-apps/environment-var.html)。

## 火山引擎 TensorFlow

关键变量是火山注入的 **`TF_CONFIG`**：`cluster` 包含各角色地址，`task.type` 和 `task.index` 指定当前节点的角色及编号。每个节点的 `task` 不同，不要在环境变量表里填写一个所有节点共用的固定值。

```bash
: "${TF_CONFIG:?MLP must provide TF_CONFIG}"
python -u train.py
```

`train.py` 需读取配置（例如使用 `TFConfigClusterResolver`），创建匹配的分布式策略并执行相应角色；单机脚本不会因为设置该变量而自动同步。选择参数服务器训练时，至少需要 1 个 `ps`，以及 `worker` 或 `chief`。普通创建入口只配置同构 worker，**PS 训练请平台管理员或运维通过「按厂商参数新建」配置多角色**。训练算法、角色拓扑和脚本需保持一致。

参考：[MLP TensorFlow PS](https://docs.volcengine.com/docs/ml-platform/launch-tensorflowps-distributed-training?lang=zh)、[TensorFlow 分布式训练](https://www.tensorflow.org/guide/distributed_training)。

## 火山引擎 Ray

火山负责初始化 Ray 集群，并将入口提交为 Ray Job。填写 driver 启动命令即可，无需逐节点执行 `ray start`，也无需重复 `ray job submit`：

```bash
python -u train_ray.py
```

脚本中显式连接已有集群：

```python
import ray

ray.init(address="auto")
# Create the application's Ray tasks or Ray Train trainer here.
```

`RAY_ADDRESS` 是 Ray 可选的集群地址来源；若运行环境提供，保留原值即可，不应猜测固定地址，也不要求手填。`auto` 未找到现有集群时会报错；`address="local"` 则会另建本地集群，不适用于这里的托管多机任务。

Ray Train 还需在脚本的 `ScalingConfig` 中指定 `num_workers` 和 `use_gpu`。例如按一进程一卡使用 2 节点 × 8 卡时，训练进程总数为 16；driver/其他 actor 也可能需要 CPU 资源，应按实际训练资源需求配置。单纯申请多卡不会替你设置这些进程。

集群所需的业务环境变量应在**提交前**填入环境变量表，例如训练代码实际读取的 `DATA_DIR`、`OUTPUT_DIR`；这些名字只是业务示例，不是平台自动注入项。不要只在 driver 启动后 `export`，期待已经启动的远端 worker 自动继承。

参考：[MLP Ray 自定义任务](https://docs.volcengine.com/docs/ml-platform/verl-dapo-training-best-practice?lang=en)、[Ray 集群连接](https://docs.ray.io/en/latest/ray-core/api/doc/ray.init.html)。

## 火山引擎 Custom

Custom 由你的程序负责进程编排和通信。`MLP_ROLE_INDEX` 是当前角色内的节点编号，`MLP_WORKER_NUM` 是 worker 数，`MLP_WORKER_GPU` 是每节点 GPU 数；还可以读取 `MLP_WORKER_0_HOST` / `MLP_WORKER_0_PORT`。这些变量来自火山，不能等同于训练进程的 `RANK` / `WORLD_SIZE`。

下面是**独立分片任务**示例，要求 `train.py` 自行实现这两个参数；它不是自动同步梯度的训练启动器：

```bash
python -u train.py --shard-index="${MLP_ROLE_INDEX:?}" --num-shards="${MLP_WORKER_NUM:?}"
```

每个分片使用独立输出路径。需要同步训练时，请选择对应框架，或在程序中自行启动进程、分配数据并实现通信。

## 复制任务或重新选择镜像

1. 在任务操作列选择 **复制并重新配置**。
2. 核对带入的镜像、规格、节点数、项目、存储和启动命令；按需修改镜像或其他参数。
3. 环境变量会从原任务的云端详情带入，可以继续编辑。若原任务已删除、连接不可用或云端不提供真实值，请按提示补填未恢复的环境变量；平台内部变量不会复制。较早创建的任务没有完整配置记录，还需要重新选择规格、镜像并填写原始启动命令。
4. 原镜像或挂载已不可用时，明确选择替代项，或关闭不再需要的挂载；不会静默移除原有挂载。
5. 完成 **配置核对** 后提交，生成独立的新任务。

此入口不会修改原任务，也不会替换运行中容器的镜像。原始配置仅供任务创建者和平台管理员读取；能查看项目任务状态不等于能够复制其他成员的创建配置。

## 按厂商参数新建（平台管理员与运维）

平台管理员视图和运维视图的 **新建训练任务** 与普通用户使用同一个算力规格表单；按钮旁的下拉 **按厂商参数新建** 打开原生表单。原生表单必须先明确选择 **资源区**（列表按资源区筛选时会预先带入，否则留空），再选择队列、规格 ID、可用区、节点数、多角色、存储挂载和仅校验，不会沿用之前点过的任务所在资源区。该表单用于平台接入和诊断，不代表普通用户的产品边界。所有原生字段仍由厂商最终校验。

## 创建多角色训练任务

环境支持任务控制时，可开启 **多角色任务**，为异构分布式工作负载分别配置 worker、ps 等角色。

每个角色需要设置：

- 角色名称。
- 节点数。
- 规格。
- 可用区。

创建前计算所有角色的 GPU 总数，而不是只看单个角色。例如，两个角色的节点和规格会共同占用队列及项目额度。

### 多节点与多角色限制

- 普通用户通过 **节点数** 创建同构多节点任务：每个节点使用相同的 GPU 型号、卡数和镜像。
- 异构多角色任务（不同角色使用不同规格）只在平台管理员视图和运维视图中提供，且受厂商能力限制：
  - 火山引擎 MLP 支持异构多角色。
  - 无问芯穹 Lanqi 仅支持同构节点，不支持异构角色。
  - 天翼云 CTyun 训练 Job 创建需要厂商 IAM 授权，暂不可用。

## 配置存储挂载

普通用户可查看个人、项目和公共存储的自动挂载状态，并在 **个人授权目录** 和只读数据集中分别多选。平台按当前账号和项目解析实际路径；项目只读成员不能获得可写项目挂载。更换镜像或规格后应重新核对存储是否可用。任务会在必要的存储准备和队列授权通过后才提交；准备失败时不会以缺少挂载的配置继续创建。

按厂商参数新建的表单可按当前环境能力添加 TOS 或 vePFS 挂载。每一项包括：

- 存储类型。
- 来源，例如存储桶或文件系统。
- 可选子路径。
- 容器内挂载路径。
- 只读开关。

建议将训练数据设为只读，将输出目录和检查点目录配置为可写。提交前确认：

1. 来源位于当前环境可访问范围。
2. 子路径真实存在，或任务具备创建权限。
3. 不同挂载项没有覆盖同一路径。
4. 启动命令使用的路径与挂载路径完全一致。

## 使用 仅校验

开启 **仅校验** 后，页面只校验参数，不实际创建训练任务，也不会启动 GPU 资源。

推荐流程：

1. 完整填写创建表单。
2. 开启 仅校验 并选择 **校验**。
3. 修正页面返回的问题。
4. 关闭 仅校验。
5. 再次核对节点数、规格、队列和项目。
6. 选择 **新建**。

仅校验 通过只代表当前参数校验通过，不会预留库存，也不能保证之后的真实提交成功。

## 判断创建是否成功

- 显示“校验通过，可正式提交”：没有创建真实任务。
- 显示任务创建请求已提交：请求已被接受，任务可能仍在创建或排队。
- 新任务出现在列表：任务已可被 Zenith 查询。
- 状态变为运行中：训练资源已经开始运行。
- 状态变为已完成：任务执行结束，仍需核对输出、检查点和指标。

创建后列表会立即刷新；提交进入等待队列时，页面会切换到 **等待提交** 标签页。新任务不在当前筛选结果中时，提示中会提供 **查看**，不会自动改写你的筛选条件。

“我的训练任务”和项目范围先按平台记录的创建者/项目任务 ID 确定可见范围，
不会扫描或展示账号下其他用户的任务。某个厂商详情暂时不可用时，列表仍会保留
平台已记录的任务摘要。

## 查看任务详情

点击任务名称打开详情抽屉。顶部是概览（状态与「同步于」时间、任务 ID、提交人、调度类型、资源区、GPU、运行时长、创建时间；运维另显示队列、优先级和资源预约），以及与列表行完全相同的操作按钮。抽屉只有一个 **刷新**，会同时刷新所有区块；列表刷新观察到新状态时，抽屉也会随之更新。下方标签页：

- **日志**：内嵌日志阅读器（见下文）。
- **监控**：CPU、内存、GPU 和显存等指标，按资源区自动选择数据来源。
- **时间线与诊断**：平台记录的状态变化，以及厂商任务控制台、TensorBoard 链接；接口可用性标签只对平台管理员显示。
- **节点**：全部节点的状态、规格、可用区、IP 和退出码，可搜索、分页；平台管理员可在运行中的节点打开终端。
- **配置**：申请资源、镜像、启动命令和存储挂载。

### 失败后的诊断

任务失败或异常后，详情会显示失败阶段、云端原因，以及可查询到的 节点原因和退出码。已采集日志仍可读取，也可独立打开日志页。镜像拉取、存储挂载或容器启动前失败时，可能尚无训练程序输出，应结合状态时间线和厂商控制台排查。

“日志待生成”仅用于尚未结束且未收到输出的任务。任务结束后没有取得日志，会明确显示未取得日志并保留刷新重试；不会一直提示等待生成。缺少运行观测时会说明阶段未确认，不代表程序一定没有运行。独立日志页也可查看平台已保存的失败原因。

### 实时日志

自定义（Custom）任务也使用同一日志阅读器。在任务列表或手机卡片中选择 **日志**，可直接在新标签页打开；也可以从任务详情进入。日志读取不需要 SSH，不会连接到任务机器的交互终端。是否可读取取决于当前资源区的日志接口及任务创建时的采集配置。

任务支持日志读取时，详情中的 **任务日志** 会在页面可见时每 5 秒后台刷新一次。刷新不会遮挡或清空正文，可以继续滚动、选择和复制；新日志按先后顺序追加到末尾。百度日志使用续读游标接收后续分段，其他资源区对近期日志窗口去重追加。

打开详情后默认跟随最新输出。向上滚动只暂停自动滚动，新日志继续追加，并显示新增条数；选择 **查看最新** 或滚动到底部即可恢复跟随。切换节点 会保留近期节点已加载的内容、搜索和阅读位置；切换任务或账号、关闭阅读器会清空阅读缓存，旧请求不会串入新窗口。暂时刷新失败时保留已读内容并提示原因。

选择 **独立打开** 可在新标签页持续阅读，保留任务和节点选择；独立页面显示任务名称和状态，**返回任务列表** 会回到对应列表并按该任务筛选。独立页面仍需登录并通过任务权限校验。`A−` / `A+` 可调整日志字号。

每个节点阅读窗口最多保留已接收的 5,000 行、约 200 万字符，超过后淘汰最早内容并显示提示。这里不是完整日志归档，重新打开会重新读取；需要完整输出时，请使用可用的厂商任务控制台或训练程序保存的日志文件。
可搜索当前节点已加载内容，匹配文字会高亮，默认保留前后文。用上下箭头或 `Enter` / `Shift+Enter` 跳转到下一个 / 上一个匹配行；勾选 **仅匹配行** 后只显示匹配内容。左侧行号是本次阅读窗口的记录编号，不是日志文件的原始行号。

可以调整自动换行，复制或 **下载当前日志**。导出区域会显示行数和范围：默认导出已加载内容（含搜索上下文）；勾选 **仅匹配行** 才会只导出匹配行。**暂停刷新** 会暂停网络读取，**继续刷新** 恢复；暂停期间仍能手动刷新。向上滚动只暂停自动滚动。

任务结束且输出稳定后会停止自动刷新，仍可手动刷新。新采集任务会标记最后上传是否完成；旧任务需要观察一段时间确认没有新增输出。若有后续分页，读取完后才会停止。权限或配置错误需要手动重试，临时网络错误会稍后重试。

新建火山任务每个节点保留最多 1,000 条、约 900 KiB 的近期记录，超长行会分段，较早内容可能移出窗口；页面会显示已知的截断或漏接情况。已运行任务仍使用创建时的采集方式。这里不能补回以前未采集的日志，也不承诺完整归档。

资源区5配置日志采集的新建任务通过 Zenith 日志中继提供输出，每个节点独立保存。失败任务在取得节点诊断后会自动展示异常退出的节点，并在下拉框标记“异常退出”；其他任务默认查看第一个节点。可以手动切换，手动选择后不会被自动改回。独立日志页也支持该行为；无法取得节点诊断时，可从下拉框选择其他节点查看。旧任务沿用原有日志读取方式；没有配置日志采集时会显示具体提示。其他资源区依赖当前环境的日志接口能力，支持多个节点时可按节点筛选。接口可用性标签只对平台管理员显示，不代表页面内嵌了相应内容；厂商入口不可用时以页面提示为准。

监控是按需获取的快照，不等于持续实时曲线；节点列表在详情顶部点 **刷新** 后更新。

## 停止和删除任务

### 停止运行中任务

1. 在运行中的任务操作列选择 **停止**。
2. 阅读确认提示并确认。
3. 等待请求已提交提示。
4. 稍后刷新，确认状态进入已停止或其他终态。

停止会中断训练。只有已经写入持久存储的检查点和输出可以可靠保留。

### 删除终态任务

1. 确认任务不再需要继续诊断。
2. 确认输出、日志和检查点已经保存。
3. 选择 **删除**并确认。
4. 刷新列表确认状态变化。

删除任务记录不应被当作删除底层对象存储文件的手段；存储内容应按存储策略单独管理。

## 任务控制

厂商能力允许时，详情或操作区可提供以下控制：

- 更新任务名称和描述。
- 修改优先级。
- 设置最大运行时间。
- 设置最长保留时间。
- 开启或关闭资源预约。
- 使用 仅校验 先校验控制参数。

控制请求可能只影响后续调度或任务运行阶段，不能假定提交后立即生效。提交后刷新任务详情并观察状态信息。

## 刷新规则与成功判断

| 操作    | 页面反馈               | 最终判断                                 |
| ------- | ---------------------- | ---------------------------------------- |
| 仅校验 | 校验通过或返回参数错误 | 通过后仍需关闭 仅校验 才会真实创建      |
| 创建    | 创建请求已提交         | 列表出现任务，并进入排队、创建或运行状态 |
| 停止    | 停止请求已提交         | 刷新后进入已停止或其他终态               |
| 删除    | 删除请求已提交         | 刷新后进入已删除或不再出现在当前列表     |
| 控制    | 控制请求已提交         | 详情中的目标字段或状态发生变化           |

训练任务页主要在进入页面、切换厂商、改变筛选、执行操作或点击 **刷新**时更新。不要依赖页面长时间停留时自动追踪状态。

## 风险提示

- 多节点和多角色任务可能快速消耗大量 GPU 与卡时。
- 停止或删除任务前未保存的进度可能永久丢失。
- 镜像须在实际资源区登记并启用；登记不代表目标环境有拉取权限。
- 仅校验 不预留库存，也不保证真实提交时仍有容量。
- 手动填写错误的规格或可用区会在最终提交时被拒绝。
- 项目归属用于配额、用量和通知，不会自动选择队列或云厂商。
- 监控、实时日志、事件 API 和 TensorBoard 的可用性依赖当前环境能力；近期日志不替代训练程序的持久日志文件。

## 常见问题

### 为什么没有“新建训练任务”按钮？

账号可能没有资源操作权限，当前厂商连接不可用，或当前环境未开放训练能力。查看按钮附近和空状态中的提示；仍无法解决时提交工单。

### 什么情况下可以不选择项目？

启用学院学生周额度的账号可以不选项目，任务仍归本人所有。未参加有效正式项目的学生只能创建低优任务；当前实际参加基础培育或自由探索项目的学生可以创建标准或低优任务。只读访问不计入资格。退出或项目结项后，新任务立即按当前资格检查；本周保留的较高额度不会保留标准任务资格。

平台管理员也可不选项目。其他普通账号仍需选择有写入权限的有效项目。已经提交的任务保留原所有者和付款方式；“重试”返回原记录，复制并重新创建则重新校验资格。

### 任务一直排队怎么办？

若任务在 **等待提交** 标签页中，先查看对应的等待原因：标准任务可能等待个人并发额度，低优任务可能等待本轮份额或前序用户释放容量。
低优任务不会自动缩小申请卡数；单个任务超过当前份额时，需要等待足够份额，或自行取消后调整规格重新提交。

已经进入云端的任务，会在列表、手机卡片和详情直接显示 **排队原因**；未获取到原因时会明确提示，不能据此判断一定是资源不足。列表使用最近同步记录，打开详情可获取最新状态。后续记录到的排队原因会保留在 **状态时间线**，停止后仍可查看；历史未记录的原因无法补推。

**队列配额充足不等于能立即开跑。** 每个节点的 GPU、CPU 和内存需要在同一台机器上同时满足。例如 8 卡 × 12 节点，需要 12 台都能满足单节点规格的机器，不能把不同机器的散卡拼成一个节点。容量提示是卡数参考，节点碎片、实时竞争等仍可能导致排队。

如果云端提示“有配额，可能存在碎片”，由平台管理员核对节点负载；这只是云端的诊断提示，不代表平台已经确认具体阻塞节点。提示本身不会自动停止其他任务或执行碎片整理。

### 仅校验 成功，真实创建为什么失败？

仅校验 校验参数但不预留资源。校验后库存、额度或厂商状态可能发生变化，真实提交仍要接受最终检查。

### 在哪里看训练程序输出？

在任务列表选择 **日志**（独立页），或打开任务详情的 **日志** 标签，自定义任务同样适用。默认跟随最新输出；向上滚动后可选择 **查看最新** 恢复跟随。该资源区暂不支持站内查看日志或需要更早的输出时，使用 **时间线与诊断** 标签中的 **厂商任务控制台**（可用时），或查看训练程序保存的日志文件。开发机的“状态日志”只记录资源状态变化，不是训练程序输出。

### 训练需要交互调试怎么办？

先在[我的开发机](/compute/instances)新建开发机，并按[连接开发机](/compute/connection)调试镜像、命令和挂载，验证后再提交训练任务。

项目可以绑定多个存储，实际挂载的存储决定本次创建的资源区，跨区存储不能混挂。平台管理员可另行为项目配置 DEV、TASK 等队列的保障卡数；创建时使用符合存储位置和工作负载类型的保障队列。资源区 5 包含火山 MLP3 和 MLP4，不同资源池的空闲卡不能拼成一个更大规格。

## 训练资源利用率与终端

在任务详情的 **监控** 标签查看资源利用率，并选择具体节点。火山展示 CPU、内存及每张 GPU 的利用率、显存；百度展示按节点采集的 GPU、显存、CPU、内存曲线，保留厂商原始数值，不把未知单位强制换算为百分比。无采样或过期会明确显示，不据此自动停止训练。

仅平台管理员可在 **节点** 标签中、运行中的节点旁点击“打开终端”。百度通过平台网页终端连接；火山优先打开云端公开调试入口，没有公开入口时会提示登录该任务的云控制台再进入 WebShell。任务本人、项目管理员和成员均不能操作训练终端。任务结束后无法新建终端连接。

API 查询利用率使用 `jobs:read`。训练任务终端仅平台管理员可见、可连接，任务本人及项目管理员均不可操作；个人 API Token 不提供训练终端权限。连接凭据只用于当前连接，请勿保存或输出。

## 每节点卡数

训练任务按组织可用规格选择每节点 **1、2、4 或 8 卡**，普通任务和低优任务都适用。
每节点 1 / 2 卡任务使用已纳管且支持训练的火山开发机队列，与开发机共享容量；每节点 4 / 8 卡任务使用原有训练队列。
按每个节点的卡数选择队列，而不是总卡数。例如 **2 卡 × 4 节点**仍使用开发机队列，保留原节点数。
训练任务仍按训练权限、预算和排队规则管理，不受开发机每人 2 卡限制。缺少小卡规格时，请平台管理员核对队列用途、训练能力和规格路由。
4 卡的偶数节点会合并为 8 卡节点，例如 **4 卡 × 2 节点 → 8 卡 × 1 节点**，总卡数不变。
4 卡 × 3 节点仍为 12 卡。请按最终预览的节点数配置分布式启动命令。
没有可用的同卡型 8 卡规格时，系统会提示调整配置，不会通过增加卡数完成合并。
已有任务按实际提交的规格展示；复制任务后需要按当前规格重新配置。

## 队列容量提示

创建任务时，所选资源区的容量不足提示会直接显示在表单内，无需展开余量面板。
当采样可用卡数为 0 时，显示“队列已满”和本次需要的卡数；可以等待资源释放或选择其他资源区。
继续提交仍可能排队或被厂商拒绝，提示不代表资源预留。容量样本超过 90 秒后会标为过期，
不再据此显示满额结论。平台管理员和运维按厂商参数新建时，也能看到所选队列的满额提示并手动刷新容量。

### 提交时提示描述过长

任务描述为选填项，最多 500 个字符。长的实验方案请保存在项目文档中；缩短或清空描述后再提交。页面会显示当前字数，不会自动截断内容。API 返回 `400 / invalid_training_description` 时，请修改 `description` 后使用新的幂等键提交，不要原样重试。已失败的提交不会自动重新执行，旧记录仍保留。
