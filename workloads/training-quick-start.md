# 训练任务快速开始

本教程带你完成一条最常用的训练路径：准备数据与代码、在「我的开发机」中验证环境、通过训练任务页面提交任务、查看日志并保存结果。如果你还没用过开发机，建议先阅读[快速开始：创建并连接开发机](/guide/quick-start)。

## 适用角色与界面路径

| 项目     | 说明                                                   |
| -------- | ------------------------------------------------------ |
| 适用角色 | 有操作权限的普通用户、项目管理员、运维或平台管理员 |
| 只读用户 | 可以查看任务，但不能创建、停止或删除                   |
| 创建路径 | **控制台 > 训练任务 > 新建训练任务**                   |
| 查看路径 | **控制台 > 训练任务**                                  |
| 日志路径 | 任务详情中的 **实时日志**                              |

普通用户只需选择 GPU 型号、卡数和 节点数，不需要手动选择厂商或队列。若组织尚未分配训练规格，请联系平台管理员。

## 开始前检查

- 账号能够正常登录并具备资源操作权限。
- 当前组织至少有一个标记为可创建训练任务的逻辑算力规格。
- 已确认目标资源区有可用的训练镜像。
- 训练数据和预期输出位置已经明确，且位于持久存储或可挂载路径。
- 启动命令已经在同一镜像或类似环境中验证过。
- 个人/项目卡时额度充足，或已了解低优任务的抢占规则。

::: warning 训练任务会立即使用真实 GPU
标准任务消耗卡时；低优任务不扣个人或项目卡时，但仍记录 GPU 用量，并可能被抢占。提交前请仔细核对节点数、规格和项目。
:::

## 第 1 步：准备数据、代码和启动命令

### 1.1 组织代码

建议把代码提交到 Git，而不是只放在开发机系统盘。训练任务的启动命令应能直接从代码仓库或持久挂载中拉取/运行代码。

推荐的代码结构：

```text
my-project/
├── train.py
├── requirements.txt
├── config/
│   └── train_config.yaml
├── data/              # 建议指向挂载的数据集
└── outputs/           # 建议指向持久存储
```

### 1.2 准备数据

- 训练数据应放在可挂载的持久存储中，例如个人存储、项目存储、公共存储或只读数据集。
- 在启动命令中使用挂载路径，而不是把数据复制到容器内临时目录。
- 如果数据在其他资源区，先通过[文件迁移](/data/file-migrations)或对象存储同步到目标区域。

### 1.3 在开发机里验证启动命令

::: tip 强烈建议先调试再提交
训练任务一旦运行，很难像开发机一样实时交互调试。先在开发机中运行一次启动命令，确认：

- 镜像能正常启动；
- 依赖完整；
- 数据路径正确；
- 输出能写入持久存储。
  :::

例如，验证单卡命令：

```bash
cd /personal_fast_storage/my-project
python train.py --config config/train_config.yaml --data_dir /datasets/my-dataset --output_dir /personal_fast_storage/my-project/outputs
```

### 1.4 准备分布式命令（如需要）

- 单节点：启动命令与在开发机中验证的命令基本一致。
- 多节点：根据厂商选择合适的分布式框架。例如火山引擎 MLP 使用 PyTorch DDP 时，页面会提供模板。
- 不要硬编码节点编号、主节点地址或 IP。

## 第 2 步：选择镜像

1. 打开 **控制台 > 镜像**，选择目标资源区。
2. 确认平台镜像中有所需环境，或自己已经登记了个人/项目镜像。
3. 镜像应与代码的框架版本、CUDA 版本和 Python 版本匹配。详见[如何选择合适的镜像](/assets/choosing-images)。

## 第 3 步：填写创建表单

1. 打开 **控制台 > 训练任务**，点击 **新建训练任务**。
2. 在 **算力配置** 中选择：
   - GPU 型号
   - 每个节点的卡数
   - 节点数（总 GPU = 单节点 GPU × 节点数）
   - 调度类型：标准任务（一般）或低优任务
3. 在 **运行环境** 中：
   - 填写任务名称（不要包含密码或密钥）
   - 选择所属项目（可选；不选则为个人任务）
   - 选择已验证的训练镜像
4. 在 **训练参数** 中填写启动命令。
5. 在 **存储与数据集** 中核对挂载路径，确认启动命令中使用的路径与实际挂载路径一致。
6. 查看右侧配置预览，确认总 GPU 数、镜像、项目和存储摘要。

::: info 启动命令示例
单节点示例：

```bash
cd /personal_fast_storage/my-project && python train.py \
  --data_dir /datasets/my-dataset \
  --output_dir /personal_fast_storage/my-project/outputs \
  --num_epochs 10
```

火山 MLP PyTorch DDP 示例（节点数 > 1 时）：

```bash
torchrun \
  --nnodes="${MLP_WORKER_NUM:?}" \
  --nproc-per-node="${MLP_WORKER_GPU:?}" \
  --node-rank="${MLP_ROLE_INDEX:?}" \
  --master-addr="${MLP_WORKER_0_HOST:?}" \
  --master-port="${MLP_WORKER_0_PORT:?}" \
  /personal_fast_storage/my-project/train.py \
  --data_dir /datasets/my-dataset \
  --output_dir /personal_fast_storage/my-project/outputs
```

:::

## 第 4 步：使用 仅校验 校验

1. 在创建窗口底部开启 **仅校验**。
2. 点击 **校验**。系统会检查参数合法性，不会真正创建任务，也不会启动 GPU。
3. 根据返回的错误修正配置。
4. 关闭 仅校验，再次核对配置。
5. 点击 **新建**。

::: tip 仅校验 不是资源预留
仅校验 通过只代表参数校验通过，不代表之后真实提交时仍有库存或额度。
:::

## 第 5 步：等待任务运行

创建后，任务可能经历以下状态：

| 状态       | 含义                     | 操作建议                       |
| ---------- | ------------------------ | ------------------------------ |
| 创建中     | 配置已提交，正在准备资源 | 等待                           |
| 排队中     | 等待队列容量或调度条件   | 查看排队原因，不要重复提交     |
| 运行中     | 训练进程已开始           | 打开详情查看日志               |
| 失败或异常 | 创建或运行出错           | 查看详情、日志、事件，排查原因 |

新任务通常需要一些时间才会出现在列表中。如果状态长时间未更新，可以点击 **刷新**，不要重复创建。

## 第 6 步：查看实时日志

1. 点击任务名称进入详情。
2. 选择 **实时日志**。日志会在页面可见时自动刷新。
3. 向上滚动可暂停自动跟随；滚动到底部或点击 **查看最新** 恢复跟随。
4. 如果日志窗口不支持或需要更早的输出，可以使用详情中的 **打开厂商任务控制台**（可用时），或查看训练程序自行保存的日志文件。

## 第 7 步：保存结果并停止/删除任务

### 保存结果

- 确认检查点、模型和日志已经写入持久存储。
- 从其他入口（例如开发机或文件浏览）验证关键文件可见。
- 不要把访问密钥写入输出文件或命令历史。

### 停止或删除

- **停止**：暂时不需要继续训练时使用。已写入持久存储的检查点会保留。
- **删除**：任务不再需要诊断时使用。删除任务记录不会删除对象存储中的文件。

## 成功判断

完成以下检查即可认为第一个训练任务提交成功：

| 阶段           | 成功判断                     | 可能的延迟         |
| -------------- | ---------------------------- | ------------------ |
| 数据与代码准备 | 启动命令在开发机中可正常运行 | 取决于代码复杂度   |
| 创建请求       | 页面显示创建请求已提交       | 通常立即           |
| 任务出现       | 新任务出现在训练任务列表     | 常见为数十秒或更久 |
| 任务运行       | 状态变为运行中               | 取决于队列和厂商   |
| 日志输出       | 实时日志显示训练程序正常输出 | 通常数秒到数分钟   |
| 结果保存       | 输出文件出现在持久存储       | 取决于程序写入逻辑 |

## 常见问题

### 为什么创建后任务一直在排队？

标准任务可能等待个人并发额度（百度和火山默认每人最多 64 卡）；低优任务可能等待本轮份额。打开详情查看排队原因。

### 仅校验 通过，真实创建为什么失败？

仅校验 只校验参数，不预留资源。真实提交时库存、额度或厂商状态可能发生变化。

### 启动命令中使用相对路径可以吗？

不建议。训练容器的工作目录可能与开发机不同。请使用绝对路径，并确保路径与挂载配置完全一致。

### 训练任务支持交互式调试吗？

不支持。先在开发机中完成交互式调试，再提交为训练任务。
