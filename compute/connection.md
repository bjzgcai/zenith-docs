# 连接开发机

Zenith 提供两种常用连接方式：复制 SSH 连接信息后从本机连接，或直接打开网页终端。两种方式都依赖开发机处于运行状态、当前环境支持 SSH，并且开发机已经授权相应公钥。

## 适用角色与界面路径

| 项目 | 说明 |
| --- | --- |
| 密钥管理 | 所有已登录用户；**账号设置 > SSH 密钥** |
| 自己的开发机 | **工作台 > 我的开发机** |
| 运维与平台管理员 | **开发机管理 > 开发机详情 > 连接** |
| 查看 SSH 信息 | 需要开发机可见，且当前厂商提供连接信息 |
| 打开网页终端、补注入、公网开关 | 需要资源操作权限，并受队列和厂商能力限制 |

## 连接前检查

- 开发机状态为 **运行中**。
- 列表没有「数据已过期」标签，详情中的「最近同步」也正常；如有异常，先刷新详情。
- 当前厂商和资源类型支持 SSH 连接信息。
- 开发机位于平台允许使用 SSH 的队列范围内。
- 你的 SSH 公钥已经在 Zenith 中登记，并成功注入该开发机。
- 从本机连接内网端点时，本机网络能够到达开发机所在网络。
- 私钥保存在安全位置，且文件权限符合本机 SSH 客户端要求。

## 管理 SSH 密钥

### 导入已有公钥

1. 打开 **账号设置 > SSH 密钥**。
2. 选择 **导入公钥**。
3. 按需填写便于识别的密钥名称；留空时平台会尝试使用公钥注释。
4. 粘贴 OpenSSH 单行公钥。
5. 保存并确认密钥出现在列表中。

支持常见的 Ed25519、RSA 和 ECDSA OpenSSH 公钥。不要粘贴私钥，也不要把密钥口令写入名称或备注。

### 生成新密钥

1. 选择 **生成密钥对**。
2. 填写密钥名称。
3. 生成后立即复制或下载私钥。
4. 将私钥保存到只有你可以访问的位置。
5. 关闭结果窗口前，确认备份可以正常读取。

::: danger 私钥只显示一次
Zenith 只保存公钥。生成结果窗口关闭后，无法再次查看或恢复私钥明文；丢失私钥后只能创建新密钥并重新授权。
:::

### 设置默认密钥

“默认”目前只是密钥列表中的管理标记，不会让创建向导自动选中该密钥。开发机创建后的自动补注入会读取你当前登记的全部公钥；创建向导如要求填写公钥，仍需按页面提示单独填写。

### 删除密钥

删除 Zenith 中的密钥记录会影响之后的自动注入，但不会自动从已经写入开发机的 `authorized_keys` 中移除该公钥。

如需撤销已有开发机上的访问权限，必须进入开发机系统或使用平台管理员认可的配置管理方式移除公钥，并验证旧私钥已无法登录。

## 公钥何时注入开发机

<a id="公钥何时注入实例"></a>

- 新创建的开发机进入运行状态后，Zenith 会在条件允许时注入你登记的公钥。
- 已经存在的开发机不会因为你后来新增密钥而立即更新。
- 对已有开发机，可在开发机详情的“用户公钥注入”区域选择 **补注入公钥**。
- 补注入会追加当前登记的个人公钥，已存在的同一公钥会被跳过。
- 老开发机或外部创建开发机如尚未授权网页终端，还可以复制页面提供的平台终端公钥，并按平台管理员指引加入开发机的 `authorized_keys`。

补注入成功后，仍可能需要数秒才能建立连接。查看注入记录中的状态、尝试次数、新增数量和错误提示后再重试。

## 从本机使用 SSH 连接

### 获取连接信息

1. 打开运行中开发机的详情。
2. 确认详情里已经显示 **厂商实例 ID**。终端、SSH 和公钥注入都按这个 ID 查询，不要用 Zenith 的内部记录号代替。
3. 找到“SSH 连接”区域。
4. 选择 **获取**。
5. 核对主机、端口、用户名，以及端点标签：`平台中转 · 固定端口`、`公网直连` 或 `仅内网`。
6. 选择 **复制**获得页面生成的连接命令。

不要手工猜测端口或用户名。开发机重新配置公网访问后，应重新获取连接信息。缺少厂商实例 ID 时，页面只会展示平台记录的快照，不能查询实时端点。

### 发起连接

1. 确认本机使用的是与已登记公钥配对的私钥。
2. 在本机终端中粘贴页面复制的 SSH 命令。
3. 第一次连接时，按组织安全流程核对主机指纹。
4. 登录后确认开发机名称和工作目录，避免误操作其他环境。

Zenith 不会把你的私钥发送到开发机，也不会替本机保存 SSH Agent 配置。

### 公网、内网和 Zenith 中转

页面可能给出三种端点，含义不同：

- **公网直连**：本机可从允许的公网环境访问，但会增加暴露面，应配合最小化访问范围和密钥认证。
- **仅内网**：只有处于可达专网、VPN、跳板机或组织指定网络中的客户端才能连接。Zenith 会禁用当前部署不可达的网页终端。
- **平台中转 · 固定端口**：常见于资源区6 的开发机。这是平台为该机器分配的固定公网端口，云端跳板封装在中转内部。你直接连接页面给出的主机和端口即可，最终仍由开发机上的公钥完成认证。中转端口在机器重启后通常保持不变；若长时间连不上，先刷新端点，再联系平台管理员检查中转路由是否已分配。

部分开发机允许在详情中切换公网访问。切换后通常需要数秒生效，页面会重新获取端点。关闭公网访问后，旧公网端点不应继续作为连接依据。

网页终端是浏览器里的独立会话，不是这条 SSH 中转。总览、开发机列表和文件页使用定时刷新，只有终端走浏览器 WebSocket。

资源区1–4 和资源区6 还可能在开发机详情「连接」标签提供独立的 **应用链接**（运维视图不显示）：

- 资源区1–4 的云账号不能读取或创建公钥时，开发机仍可正常新建，但 SSH 不启用；请打开
  JupyterLab 应用链接。平台会尝试通过临时 Jupyter Terminal WebSocket 补写公钥，但该操作
  不会开启云端 SSH 端口。主账号预先登记平台终端公钥、并由平台管理员配置对应公钥 ID 后，
  新开发机才可直接绑定 SSH。
- 资源区6 若已分配中转端口，详情会显示“平台中转 · 固定端口”，请复制该命令，不要改用手写内网地址。尚未分配中转端口时，可先用网页终端或 Web 应用入口。
- 资源区6 若只返回 `10.x` 集群内网 SSH，Zenith 会把它标为内网并禁用当前部署不可达的网页终端；配置过监听端口的 Web 应用可从应用链接打开。
- 资源区6 的 Code Server、JupyterLab 或 TensorBoard 必须先在开发机内启动；没有监听端口时不会把占位地址显示成可用应用。
- 应用链接可能要求相应云账号会话，Zenith 不会代替用户确认云服务协议或登录。

::: warning 非必要不要开启公网 SSH
优先使用组织提供的内网连接或网页终端。不要为了临时排障长期开放公网访问，也不要使用弱口令替代密钥认证。
:::

## 网页终端

网页终端适合在浏览器中快速进入运行中的开发机，无需把私钥上传到浏览器页面。

### 打开 Web 终端

1. 在 **我的开发机** 的 **更多 > Web 终端**，或开发机详情 **连接** 标签的 **Web 终端**，或 **连接** 弹窗中的 **打开 Web 终端**。三处使用同一条可用规则：开发机必须运行中、有可达的 SSH 端点。
2. 等待状态从“连接中”变为“已连接”。
3. 连接后先确认当前主机和目录，再执行命令。
4. 完成工作后正常退出终端，并关闭抽屉。

网页终端通常要求：

- 当前用户具有资源操作权限，并且是开发机所有者（项目管理身份不能代替所有权）。
- 详情已显示厂商实例 ID；缺少该 ID 时无法打开终端。
- 开发机属于平台允许使用终端的队列。
- 当前厂商支持 SSH 访问，且端点不是当前部署不可达的纯内网地址。
- 开发机已授权平台终端公钥。

### 终端断开与重新连接

终端可能因开发机停止、网络变化、空闲超时、远端关闭或数据积压而断开。

断开后可选择 **重新连接**，平台会建立一个新的终端会话。重新连接不能恢复旧会话，也不能恢复旧会话的屏幕内容、当前交互状态或尚未保存的输入。

对于长时间运行的命令：

- 优先提交为训练任务；或
- 在开发机镜像已提供相应工具时，使用会话保持工具或可靠的后台运行方式；并
- 持续把输出和检查点写入持久存储。

不要把浏览器终端本身当作长任务的可靠运行保障。

## 如何判断连接成功

| 阶段 | 成功判断 | 常见延迟 |
| --- | --- | --- |
| 密钥登记 | 公钥出现在 SSH 密钥列表 | 通常立即显示 |
| 公钥注入 | 注入记录显示成功，并列出新增或跳过数量 | 开发机运行后数秒至更久 |
| SSH 信息 | 页面返回主机、端口和用户名 | 通常数秒；公网切换后需重新获取 |
| 本机 SSH | 出现远端 shell 提示符 | 取决于网络和密钥认证 |
| 网页终端 | 状态标签显示“已连接” | 通常数秒 |

开发机刚进入运行中时，SSH 服务和公钥注入可能尚未完成。等待片刻并刷新注入状态后再尝试，不要连续快速点击。

## 风险提示

- 私钥泄露会导致账号或开发机被冒用；不要把私钥粘贴到 Zenith 公钥输入框、聊天、工单或共享文件。
- 删除平台密钥记录不会撤销已有开发机中的公钥。
- 公网 SSH 会扩大网络攻击面；只有在业务需要且符合组织安全要求时开启。
- 重启、停止开发机或修改端口会中断现有 SSH 和网页终端会话。
- 网页终端重连会创建新会话，不能恢复旧会话。
- 更新开发机 SSH 公钥或端口时可能覆盖已有完整配置，提交前先核对所有需要保留的项。

## 常见问题

### 为什么开发机运行中，但没有 SSH 信息？

当前厂商或资源类型可能不提供连接端点，SSH 服务也可能仍在初始化。先刷新开发机详情并查看能力提示；多个同步周期后仍无结果，再联系平台管理员。

### 为什么显示内网地址，本机却连不上？

内网端点要求网络可达。确认是否已经接入组织 VPN、专网或指定跳板环境；不要自行开放未知网络入口。

### 为什么出现公钥认证失败？

确认本机私钥与 Zenith 中登记的公钥配对，检查注入记录，并对已有开发机执行一次“补注入公钥”。如果密钥刚新增，等待注入完成后再试。

### 为什么“Web 终端”按钮不可用？

常见原因包括没有资源操作权限、不是开发机所有者、缺少厂商实例 ID、开发机不属于允许的平台队列、厂商不支持 SSH、端点仅内网不可达，或开发机缺少终端公钥授权。以按钮旁的能力或权限提示为准。

### 重新连接能回到原来的 shell 吗？

不能。**重新连接会创建新会话，不能恢复旧会话。** 如需保存长期交互状态，请使用开发机中已安装的会话保持工具，或改用训练任务运行长作业。

### 删除 SSH 密钥后，旧私钥为什么还能登录？

因为平台删除只影响后续注入，已经写入开发机的公钥仍然存在。需要在开发机中移除对应公钥，并重新验证访问权限。
