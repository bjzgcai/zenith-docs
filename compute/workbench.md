# 我的开发机

侧栏「工作台」分组是普通用户登录后的主要入口。**我的总览**只放提醒、4 个指标、「我的卡时与项目」和「资源区余量」，具体操作在**我的开发机、我的训练任务、镜像、我的存储、数据集**等页面。云平台、原生队列、资源池标识和完整容量只在平台管理员视图维护；普通用户只看到按资源区显示的参考余量：我的总览按不具名的队列列出空闲卡数，新建窗口显示所选规格的短时参考余量。

::: tip 想系统了解开发机的完整使用与生命周期？
阅读[开发机使用与生命周期最佳实践](/compute/instance-lifecycle)，获取从创建、连接、保存环境到停止/删除/保存镜像的完整决策方法。
:::

## 适用角色与界面路径

| 项目             | 说明                                         |
| ---------------- | -------------------------------------------- |
| 适用角色         | 所有已登录用户                               |
| 总览路径         | **工作台 > 我的总览**           |
| 开发机路径       | **工作台 > 我的开发机**         |
| 文件路径         | **工作台 > 我的存储**     |
| 项目             | **协作与支持 > 项目**                        |
| 创建、停止、删除 | 需要资源操作权限；最终以提交时的权限校验为准 |
| 算力规格         | 需要所属组织已获得平台管理员分配的 GPU 或 CPU-only 规格  |

普通用户和项目管理员都可在「工作台」分组查看自己拥有的资源。项目管理员的「开发机」页工具栏左侧有「我的 | 项目」切换，可查看项目范围的开发机；运维必须先用右上角切换器进入用户预览，才会显示「工作台」分组。更大范围的开发机见[开发机管理](/compute/instances)。

如果需要确认组织开关、组织分配的算力规格或自己为何看不到某个项目，请先打开
[组织与项目](/account/organization)。组织归属和项目成员关系相互独立。

新建 GPU 开发机时，「扣费顺序」默认先扣个人卡时，再扣「项目分配给我」，最后扣「项目池待分配」。可改为优先使用某一来源，
并取消「余额不足时按顺序继续扣减」，只使用一个来源；所选来源耗尽时平台会请求停机。
我的总览的「我的卡时与项目」按项目列出分配给我和项目池待分配。旧开发机保留原有扣费设置；训练任务按各自的扣费方式处理。

## 我的总览

**工作台 > 我的总览**只回答三件事：有什么需要处理、开发机用了多少、卡时还剩多少。页面自上而下依次是：

1. **工具栏**：右侧「新建开发机」「新建训练任务」，以及「更新于」时间和「刷新」（一次刷新全部区块）。只读账号的新建按钮不可用。
2. **提醒**（每条一行，按严重程度排列，没有时不显示）：只读账号、个人存储超额（附「去清理」）、欠款、「有 N 条上交请求待你确认」（点「去确认」进入项目详情 › 卡时）、「部分数据暂时无法加载」（附「重试」）。
3. **4 个指标**：运行中开发机（运行数 / 总数，进入我的开发机）、运行中 GPU（只计运行中的开发机）、个人可用卡时（进入我的用量）、项目可用卡时合计（进入项目）。
4. **我的卡时与项目**：一张卡片，宽屏时左右并排、窄屏时上下排列。
   - **个人额度**：可用卡时、本期已扣与额度、学生额度档位；本周期有低优训练任务时另显示「低优任务已用 X 卡时（不扣额度）」，没有时不显示。
   - **我的项目**：每个项目一行（名称 · 我的角色 · 状态 · 分配给我 · 项目池待分配）。可动用卡时多的项目排在前面；没有卡时池的项目（如已归档或只读）余额显示「—」。点项目名进入项目详情，点余额进入该项目的 **卡时** 页签；超过 5 个时点「查看全部」在卡片内展开。
   - 右上角「查看用量」进入我的用量，「全部项目」进入项目列表。
5. **资源区余量**：各资源区还有多少空闲 GPU 卡可以新建，按队列逐行列出，例如「A100 · 队列 1　剩余 12 卡」；资源区标题右侧是该区合计。
   - 队列只用「队列 1」「队列 2」这样的编号区分，不显示队列名称；编号按平台登记顺序固定，刷新后不会变。
   - 「专用，不可新建」是只供预约或专用的队列；「暂停使用」是队列暂未运行；「暂无数据」是还没有新的采集结果。部分队列没有数据时，合计显示为「已知剩余 N 卡」。
   - 右上角是数据时间：「更新于 hh:mm · N 秒前」；所有资源区都连不上时显示「接入节点离线」，某个资源区离线时该区标题显示「接入节点离线」。
   - 余量是平台定时采集的观察值，不是预留；新建时仍会检查规格库存、配额和卡时，以新建窗口的提示为准。

页面可见时每 60 秒静默刷新一次（资源区余量在其他区块加载完成后再读取），刷新期间保留旧数据；切到其他浏览器标签页时暂停，返回后立即刷新。读取失败时提醒区列出无法加载的部分，对应指标显示「—」，不会显示为 0。上交卡时、按周期分配和卡时记录不在总览里，统一在 **项目 › 项目详情 › 卡时** 处理，见[向项目提供个人卡时](#向项目提供个人卡时)。

### 个人额度与卡时口径

- **个人额度**：所属组织配置了周期额度时按周期额度计；否则按平台管理员设置的月度额度计；两者都没有时显示「未设个人额度（不限）」。我的总览、我的用量和新建开发机的「扣费顺序」使用同一口径。
- **周期**：周、月、半年或自定义天数。例如组织可给每位学生每周分配 `4 × 24 × 7 = 672` 卡时，并在每周一 00:00（北京时间）重置；重置只开始新的计量窗口，历史用量不会被删除，也不会自动启动已停止的资源。周额度不会在每月 1 日额外重置。
- **到达额度**：平台拒绝新的新建或启动请求，但不会强行停止已运行的资源。
- **已扣卡时**：按观察到的运行时长结算（约每 5 秒一次），数值可能带小数。启动和停止的边界取决于云端状态同步，开发机通常有约 30 秒的同步延迟；点击停止后统计不会立即停止增长。

只读访客仍能查看资源，但新建按钮会被禁用。

## 使用前提

- 当前账号可以正常登录。
- 平台管理员已配置至少一个可用算力规格及其内部平台/队列顺序，且用户有可选镜像。
- 用户配额未耗尽；GPU 开发机还需有可用卡时，CPU-only 不消耗卡时。如果选择项目，该项目还须有效且项目额度未耗尽。开发机可以不选项目。
- 使用 SSH 时，已经在 **账号设置 > SSH 密钥**登记公钥。
- 使用个人存储时，所属组织已开启该能力；使用存储桶时，平台管理员已为项目或公共范围绑定存储桶。

## 新建开发机

### 填写创建弹窗

进入「我的开发机」页面时首屏就是你的开发机列表；点击列表工具栏右侧的 **新建开发机** 会弹出新建窗口；列表支持按名称、厂商实例 ID 或 GPU 搜索全部开发机，筛选条件保存在地址栏，从详情点页面标题中的 **我的开发机** 返回时保持不变。

1. 在弹窗中填写名称，或直接留空由平台按时间自动命名（如 `dev-0828-1547`）。名称只能用小写字母、数字和中划线（4–32 位，字母开头、字母或数字结尾）；输入不合法字符（例如下划线）时输入框会立刻标红提示，不会等到提交才报错。
2. 选择 **算力类型**。GPU 先选型号再选卡数；CPU-only 选择平台管理员分配的 vCPU / 内存规格，首期仅支持资源区5。
3. 选择本次启动使用的镜像；默认随实际分配的资源区使用已登记的标准镜像，允许容量不足时自动回退；也可以搜索个人、项目或平台已登记的资源区镜像。长名称会在下拉列表中完整换行显示。选择资源区专属镜像后，目录开关和容量提示会按镜像所属资源区重新计算；资源区为“自动分配”时也会遵循镜像所属资源区。资源区 5 内的已登记镜像可随开发机自动分配，无需选择底层队列。容量快照仍是单个最佳候选的参考余量，不是区内资源总和。
4. 选择资源区或保留“自动分配”。所属项目是可选项；没有加入项目时留空，按组织个人额度创建。资源区选项保留编号并显示该区已开放的 GPU 卡型，不展示具体云平台名称。
5. 默认允许自动回退到只有公共存储的资源区。资源区5 候选容量不足时，可继续尝试资源区 2、3、4；资源区1–4 只挂公共存储，个人和项目文件保留在原资源区，不会自动同步。需要个人存储时选择对应模式；显式选择的镜像、资源区和存储挂载仍会限制分配范围。
6. SSH 由平台按资源区自动配置：资源区5自动开通公网 SSH，资源区6使用安全中继，资源区1–4使用厂商连接端点。平台管理员新建基础设施测试机时仍可显式关闭资源区5公网 SSH。
7. 如果所选资源区支持，可在“自定义端口”中添加最多 5 个 TCP 服务端口（资源区10 的常规开发机含 SSH，最多 4 个自定义端口）。普通用户只能添加私网端口；公网端口仅平台管理员可选。端口名称和容器端口不能重复，外部端口可留空由平台分配。
8. 核对弹窗下方的规格说明、端口和“将挂载”提示。
9. 选择 **新建**。提交成功后弹窗自动关闭，并提示“已提交新建，约 30 秒后出现在列表”。首次使用某个资源区需要准备存储时，可以先关闭窗口，平台在后台继续处理并在完成时提示一次。

资源区 5 会在符合镜像、项目和存储要求的可用队列中选择负载较低的位置，每台开发机的全部 GPU 必须来自同一队列。选路后沿用现有的准入和存储准备流程；已经开始准备存储或提交创建的请求会固定在原队列，避免重复创建。项目保留规则、训练任务和已有开发机的位置保持不变。

容量快照显示的是 **GPU 参考余量**，系统盘额度还需单独满足。即使显示有空闲 GPU，队列的云盘配额用满后也无法创建新开发机。多个候选队列都不满足时，错误信息会分别列出各队列的原因；不要把其中一个队列的 GPU 余量当作整个资源区都能创建的保证。

创建中的请求会占住所需 GPU，不能被其他请求重复使用。提交前某个候选队列检查失败或剩余容量被其他请求占用时，会继续尝试后续符合镜像、存储和资源区要求的队列；全部候选失败后，页面保留各队列的具体原因。已提交云端但结果尚不确定时，平台会继续核对原请求并保留占位，请通过创建进度查看结果。

镜像搜索匹配已登记的名称和原生地址，可输入 `pytorch`、`2.6` 等片段或完整镜像地址。可选择本人登记、当前项目成员可见的镜像，以及平台管理员导入并启用的平台镜像。

镜像按 **类别 → 版本 → 具体镜像** 选择。每个镜像归入一个类别，一次只选一个类别；**全部** 展示所有类别，**其他** 收纳未识别类别的镜像。选定类别后，可进一步选择已识别的版本；该类别没有可识别版本时，不显示版本选择框。

页面会读取当前资源区可用的已登记镜像，并在已加载清单中按名称或原生地址搜索。类别、版本和搜索词共同筛选结果；没有匹配结果时，可切回 **全部**、取消版本限制或调整搜索词。筛选不会自动更换已选镜像，当前已选项会保留供核对，即使它不匹配当前筛选条件。清单未完整加载或读取失败时，页面会提示，可点击 **刷新镜像** 重试。

镜像选择按资源区读取当前账号有权访问的清单。切换资源区后重新选择镜像；点击 **刷新镜像** 可读取最新登记状态。页面中已有的选择仍会在提交时核对，已失去访问权限、停用或移除登记的镜像不能用于新的创建。

选中后，镜像名称在输入框内单行显示，过长部分会省略；展开下拉列表可查看完整名称。

算力规格不代表资源已预留。平台按平台管理员启用的平台和队列顺序解析实际创建位置，提交时仍会检查可用性和配额。

### CPU-only 开发机

平台管理员完成 CPU 队列纳管后，还需配置 CPU 规格、创建路由、镜像与存储，并将规格分配给你的组织。
只有完成这些配置，创建窗口才会提供 CPU-only 选项；队列纳管本身不会自动分配规格。

CPU-only 首期使用资源区5的已纳管预付费 CPU 队列，只支持 **一般** 优先级。
按 vCPU / 内存选择规格，不需要选择 GPU 卡数或扣费顺序。CPU-only 不消耗卡时，
卡时余额为零也可申请；开发机台数、项目权限、镜像、存储配额和目录授权仍会校验。
学生最多同时使用两台开发机，CPU 与 GPU 合并计数，GPU 合计仍不超过两张。

容量提示同时显示 CPU 和内存参考余量。任一维度不足、容量样本过期或信息未知时，平台不会
据此创建资源，请刷新或联系平台管理员确认。正在创建及结果待确认的请求会继续占用 CPU / 内存，
不要重复提交。CPU-only 沿用现有镜像、存储挂载、SSH 和启停流程；首期不提供 CPU 训练任务
和 CPU 改配，也不能在 CPU 与 GPU 之间转换。

列表与详情仅在平台确认规格后显示 **CPU-only**。GPU 信息缺失会显示规格未确认，不会被当作
CPU-only。创建后请在详情核对运行状态、目录挂载与 SSH 连接；再次启动后也应等待运行状态确认。

### 判断创建是否成功

- 页面出现成功提示：表示请求已提交，不表示开发机已经运行。
- “我的开发机”出现新记录：表示 Zenith 已观察到该资源。
- 状态变为 **运行中**：开发机已经可以继续连接和使用。

新开发机通常需要约 30 秒或更久才会出现在列表中。请使用列表工具栏的「刷新」，不要因短暂看不到开发机而重复新建。

## 我的开发机

**工作台 > 我的开发机**以表格显示当前账号拥有的开发机，总数、分页和搜索都覆盖全部开发机：

- 名称，以及名称下方的厂商实例 ID（终端、SSH、监控都用它，不要和平台内部编号混淆）。
- 资源区（悬停查看区域 / 可用区）。
- 算力：GPU 型号与卡数，或 CPU-only 规格；低优开发机带「低优」标记。
- 状态：操作提交后在状态旁显示「停止中（等待确认）」等提示；有待审批的扩容申请时显示「扩容申请中」。
- 利用率、SSH 端点类型（公网 / 内网 / 中转）和最近操作时间（悬停查看完整时间）。

勾选「显示已删除」才会列出已删除（含自动回收后释放）的历史开发机；这些行只显示「已删除」状态，不再显示 SSH 和过期提示。

**点击任意一行即可进入该开发机的详情页。** SSH 连接方式、云盘与挂载明细、监控、状态日志、应用链接和项目归属都集中在详情页，不再平铺在列表里。

详情页的“SSH 连接”直接显示可复制执行的命令，例如 `ssh -p 2200 root@gpu.example.test`。点击“复制命令”后可粘贴到本机终端；“连接详情”继续提供主机、端口、用户名、密钥状态和排障信息。

详情页的页面标题显示为 **我的开发机 › 开发机名称**（项目管理员从项目范围进入时为 **开发机 ›**，运维与平台管理员为 **开发机管理 ›**），点前半部分回到列表。顶部一行显示名称、状态、资源区和与列表相同的操作；内容分「概览 · 连接 · 监控 · 日志 · 设置」五个标签，停机原因和数据安全提示保持可见。

启动或停止操作返回后，页面立即读取平台记录，列表与详情共享同一个状态值，如“排队中”“创建/启动中”“停止中”，不会用“请求中”代替机器状态。实际启动、停止完成仍以随后同步的“运行中”“已停止”为准。请求失败、超时或状态刷新失败不会让前端自行猜测机器状态；请先刷新确认，勿重复提交。详情页顶部的「刷新」会同时更新云端配置与平台状态。

详情页的状态日志除生命周期事件外，还记录该开发机自己的计费流水：进入运行状态时写入**开始计费**（规格 + 当时剩余额度），停止时写入**停止计费**（本次运行时长、精确卡时消耗、结算后剩余额度）；启动或扩容因额度不足被拒时，拒绝原因同样落在日志里。

停止记录会保留平台已知的停止原因；如果只观测到资源区停止、找不到对应的平台命令，则显示原因未知，不把它推断成“额度耗尽”。重新启动不会清除过去的停止说明。已停止资源仍可打开历史；从运行变为停止时会补读最终状态，并在约 10 秒后再读取一次，以收齐稍后写入的计费记录。

### 扩容云盘

<!-- Older links (account/feedback) point here as #申请云盘扩容. -->
<a id="申请云盘扩容"></a>

资源区5 的开发机支持申请扩容已有云盘。在自己的开发机上打开 **更多 → 扩容云盘**，填写
**扩容后的总容量（GiB）** 和 **申请原因**，提交给平台管理员审批。例如当前 100 GiB、希望增加 40 GiB，
目标容量应填 140。扩容只能增大容量。

在左侧 **我的工单 → 云盘扩容** 查看审批和执行进度。待审批时可以撤回；同一台开发机有未完成的申请时，「扩容云盘」显示为禁用并提示「已有待审批的扩容申请」。
平台管理员在 **工单受理 → 云盘扩容审批** 批准或驳回，驳回时会填写原因。

批准后平台会重新核对开发机归属、当前容量和队列剩余云盘配额，再后台执行。**已批准不等于扩容完成**：
只有云端确认容量达到目标后，工单才显示“扩容完成”。容量不足或云端拒绝时会展示具体原因；长时间没有
确认结果时显示“需平台管理员核查”，系统继续核验，不会重复扩容。完成后请在开发机内确认文件系统可用容量。

若平台管理员给你分配了挂载盘，**我的存储 › 挂载** 还会列出“挂载盘”。挂载盘是已经存在的存储，登记和删除只改平台记录，不会在云上新建或销毁数据。新建开发机时可勾选；资源区6 的开发机可在确认重启后追加挂载。文件可在 **我的存储** 按挂载盘浏览。

同一资源区内如果多台开发机挂了不同的旧个人存储，页面会提示新老机器的 `/personal_fast_storage` 内容不互通。需要合并时联系平台管理员做一次明确迁移，平台不会自动搬数据。

资源区1–4 当前的个人和项目存储在新建后需另行挂载；资源区6 只列出所选资源池明确授权的存储。
两种情况下，新建窗口没有挂载候选时都可以不挂载存储直接新建，不要手填存储 ID。

资源区1–4 的 A100 专属池按单卡 `80GB 显存 + 12 核 + 120GB 内存` 线性组合。2 卡规格就是同一台
开发机的 24 核 / 240GB，4 卡和 8 卡同理，不会拆成多台开发机。专属池已预付，开发机配置显示
¥0/时；框架镜像的 25--50GB 系统盘是非持久存储，重要数据不要只放在系统盘。

开发机详情「连接」标签中的 **应用链接** 按资源区实际提供的入口展示：资源区1–4 提供 JupyterLab；资源区6 只有在
开发机配置了监听端口后才显示 Web 应用预览。资源区6 返回 TensorBoard 链接不代表服务已经启动，
仍需先在开发机内运行 TensorBoard。Code Server、JupyterLab 等自建应用同样需要先启动服务并
配置监听端口。

网页终端和外部 SSH 的准备步骤见[连接开发机](/compute/connection)。

## 我的文件

**工作台 > 我的存储** 只列出平台已确认你有权使用的存储，不允许自行输入桶名或路径：

1. **个人存储**：所属组织开启、规格启用个人存储，并且新建时挂载后，位于 `/personal_fast_storage`。
2. **项目存储**：被项目的负责人或管理员显式加入项目、项目开启存储，并且新建时挂载后，位于 `/project_<identifier>`。组织成员身份不会自动获得它。项目角色为只读的成员只读，其他成员读写。资源区1–4 当前不能由平台自动挂载这两类目录，新建窗口也不会承诺这两条路径。
3. **公共存储**：组织开启后，开发机内可能额外出现 `/public_fast_storage` 或 `/data` 下的公共、个人、项目子目录。
4. **挂载盘**：平台管理员分配给你或项目的已有存储，按登记的挂载路径浏览。
5. **项目存储桶**：只显示自己显式加入的项目所绑定的存储桶，可以浏览、下载；读写授权时可上传、新建目录或删除。
6. **公共存储桶**：只有所属组织开启后才显示；具体只读或读写由平台管理员配置。

个人、项目、公共存储和挂载盘可以在网页里浏览和传输小文件，但需要一台**运行中且已挂载该存储**的开发机。没有这样的开发机时，页面会提示先启动或新建开发机，而不是报成存储不存在。网页单文件上限以页面显示为准；更大的文件请直接在开发机里读写。

存储桶的上传和下载使用短时地址，不会把平台访问密钥发给浏览器。单文件上限以页面提示为准（常见约 200 MiB）。访客（只读）可以浏览和下载；上传、新建目录和删除还要求普通用户及以上平台角色、项目角色不是只读，并且对应绑定为“读写”。大文件或跨资源区复制请用[文件迁移](/data/file-migrations)。存储的完整说明见[我的存储](/data/storage)。

## 镜像

进入 **镜像**，按资源区查看个人、项目和平台环境。资源区5 与资源区10 提供 **登记镜像**，填写完整地址后选择仅本人或项目成员可见。平台管理员从云平台目录中导入平台镜像，并维护启用状态。

资源区5 与资源区10 的开发机均可在自己的开发机详情「设置」标签中使用 **保存为镜像**。运行中开发机的环境保存成功后，会自动加入对应资源区的个人镜像；使用平台配置的云账号和仓库授权，无需另填凭据。详情见 [镜像登记与导入](/assets/images)。

## 风险提示

- 新建开发机可能立即产生费用和消耗项目额度。
- 手动删除开发机会立即释放、无法恢复；停止也不代表所有附属资源停止计费。
- 镜像可能引用当前账号无权访问的外部资源，实际创建仍可能失败。
- 公开 SSH 会增加攻击面，非必要不要开启。
- 文件列表、算力规格可用性和开发机状态都可能有短暂延迟，不应据此连续重复操作。

## 常见问题

### 为什么“新建”按钮不可用？

检查是否已填写名称、选择组织分配的算力规格和镜像。所属项目不是开发机必填项；没有项目时留空即可。如果没有可用规格，请联系平台管理员配置逻辑规格和内部路由；如果按钮可点但提交被拒绝，继续检查操作权限、个人配额和卡时额度（选择项目时再检查项目配额）。包内规格失败时先看容量和配额，不要先怀疑账号余额。

### 为什么不能选择厂商或队列？

普通用户选择 GPU 型号和卡数，或 CPU-only 的 vCPU / 内存规格。厂商、队列、资源池、Flavor、可用区和优先级由平台管理员在逻辑算力规格中统一配置，避免越过组织的纳管边界。

### “我的开发机”为什么只看到一部分开发机？

工作台面向当前用户自己的开发机。项目管理员或运维请在 **开发机** / **开发机管理** 查看更大范围；训练和推理工作负载则分别在对应页面查看。

### 个人 Fileset 创建失败，还能创建开发机吗？

可以。云端明确返回个人 Fileset 创建失败后，页面会询问 **是否不带个人存储创建？**。
选择 **不带个人存储创建**，才会继续提交；本次的项目、公共存储和其他已授权挂载保持原选择。
选择 **取消** 不会创建开发机。未挂载个人存储时，请将重要文件保存到已挂载的项目或公共存储，或及时下载。

如果请求仍在处理或结果待确认，请先等待核实，不要重复创建。

### 队列有余卡，创建为什么仍失败？

余量可能已被其他请求占用，也可能受可用区、具体规格、个人配额、项目配额或卡时额度限制。以创建时的错误提示为准。

### “可能排队”表示什么？

创建窗口展示的是所选逻辑规格在具体纳管资源中的短时容量快照。窗口可见时约每 15 秒刷新，切回浏览器页面或重新打开窗口时会立即重新获取；样本最多缓存 60 秒，超过 90 秒会显示“容量快照已过期”，不会继续据此判断当前可用。快照不会预留 GPU。参考余量少于所需卡数时，平台仍允许提交，由厂商决定排队或拒绝。Zenith 不会在厂商没有提供统一接口时猜测队列位置或等待时间；余量未知也不等于确定没有资源。

### 镜像已经登记，为什么拉取失败？

登记镜像地址不会同步仓库凭据。确认地址完整、目标区域可达，并由平台管理员检查云端拉取权限。

### “我的存储”提示需要运行中的开发机？

个人、项目、公共存储和挂载盘的网页读写要经过一台已挂载该路径的运行中开发机。先启动或新建符合条件的开发机，再点“立即检测”。存储桶的浏览不需要开发机。

### 如何开始第一次创建？

按[快速开始](/guide/quick-start)完成 SSH 密钥、创建、连接和停止的完整流程。

如果是在替换旧开发机，先阅读[新开发机与存储迁移](/data/storage-migration)，不要直接删除旧机。

## 向项目提供个人卡时

在 **项目 › 项目详情 › 卡时** 点击 **上交**，填写数量和原因说明，把个人卡时上交到项目池。项目管理员也可以发出 **请求上交**，你会在我的总览看到「有 N 条上交请求待你确认」，在项目详情 › 卡时的「记录」中同意或拒绝。
待确认的请求不会扣款。确认前请核对数量、用途、当前余额和到期时间；项目管理员和平台管理员都不能代替本人同意。
具体步骤及退出项目后的返还规则见[项目详情 › 卡时：上交、分配与收回](/projects/quotas-billing#项目详情-›-卡时-上交、分配与收回)。
