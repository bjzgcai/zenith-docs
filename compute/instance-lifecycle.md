# 开发机使用与生命周期最佳实践

本文面向普通用户和项目管理员，总结从登录 Zenith 到长期管理开发机的完整最佳实践。如果你还没创建过开发机，建议先阅读[快速开始：创建并连接开发机](/guide/quick-start)。

## 登录后第一件事：完成前置准备

在新建开发机之前，先确认以下事项已经完成或已了解：

| 检查项                | 为什么重要                                           | 操作位置                         |
| --------------------- | ---------------------------------------------------- | -------------------------------- |
| 账号已加入正确的组织  | 组织决定可用的算力规格、存储和镜像                   | 协作与支持 > 我的用量 › 组织与配额 |
| 已登记 SSH 公钥       | 网页终端和外部 SSH 都需要公钥授权                    | 账号设置 > SSH 密钥                |
| 了解个人/项目卡时额度 | 避免创建后因额度不足被立即停机                       | 工作台 > 我的总览   |
| 知道数据应该写到哪里  | 系统盘不一定是持久的，长期数据应写入持久存储         | 见下文“数据持久化”               |
| 已确认可用的镜像      | 不同资源区镜像不互通，创建前需确认目标区域有可用镜像 | 工作台 > 镜像                    |

::: tip 先创建一台“验证机”
第一次使用新组织或新资源区时，建议先创建一台最小规格（如 1 卡）的开发机，验证 SSH、挂载路径和镜像可用性，再创建正式工作环境。
:::

## 新建开发机时的决策清单

### 1. 命名规范

- 使用能反映用途的名称，例如 `dev-llama-finetune`、`exp-deepspeed`。
- 避免在名称中写入密码、密钥、项目名称缩写或其他敏感信息。
- 多人协作时，建议在名称中包含自己的标识，方便项目管理员识别。

### 2. 选择 GPU 型号与卡数

- **够用即可**：开发机的主要用途是调试代码、验证数据和轻量训练，不需要一次性申请最大卡数。可以先申请最小可用规格，需要时再调整卡数（仅限同型号支持变配的资源区）。
- **注意同型号限制**：调整卡数通常要求目标规格与原规格属于同一 GPU 型号。`A100` 与 `A100 80GB` 一般视为同型号，但 `H100` 不能改成 `A100`。
- **开发机不是训练集群**：如果需要运行完整训练任务，请使用[训练任务](/workloads/training)页面，而不是把开发机当作长期训练节点。

### 3. 选择镜像

- 优先选择平台已启用、与目标代码匹配的官方镜像。
- 如果项目有维护团队镜像，优先使用项目镜像，保证依赖一致性。
- 镜像选择直接影响创建到的资源区；选择某资源区专属镜像后，平台会按该镜像所属资源区路由。
- 更多选择方法见[如何选择合适的镜像](/assets/choosing-images)。

### 4. 选择资源区与优先级

- **自动分配**适合大多数场景：平台会按平台管理员配置的顺序，在满足镜像、项目和存储要求的前提下选择可用队列。
- 如果需要个人存储或项目存储，不要选择只挂公共存储的资源区，否则个人存储和项目存储不会挂载。
- **低优开发机**可以借用空闲资源，但可能在资源紧张时被回收。只把低优用于可中断、数据已保存到持久存储的临时调试。

### 5. 项目与扣费顺序

- 开发机可以不选项目，按个人额度创建。
- 选择项目后，任务归属、存储授权和通知都会关联该项目；扣费默认先用个人额度，不足时按所选顺序使用项目额度。
- 如果只想使用项目额度，可以在创建窗口调整「扣费顺序」。

### 6. 挂载与数据位置

- 创建窗口下方的“将挂载”提示会列出本次创建挂载的存储路径，请仔细阅读。
- 不要把重要数据只放在系统盘或 `/root` 目录下。系统盘在不同资源区的持久性策略不同，停止或删除后可能丢失。
- 长期数据应写入个人存储、项目存储或挂载盘等持久存储。

## 创建或开机等待过久

开发机处于 **排队中（Pending）**、**启动中** 或 **重启中** 时，可以立即在“我的开发机”、开发机详情或「开发机管理」列表点击 **强制关闭**，无需等待 5 分钟。用户可以关闭自己的开发机，运维可以关闭平台管理的开发机；手机端也有相同入口。

确认后会发送停止命令，保留开发机、系统盘和挂载存储。请等状态变为“已停止”后再开机，不要重复创建。若资源区已开始运行或启动批次变化，平台会提示刷新，避免用旧页面取消新的启动。

这是手动操作，等待时间不会自动触发关机。该入口适用于各资源区；资源区服务尚未升级或状态无法核实时会明确提示，平台不会假报关闭成功。如果开发机已进入运行状态，请刷新后使用普通停止操作。关闭是否成功以资源区确认结果为准；若资源区暂不允许中断当前重启步骤，页面会显示失败原因。

## 数据持久化最佳实践

### 应该保存在持久存储的内容

- 代码仓库（建议同时也提交到 Git）。
- 训练数据集、预处理结果、模型检查点。
- 实验日志、TensorBoard 事件文件。
- 自定义环境配置文件（如 `requirements.txt`、`environment.yml`、`Dockerfile`）。

### 不应该依赖系统盘保留的内容

- 系统盘上的临时下载文件。
- 未提交的代码修改。
- 安装到系统盘但没有导出配置清单的软件包。

### 目录使用建议

| 路径                                           | 用途                   | 是否持久         |
| ---------------------------------------------- | ---------------------- | ---------------- |
| `/personal_fast_storage`                       | 个人存储，长期保留     | 是（按组织配置） |
| `/project_<identifier>`                        | 项目存储，团队共享     | 是（按项目配置） |
| `/public_fast_storage` 或 `/data` 下的公共路径 | 公共存储，组织公共数据 | 是（按组织配置） |
| 挂载盘路径                                     | 平台登记的已有存储     | 是               |
| `/root`、`/tmp`、系统盘其他路径                | 临时使用               | 不一定持久       |

::: warning 资源区1–4 的系统盘
资源区1–4 当前的系统盘在停止或重启后可能清空未挂载数据。创建弹窗和停止确认框都会再次提醒，请先把文件写到已挂载的存储或持久挂载盘。
:::

## 使用开发机时的日常习惯

1. **进入环境后立即检查挂载**

   ```bash
   df -h
   ls /personal_fast_storage
   ls /project_<identifier>  # 如果有项目挂载
   ```

2. **在工作目录创建软链接或约定目录结构**
   例如：

   ```bash
   mkdir -p /personal_fast_storage/projects/my-experiment/{code,data,checkpoints,logs}
   ln -s /personal_fast_storage/projects/my-experiment ~/my-experiment
   cd ~/my-experiment
   ```

3. **安装额外依赖时记录版本**

   ```bash
   pip list > /personal_fast_storage/projects/my-experiment/requirements.freeze.txt
   ```

4. **定期提交代码到 Git**
   不要把开发机当作唯一代码存储。即使挂载盘是持久的，也建议每日提交。

5. **长时间运行的任务建议提交为训练任务**
   开发机受空闲规则影响，且可能因低优回收等原因被停止。超过数小时的重型训练应通过[训练任务](/workloads/training)提交。

## 生命周期决策：停止、删除还是保存镜像

### 暂时不用：停止

- 近期还会继续使用当前环境时选择停止。
- 停止前确保任务已结束、数据已保存。
- 停止不保证所有附属费用归零，仍可能保留磁盘、网络或其他费用。
- 停止后系统盘数据是否保留取决于资源区策略，不要把停止当作数据备份手段。

### 环境需要复用：保存为镜像

- 如果当前开发机中安装了较多依赖、配置了复杂环境，且希望未来复用，可以选择**保存为镜像**。
- 保存镜像时开发机必须处于运行中，保存期间不要停止、重启或修改文件。
- 保存成功后，镜像会加入对应资源区的个人镜像，可以在创建新开发机或训练任务时选择。
- 保存的是软件环境，不是挂载存储中的数据。不要把保存镜像当作数据备份。

### 不再使用：删除

- 确认数据已经备份到持久存储或 Git 后再删除。
- 手动删除会立即释放这台开发机及其云盘，不进入回收站、无法恢复；个人存储、项目存储、存储桶和挂载盘不受影响，历史记录保留。
- 删除开发机不会自动删除其挂载的存储或存储桶中的数据。

### 连续停机保留 30 天

平台管理的开发机按**连续停机时长**计算保留期，运行中的机器不执行自动删除。

| 阶段 | 平台处理 |
| --- | --- |
| 连续停机第 27 天起 | 每天提醒一次，共 3 天，并显示进入回收站的准确时间 |
| 连续停机满 30 天 | 软删除，进入回收站；云端实例和系统盘继续保留 |
| 进入回收站后 7 天 | 到期释放云端实例及系统盘，平台历史记录保留 |

已经超期或剩余不足 3 天的开发机，从首次提醒起给足 3 天，再保留 7 天。
每日提醒不会推迟截止时间。提前开机即可取消本轮回收，之后再次停机重新计时。

在回收站的 7 天内，机主或平台管理员可以点击**恢复开发机**。
恢复后机器仍保持停机，重新保留 30 天；开机仍需满足正常的卡时和资源条件。
开始释放后无法恢复。请在期限内保存系统盘上需要保留的数据。

自动回收不会删除挂载的个人、项目、公共持久存储。释放后的开发机记录仍可在
“我的开发机”中勾选**显示已删除**查看，状态显示为「已删除」。用户主动点击删除仍走原来的删除确认流程。

### 决策流程

```
是否还会继续使用这台开发机？
├── 是 → 停止（保留开发机环境）
│     └── 环境希望未来复用且难以重装？
│           ├── 是 → 先保存为镜像，再停止或删除
│           └── 否 → 直接停止
└── 否 → 数据是否已备份？
      ├── 是 → 删除
      └── 否 → 先备份数据，再删除
```

## 从开发机过渡到训练任务

很多用户先在开发机里调试代码，再提交正式训练任务。推荐流程：

1. 在开发机里完成代码调试、数据路径验证和入口命令测试。
2. 确认入口命令不依赖交互式终端、不硬编码节点信息。
3. 确认输出目录和检查点目录指向持久存储。
4. 使用[训练任务](/workloads/training)页面提交，或复制任务配置后修改。
5. 训练任务运行后，保留开发机用于后续分析；不需要时停止或删除。

## 常见问题

### 应该创建多大的开发机？

调试和代码开发通常 1–2 卡即可；需要验证多卡通信或 DDP 逻辑时，再创建与训练任务一致的卡数。不要盲目申请最大规格。

### 低优开发机可以用在正式工作中吗？

不建议。低优开发机可能因资源紧张被回收，没有 15 分钟预告保证（具体以页面提示为准）。只用于可中断、数据已保存的临时任务。

### 保存镜像后原开发机可以删除吗？

可以，但请确认：

- 镜像保存成功且已出现在镜像列表中；
- 挂载存储中的数据已经单独保留；
- 没有未提交到 Git 的代码修改。

### 为什么建议定期停止不用的开发机？

运行中的开发机持续消耗卡时和额度。即使利用率低，也可能按运行时长计费。养成良好的停止习惯可以显著降低费用。
