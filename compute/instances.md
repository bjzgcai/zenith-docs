# 开发机管理

“开发机管理”（项目管理员菜单名为“开发机”）用于查看项目或全局范围内的开发机，并执行权限允许的生命周期、配置、监控和连接操作。普通用户管理自己的开发机请用 **我的开发机**；三个入口是同一个列表，操作按钮和确认文案完全相同。

## 适用角色与界面路径

| 项目           | 说明                                 |
| -------------- | ------------------------------------ |
| 页面路径       | **开发机管理**（项目管理员：**开发机**）                |
| 可进入页面     | 项目管理员、运维、平台管理员 |
| 查看开发机       | 取决于当前用户类型和资源可见范围     |
| 创建和变更资源 | 需要普通用户及以上角色（访客只读）               |
| 普通用户入口   | **工作台 > 我的开发机** |

用户类型决定能否进入页面，平台角色决定能否执行变更；即使能看到开发机，也不一定能够启动、停止或删除。

## 首次创建的等待

资源区 10 首次使用时，需要准备个人存储并确认配额，可能等待数分钟。页面显示“正在准备持久化存储”期间，请保留当前创建请求，不要重复提交。只有存储确认完成后才会创建开发机；“请求已受理”不代表机器已创建。若页面停止等待但提示后台仍在处理，应继续查看同一请求的进度。

## 系统盘已满时的启动恢复

单台开发机报告系统盘已满（`DevEbsFull`）时，原因会显示在该机器的详情和历史记录中，不会因此阻止其他用户在同一资源区、同一队列创建或启动开发机。新请求仍需满足自身的 GPU、系统盘配额和权限条件；如果队列实际云盘配额不足，请联系平台管理员。

资源区5 的开发机出现该状态并持续 60 秒后，平台会尝试自动关机、扩容 5 GiB 并重新启动，默认每台最多自动扩容两次。超过预算或扩容失败时，请联系平台管理员；扩容只能增大系统盘，无法替代持久存储或数据备份。

## 开发机名称

平台名称支持 1–128 个字符，可使用中文、英文字母、数字和常用标点，内部及末尾空格会原样保留。名称不能以空白开头，也不能包含换行、制表符或其他控制字符。

新建开发机会由平台生成独立的 16 位云端名称，仅含小写英文字母和数字，不含空格或特殊字符；控制台仍显示您填写的平台名称。已有资源继续显示原名称。名称可以重复，操作和工单仍应使用页面提供的资源标识。

## 使用前提

- 当前环境至少有一个可用云厂商连接。
- 创建开发机时有可选的地域、可用区、规格、镜像和队列。
- 账号和所选项目的开发机、GPU、卡时等额度未耗尽。
- 需要 SSH 时已经登记公钥。
- 需要挂载存储时，提前确认存储来源、子路径、挂载路径和读写模式。
- 执行重建、调整规格或开发机更新前，已经备份重要数据并确认目标厂商支持对应能力。

## 低利用率自动关机

这项规则**默认关闭**。平台管理员可在开发机管理工具栏点击 **空闲回收策略**，查看最近 2 小时的 GPU 利用率、监控覆盖率、判断结果、回收预告和历史记录，分别设置“空闲自动回收”和“空闲提醒”。只浏览检查页面不会触发预告或关机。

**空闲提醒默认开启，自动回收默认关闭。** 即使关闭回收，平台仍约每分钟检测一次；满足连续两小时各 GPU 利用率均不超过 10% 的条件后，向资源所有者发送站内提醒，并在钉钉应用配置完成且账号已绑定时发送钉钉私信（配置机器人时进入独立单聊，兼容原企业应用工作通知）。平台管理员自己的开发机也可以收到提醒。

同一开发机、同一所有者和本次开机周期，每 24 小时最多生成一次提醒；发送失败会有限重试，结果不确定时不会立即重复发送。检查页面会显示未配置、未绑定、失败或“钉钉已受理”等状态。“已受理”不代表已送达或已读。空闲提醒本身不会安排关机。

开启后，平台约**每 5 秒检查一次**。开发机本次运行满 **2 小时**，且连续两小时内各张 GPU 的有效采样均 **≤ 10%** 时，进入回收预告。任一卡出现超过 10% 的读数，会重新等待两小时低利用率窗口。这里的利用率是 GPU 硬件利用率，与卡时额度消耗比例不同。

**CPU 利用率、显存占用和进程存在不再阻止低 GPU 回收。采样覆盖率仅供参考，不要求达到 95%，也不会把缺失时段当成 GPU 满载。**

没有有效 GPU 数据、最新采样超过 90 秒或无效、监控历史尚不足两小时，或中间连续断采超过 15 分钟时，继续等待数据。窗口起点允许最多 5 分钟的采集时间偏差。短时断采不会清空已有的低利用率历史。

平台管理员拥有的开发机不参加自动回收，但可收到空闲提醒；平台提交的训练任务也不参加。通过 SSH、终端或 `nohup` 在开发机内运行的程序，仍随该开发机一起管理；即使进程仍在，只要持续低 GPU 利用率满足规则，也会进入回收预告。

### 收到回收预告后

平台会先向开发机所有者发送站内通知，说明原因、开发机和**最早关机时间**，预留至少 **15 分钟**保存 checkpoint 和工作进度。控制台页面可见时，右上角通知铃铛约每 15 秒刷新，收到未读的近期预告会自动展开。钉钉应用配置完成且账号已绑定时，平台也会尝试发送同一条回收预告的钉钉私信（配置机器人时进入独立单聊，兼容原企业应用工作通知）；关闭“空闲提醒”不会关闭真正的回收预告。

请以预告中的**最早关机时间**为准。宽限从站内通知生成时开始，不从收到钉钉或阅读时开始；较晚收到消息不会重新获得 15 分钟。钉钉未配置、账号未绑定、发送失败或结果不确定时，站内预告仍有效，宽限不会因此延长。“钉钉已受理”不代表已送达或已读。平台管理员可在 **空闲回收策略** 的回收预告记录中查看原因、原定最早关机时间、发送状态和尝试次数；这些是通知发送记录，不代表已经关机。

宽限期间 GPU 利用率超过 10%、开发机归属或本次运行发生变化，平台会取消本次回收；之后再次满足条件时会重新预告。监控暂时缺失或云接口出错时只暂停执行，恢复后复用原预告时间，并重新核对关机条件。到期仍会核对当前状态和监控，满足条件才提交停止请求。旧预告会保留在通知历史中，不代表机器一定已关机。

停止原因和历史记录可在开发机详情查看。“已受理”只表示停止请求被接受；状态变成“已停止”后才表示完成。自动规则不会删除开发机，但停止会丢失内存中的进度，部分厂商的临时系统盘也可能丢失数据。请把重要输出保存到**已经验证挂载成功的持久存储**，不要仅依赖系统盘或容器内同名目录。

### 低优开发机让出队列资源

低优开发机使用另一套资源让出规则：同一队列有一般任务排队且空闲 GPU 不足时，平台先发送至少 **15 分钟**的站内回收预告，并在钉钉应用和账号身份可用时尝试发送私信，随后再次确认需求和容量。两种通知使用同一最早关机时间，钉钉发送或阅读状态不改变宽限。**低优开发机即使正在训练，也可能在预告期结束后被停止**；需求消失、容量恢复或核对失败会取消本次回收。

新建开发机默认选择“一般”。需要持续运行且不能承受队列回收的工作，应保持“一般”；明确接受可中断运行时才选择“低优”。一般开发机不会因队列让出规则被停止，但仍可能适用平台管理员开启的低利用率规则。厂商故障或厂商原生抢占不在上述平台预告保证范围内。

## 查找开发机

页面支持以下筛选方式：

- 资源区。
- 开发机状态。
- 队列。
- 仅看有 SSH 的开发机。
- 按用户名（显示名或登录名）、开发机名称、资源标识或 GPU 型号搜索，支持部分匹配。

搜索会查找当前可见范围内的所有分页记录，并与状态、资源区等筛选条件共同生效。查找某位用户的已停止开发机时，请先把状态切换为“全部状态”或“已停止”；浏览器的页面查找只能搜索当前已显示的内容。

修改筛选条件后选择 **搜索**；选择 **刷新**可立即获取当前筛选条件下的最新记录。

运维还可以切换 **平台管理** 和 **仅监控**：平台管理开发机必须由 Zenith 创建、
已经记录稳定的用户归属，并且仍位于平台管理员启用的平台管理的队列、资源池或区域。同一资源池中
由厂商控制台或其他系统创建、尚未被 Zenith 认领的开发机归入仅监控，只提供查看能力。

列表通常包含：

| 信息              | 如何理解                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 名称              | 用户创建时填写的名称或云端显示名称                                                                                       |
| 资源区与厂商实例 ID | 资源在实际云厂商中的身份。启动、停止、重启、删除、SSH、监控、终端和镜像构建都使用这个 ID，不要用 Zenith 内部编号代替 |
| GPU 与规格        | 当前已观察到的计算配置                                                                                                   |
| 状态与计费        | Zenith 最近一次确认到的云端状态；旁边可能有“包内 / 按量 / 计费未知”徽标                                                  |
| 队列 / 资源池     | 资源使用的容量范围；并非所有厂商都提供                                                                                   |
| SSH               | 是否返回连接信息，以及当前是公网还是内网                                                                                 |
| 地域与可用区      | 资源的云端位置                                                                                                           |
| 最近观测          | Zenith 最近确认到该记录的时间                                                                                            |
| 数据已过期        | 最近未能再次确认；详情页会在「最近同步」中提示，不等于资源已删除                                                         |

点击列表中的任意一行（或名称、“详情”按钮）都会进入该开发机的详情页。

::: warning 不要把旧状态当作云端实时结果
开发机列表是 Zenith 最近一次观察到的记录。创建、启动、停止或删除后，云端处理和状态同步都需要时间；「数据已过期」也不能作为资源已释放的依据。
:::

## 按资源区规格新建开发机

运维与平台管理员选择页面右上角的 **新建开发机**，进入「新建开发机（按资源区规格）」四步向导。

### 第 1 步：选择资源区

1. 选择当前显示为可用的资源区。
2. 阅读页面能力标签和限制提示。
3. 如果资源区不可选，先不要继续填写；等待连接恢复或联系平台管理员。

Zenith 不会根据价格、库存或性能自动替你选择资源区。

### 第 2 步：选择地域、可用区和规格

1. 选择地域。
2. 选择可用区。
3. 选择开发机规格，核对 CPU、内存、GPU 型号和 GPU 数量。
4. 页面要求时选择队列。
5. 查看队列容量或 GPU 余量提示。

资源区5 的部分计算模式要求同时选择队列和可用区。若页面允许手动填写标识，也应只填写平台管理员或云厂商已确认的值，不要猜测。

已售罄、不可用或容量不足的规格可能被禁用。余量信息只用于提交前参考，不代表资源已经预留。

::: info 资源区1–4 专属池的多卡规格
当前 A100 专属池以单卡 `80GB 显存 + 12 核 + 120GB 内存` 为基准。选择 2 / 4 / 8 卡时，
CPU 和内存对应变为 24 / 48 / 96 核和 240 / 480 / 960GB；这是**同一台开发机的多卡规格**，
不是创建多台单卡开发机。页面会结合队列实时 GPU、CPU 和内存余量禁用放不下的规格。
:::

### 第 3 步：配置开发机

根据厂商和计算模式，页面可能显示以下字段：

- 开发机名称。
- 所属项目。
- 镜像：逻辑规格创建按类别、版本和具体镜像依次选择，每次选择一个类别；**全部** 展示所有类别，**其他** 收纳未识别类别的镜像。没有可识别版本时不显示版本选择框。搜索在已加载清单中匹配名称和原生地址；已选镜像会保留供核对，不会因筛选自动更换。读取失败或清单未完整加载时可刷新重试；过长的镜像名会在下拉列表中完整换行显示。
- 计费方式。
- 系统盘大小或云盘类型。
- RDMA 开关。
- SSH 访问、公钥和公网 SSH。
- 资源区5、资源区10 的自定义 TCP 端口（当前连接声明支持时）：最多 5 条（资源区10 含 SSH 时最多 4 条），可填写名称、容器端口、可选外部端口和暴露方式；公网暴露仅平台管理员可用。
- 存储挂载来源（资源区5 的选项为 `TOS` / `vePFS`）、子路径、挂载路径和只读模式。

自定义端口用于开发机内自行启动的服务。服务必须监听 `0.0.0.0`，并满足安全组入方向规则；平台只提供 `IP:port`，不会自动提供 HTTP 域名、TLS 或应用登录认证。资源区10 的自定义端口依赖平台管理员预先登记的负载均衡，同一次新建中的端口必须使用相同暴露类别。实际分配地址以新建后的开发机详情为准；资源区10 的开发机停止再启动后可能换端口，需要重新复制。

项目仅用于 Zenith 中的用量归集、额度、通知和管理视图，不会让平台自动改变云厂商、区域或资源所有权。

资源区1–4 当前队列属于已预付专属资源池，向导固定显示“¥0/时”，不会让用户误选按需或
包年包月档位。框架镜像附带 25--50GB 非持久系统盘；停止、释放或厂商自动停止可能重置
其中数据。Zenith 默认关闭自动停止，当前个人和项目存储仍需新建后从云控制台挂载。

### 第 4 步：确认并提交

1. 逐项核对资源区、地域、可用区、规格、GPU 数量、镜像、队列和计费方式。
2. 核对项目、SSH 和存储挂载。
3. 查看报价和额度预检查结果。
4. 选择提交并等待页面反馈。

报价获取失败不一定阻止提交；额度预检查通过也不保证创建一定成功。实时库存、云账号权限和厂商最终校验仍可能拒绝请求。

### 创建成功的判断

- 页面提示创建请求已提交：请求已被接受，但资源可能仍在排队或创建。
- 列表出现新记录：Zenith 已经观察到开发机。
- 状态变为 **运行中**：开发机已具备继续连接和使用的基本条件。

创建后列表会自动刷新，但云端状态通常约 30 秒或更久才同步。不要因为短暂看不到记录而重复提交。

## 生命周期操作

操作列固定展示「详情」和当前状态可用的「启动 / 停止」；其余动作收在「更多」菜单里，按状态、权限和厂商能力显示：

| 操作       | 位置                   | 常见可用状态                                  | 结果与注意事项                                                                                             |
| ---------- | ---------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 启动       | 操作列按钮             | 已停止或节省关机                              | 提交后等待状态变为运行中，可能重新产生费用                                                                 |
| 停止       | 操作列按钮             | 运行中                                        | 提交后等待状态变为已停止；附属资源仍可能计费。资源区1–4 的系统盘在停止或重启后可能清空未挂载数据，确认框会再次提醒 |
| 重启       | 「更多」菜单           | 运行中                                        | 会中断当前连接和运行中的前台进程。资源区1–4 同样会提示系统盘可能丢失未挂载数据                                   |
| 扩容云盘 | 「更多」菜单           | 资源区5 的开发机，或已停止的资源区10 开发机，且你是平台管理员 | 只能增大。在「我的开发机」或开发机详情提交；平台核对实时容量和队列剩余云盘配额，新容量以稍后快照为准         |
| 发起迁移   | 「更多」菜单（平台管理员） | 有厂商实例 ID                                 | 跳转到文件迁移页并预填来源开发机                                                                             |
| 删除       | 「更多」菜单底部       | 支持删除的开发机                              | 有确认对话框；立即释放这台开发机及其云盘，不进入回收站、无法恢复；个人/项目存储、对象存储和挂载盘不受影响 |

选择动作并看到成功提示，只表示操作请求已提交。请等待列表状态更新后再进行下一项相互依赖的操作。

## 高级操作

“更多”菜单可能提供以下能力；是否显示以当前页面为准。

### 重建开发机

- 需要填写目标镜像标识。
- 重建会替换当前系统环境，可能清除系统盘数据。
- 提交前确认业务数据已经位于持久存储，并确认目标镜像可拉取。

### 调整规格

- 需要填写目标规格标识。
- 开发机可能需要停止或重启，具体规则由当前厂商决定。
- 目标规格仍受区域库存、配额和计费限制。

### 更新开发机

页面可能允许修改：

- 名称和描述。
- 队列、规格和可用区。
- 完整存储挂载列表。
- SSH 公钥。
- WebIDE、SSH 端口和公网访问设置。

系统盘扩容不走本表单。仅平台管理员可为资源区5 的开发机或已停止的资源区10 开发机扩容，请在开发机列表或详情使用「更多 › 扩容云盘」；资源区1–4 和资源区6 不提供根盘扩容。

::: danger 完整列表会覆盖已有配置
启用“更新存储挂载”后，页面会提交完整挂载列表；空列表表示清空挂载。端口配置也可能整体覆盖当前设置。提交前确保列表包含所有需要保留的项。
:::

填写 SSH 公钥可能整体替换开发机侧的配置，并在后续重启时重置授权文件。平台会尽量保留网页终端所需公钥，但仍应先确认个人密钥和连接方案。

### 取消厂商空闲关机

「更多」菜单只在资源区报告了厂商空闲关机计划时显示此项，执行前需要确认。这个厂商操作不等于取消 Zenith 的站内回收预告：平台会依据最新活动和资源需求重新核对，平台管理员也可关闭平台低利用率规则。低优队列回收使用独立的资源让出条件。

## 查看开发机详情

点击开发机名称进入独立详情页。状态、**本次运行时长**、**预计关机时间与倒计时**、常用规格、GPU、镜像、系统盘持久性、挂载和连接入口默认可见，停止原因与数据安全提示不会折叠。

**本次运行时长**从平台观察到本次进入运行状态开始计算，按分钟显示（例如“1 小时 30 分”），计时每分钟更新，并随约 15 秒一次的状态刷新及时校正。它不是开发机创建至今的时间，也不等于机器内的系统启动时间。未运行时显示“当前未运行”；无法确认本次运行起点时显示“本次开机时间待确认”，观察过期时显示“状态待刷新”，接口暂时不可用时显示“暂无法获取”。**累计运行时长**和**累计卡时**在「概览」的规格区显示。

**预计关机**只在平台已有有效回收预告时显示最早关机时间及剩余倒计时，包括空闲回收和低优队列回收。倒计时也按分钟显示，例如“约 15 分钟”或“不足 1 分钟”，计时每分钟更新。没有有效预告时显示“暂无预计关机时间”，不会按“开机两小时”推算关机时间；数据暂不可用时也不会把旧预告当成当前安排。倒计时归零时显示“等待核对并执行关机”，表示平台仍需核对条件并决定是否停止，不表示机器已关机。状态刷新确认取消预告或关停后会及时校正显示；预告证据过期时撤下倒计时，运行状态仍以平台最近的有效观察为准。分钟显示不会改变平台计费或回收规则。

详情分为「概览 · 连接 · 监控 · 日志 · 设置」五个标签，地址栏的 `?section=` 会记住当前标签；未打开的标签不读取数据。扩容云盘在页头「更多」菜单中（仅平台管理员）。「连接 › 连接详情」提供完整 SSH 命令、公钥注入状态和排障信息。

列表与详情共享平台记录的状态，云端实时查询只补充配置与连接信息。启动、停止操作返回后立即读取平台记录，按平台返回值显示“排队中”“创建/启动中”“停止中”等状态，不把请求进度当成机器状态，也不把命令任务的“运行中”当成机器已经开机。超时或网络中断时请先刷新确认，不要连续重复提交。点击“刷新详情”会同时读取最新配置与平台状态。缺少厂商实例 ID 时，详情、监控和 SSH 只能展示平台记录的快照。

详情随状态轮询重新获取配置、SSH 与应用入口，连接尚未就绪时会在后续刷新中重试；也可以点击“刷新详情”手动重试。刷新不会收起已展开的栏目或清空当前项目选择。

如果实时详情暂时获取失败，页面可能继续展示最近一次保存的记录。查看操作结果时，应同时关注刷新时间、列表「数据已过期」标签和详情中的「最近同步」。

### 状态日志不是应用日志

状态日志记录平台处理节点、资源状态变化和公钥注入等事件，不是容器标准输出，也不是训练程序日志。查看训练程序输出时，应进入[训练任务](/workloads/training)中的日志或诊断入口。

页面可见且开启“跟随”时，非终态资源的状态日志约每 10 秒更新，状态变化仍受云端同步延迟影响。转为停止状态后会补读最终历史，并在约 10 秒后再读取一次计费记录；已停止资源首次打开仍可读取历史，不会持续轮询。

停止历史会保留平台已知的停止原因。未匹配到平台停止命令时只显示“具体原因未知”，不能据此断定是额度耗尽或资源区故障；重新启动不会擦除已有停止说明。

### 日志中的计费与额度记录

带 GPU 的开发机进入运行状态时，日志会追加一条**开始计费**记录（规格与当时的剩余额度）；停止运行时追加一条**停止计费**记录，汇总本次运行时长、按 5 秒结算口径的精确卡时消耗和结算后的剩余额度。启动或扩容因额度不足被拒时，拒绝原因也会写入该开发机的日志，方便回查"机器为什么没有启动"。CPU 开发机没有卡时概念，不产生计费记录。

### 监控数据

“监控”标签展示平台采集的趋势；云端快照需点击 **从云端读取快照** 按需读取。不同厂商可能只返回部分指标；页面显示“未返回可展示的指标”不等于开发机一定没有负载。

## 连接与项目归属

- SSH 和网页终端操作见[连接开发机](/compute/connection)。
- 已有开发机可在详情中归入项目，用于用量、额度和通知聚合。
- 归入项目不会转移开发机所有权，也不会改变云端网络和资源位置。
- 将资源从其他项目改到当前项目可能需要更高权限。

## 刷新规则与成功判断

- 页面可见时，开发机列表约每 15 秒刷新一次；这是 REST 轮询，不是实时推送。
- 切到其他浏览器标签页后常规刷新会暂停；返回页面时会立即补刷新。
- 云端实例清单和状态通常需要约 30 秒一个同步周期，也可能更久。
- 生命周期、SSH、监控和终端请求都会带上当前行的厂商和厂商实例 ID。ID 为空时对应按钮会失败或不可用。
- 生命周期操作成功后，页面只确认请求已提交；以最终状态变化作为完成判断。
- 高级配置变更可能需要开发机重启或云端重新下发，按页面提示再次获取详情。

如果连续多个刷新周期没有变化，请保留开发机名称、资源区、页面提示和操作时间后联系平台管理员；不要提供密码或私钥。

## 风险提示

- 创建、启动和调整规格可能产生费用并消耗项目额度。
- 删除、重建和部分更新操作不可恢复，可能造成数据或连接配置丢失。
- 停止开发机不保证磁盘、网络或其他附属资源停止计费。
- 公网 SSH 会扩大网络暴露面。
- 挂载和端口更新采用完整列表时，遗漏项可能被覆盖。
- 列表状态、报价、队列余量和额度预检查都可能晚于实时云端情况。
- 厂商能力按当前环境动态提供，不要依据其他厂商或其他区域的经验强行操作。

## 常见问题

### 为什么我能看开发机，却不能操作？

进入页面和变更资源使用不同权限。查看范围还可能来自用户类型或项目成员关系；创建、启动、停止和删除通常需要普通用户及以上角色（访客只读）。

### 为什么操作成功后状态仍没变化？

成功提示表示请求已提交。等待至少一个状态同步周期并点击刷新；不要在旧状态下连续提交相同请求。

### 「数据已过期」是不是开发机已经删除？

不是。它只表示 Zenith 最近没有再次确认资源。应刷新实时详情，必要时由平台管理员到云厂商侧确认。

### 为什么没有重建、调整规格或监控按钮？

这些能力依赖厂商、计算模式、资源状态和权限。以页面能力提示为准，不能假定所有云厂商都支持相同操作。

### 为什么开发机有 SSH 信息却不能打开网页终端？

开发机可能不属于允许的平台队列，个人公钥尚未注入，或当前账号没有资源操作权限。按[连接开发机](/compute/connection#网页终端)检查前置条件。

### 普通用户在哪里看自己的开发机？

打开侧栏 **工作台 > 我的开发机**（见[我的开发机](/compute/workbench)）。

## 调整已有开发机的项目与公共存储

在自己开发机的「更多 → 调整存储挂载」中，可以追加本人已加入项目的存储，以及所属组织已启用的公共存储。只显示同一资源区的可用项目存储；挂载使用平台分配的目录和读写权限，不改变计费项目。项目管理员不能调整其他成员机器的挂载。

资源区5、资源区10 需先停机，保存后手动启动；资源区6 需要确认重启。保存期间该开发机的启动、停止、重启等操作暂时禁用，直到调整完成。项目已删除、停用或本人已退出项目时，现有挂载会标记为失效，必须先卸载或更新才能启动。只移除挂载入口，文件保留。资源区1–4 的项目隔离挂载仍待云端接口确认。

## 资源区10 开发机的 SSH 端口

启用动态 SSH 端口的资源区中，开发机停止或失败后会释放端口，开发机和文件仍保留。
重新开机会分配当前可用端口，请在开发机详情中重新获取连接信息，不要继续使用以前复制的地址。
云端配置更新期间需要稍等片刻；端口和 SSH 公钥准备完成后，平台才会启动开发机。
