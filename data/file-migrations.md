# 文件迁移

文件迁移用于在两个已支持的资源环境之间复制单个文件或目录。迁移过程会校验内容完整性，但不会替你判断目标文件是否应当被覆盖。

平台管理员还可以使用同一标签页下方的 **数据快传**，把本地单文件临时上传到平台中转存储，
再复制命令到资源区6 开发机下载。它适合临时快速传文件，不等同于下方有任务记录、校验和审批的文件迁移。

## 使用信息

| 项目 | 说明 |
| --- | --- |
| 适用角色 | 平台管理员 |
| 界面路径 | **存储管理 → 跨区传输**（预览）；从开发机详情的「迁移」入口进入时会预填来源信息 |
| 前置条件 | 平台已配置中转存储；迁移还要求源端和目标端均可用、源路径可读且目标目录可写 |

## 数据快传到资源区6

1. 在「数据快传」中填写准备上传的文件名，以及文件所在机器的本地路径。
2. 选择 30 分钟、1 小时或 3 小时有效期，然后生成快传链接。若提示链接仍在生成，稍后点按钮上的「查询结果」取回同一组链接，不会重复生成。
3. 复制上传命令，并在文件所在机器执行，把文件上传到中转存储。只修改本地路径时，已生成的链接保持可用。
4. 修改资源区6 开发机内的保存路径，复制下载命令，进入对应开发机后执行。命令会先设置平台配置的出网代理变量，再下载文件。
5. 下载完成后核对文件大小和内容，再开始使用。

链接和命令即凭据，拿到它的人在到期前可以访问对应对象，请勿发到公开群聊。中转对象最长约保留 24 小时。数据快传使用单次上传，目录、超大文件、需要 SHA-256 校验或审批记录时，使用下方正式文件迁移。

::: tip HTTP 页面也能复制
点击“复制”会打开已经全选的文本框。浏览器不允许自动写入剪贴板时，直接按 Ctrl+C（macOS 为 Command+C）即可。
:::

## 最重要的路径要求

源路径和目标路径必须是**迁移服务可访问的绝对挂载路径**，例如某个已约定共享挂载点下的文件或目录。

请特别注意：

- 路径必须以 `/` 开头。
- 不能使用根目录 `/`，也不能包含 `..` 这样的上级跳转。
- 路径必须是平台管理员确认可供迁移使用的挂载位置。
- 仅在计算实例内部存在的本地路径，不一定能被迁移服务访问。
- 表单中的源厂商实例 ID 和目标厂商实例 ID 只是可选的关联记录，不会授权路径，也不会让开发机内的目录自动变得可访问。

不确定路径时，请先向运维确认“迁移服务可访问的挂载路径”，不要使用猜测路径试传。

## 发起迁移

1. 打开 **存储管理 → 跨区传输**，在「迁移任务」中点击「发起迁移」。源资源区和目标资源区不能相同。
2. 选择“源资源区”。
3. 填写“源路径”，可以是单个普通文件或目录。
4. 按需填写“源厂商实例 ID”，仅用于记录关联资源。
5. 选择“目标资源区”，不能与源资源区相同。
6. 填写“目标路径”。文件迁移应填写完整目标文件路径；目录迁移填写目标目录位置。
7. 按需填写“目标厂商实例 ID”，规则与源厂商实例 ID 相同。
8. 再次检查目标位置是否允许覆盖，然后点击“发起迁移”。

如果当前开启了审批，提交后会先显示“待审批”；平台管理员审批通过后才开始复制。被拒绝时，将显示“已拒绝”，把指针停留在状态上可查看拒绝原因。

## 字段说明

| 字段 | 如何填写 |
| --- | --- |
| 源资源区 | 实际保存源文件或源目录的资源区 |
| 源路径 | 迁移服务可读取的绝对挂载路径 |
| 源厂商实例 ID | 可选，仅用于记录关联资源，不代表从开发机磁盘自动读取 |
| 目标资源区 | 目标文件应写入的资源区 |
| 目标路径 | 迁移服务可写入的绝对挂载路径 |
| 目标厂商实例 ID | 可选，仅用于记录关联资源，不会自动完成挂载 |

## 状态和刷新

| 状态 | 含义 | 你可以做什么 |
| --- | --- | --- |
| 待审批 | 等待平台管理员审批 | 检查路径；不再需要时可取消 |
| 排队中 | 已受理，等待执行 | 等待自动进入下一阶段 |
| 上传中 | 正在读取并传输源内容 | 保持源文件稳定，不要修改或删除 |
| 下载中 | 正在写入目标位置 | 不要同时写入同一目标路径 |
| 校验中 | 正在核对内容完整性 | 等待校验结束 |
| 已完成 | 目标内容已写入并通过校验 | 在目标环境核对文件名、大小和可读性 |
| 失败 | 某个阶段未完成 | 查看状态提示，修正原因后重新发起 |
| 已取消 | 后续阶段不会继续 | 检查目标位置是否留下临时或部分内容 |

进行中的任务（待审批之后、完成/失败/取消之前）约每 5 秒刷新一次进度；页面其余时间约每 15 秒刷新。你也可以点击页面顶部的「刷新」。最终成功判断应同时满足：状态为“已完成”，并且在目标位置能够读取预期内容。


## 目录和大文件限制

- 目录迁移最多处理 1,000 个普通文件。
- 空目录不能作为有效迁移内容。
- 符号链接会被跳过，不会复制其指向内容。
- 大文件会自动分段处理，无需手工切分。
- 目录会保留相对路径，但不会删除目标目录中原有的额外文件。

## 取消迁移

平台管理员可点击进行中或待审批任务右侧的「取消」并确认。取消通常在当前传输阶段结束后生效，**不会保证立即中断正在进行的单次读写**。取消后请等待状态变为“已取消”，再检查目标路径。

## 风险提示

::: danger 成功迁移可能覆盖目标文件
目标位置已有同名文件时，迁移在完成校验后会替换它。提交前请备份目标文件，或使用新的目标路径。目录迁移会逐个覆盖同名文件，但不会清理目标目录中多余文件。
:::

- 上传或下载期间修改源文件，可能导致校验失败。
- 取消不是瞬时停止；不要依赖取消来避免一次已经开始的覆盖。
- 失败任务不会自动完整重试。修正权限、路径、容量或可用状态后，需要重新发起。
- 目录中的符号链接不会复制；依赖链接的数据集应先整理为普通文件。
- 迁移期间应预留足够的目标空间。

## 常见问题

### 为什么绝对路径仍提示不可访问？

“绝对路径”只是格式要求，还必须是迁移服务实际可访问的挂载路径。请确认该路径已经按平台管理员要求挂载，并且源端可读、目标端可写。

### 为什么填写实例后仍找不到文件？

实例信息不会自动打开实例本地磁盘。只有已作为共享位置挂载并对迁移服务可见的路径才能使用。

### 任务长时间停在某个阶段怎么办？

先点击刷新并检查状态提示。如果源端或目标端不可用、容量不足或权限变化，请修复后重新发起；不要连续创建多个相同任务。

### “已完成”后还需要检查什么？

到目标挂载位置确认文件可以读取，并核对目录结构和业务所需文件是否完整。符号链接和超过目录上限的内容不在迁移结果中。

开始迁移前，也可先阅读[存储与文件](/data/storage)了解挂载点和容量字段。
