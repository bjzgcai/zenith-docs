# 新开发机与存储迁移

这份指南用于两类场景：

1. 新同学第一次新建开发机；
2. 已有旧开发机的同学把数据迁到新的个人存储标识和新开发机。

## 先记住三条

1. **长期数据放 `/personal_fast_storage`，不要只放 `/root`。**
2. **三个资源区的个人存储互不相通。** 在资源区5写入的数据，不会自动出现在资源区1–4或资源区6。
3. **项目不是新建开发机的前提。** 已加入学院组织、账号有资源操作权限的同学，即使没有加入任何项目，也可以新建组织分配的 1 卡开发机；项目还用于项目额度、用量归集和项目存储；组织可额外配置加入项目后的开发机卡数上限。

## 停止再启动后，`/root` 是否还在

2026-09-07 使用真实 1 卡开发机和哨兵文件完成了“写文件 → 停止 → 确认已停止 → 启动 → SSH 复查”：

| 资源区 | `/root` 停止→启动 | 应该怎么放数据 |
| --- | --- | --- |
| 资源区1–4 | **会丢失**。实测 SSH 主机密钥也发生变化，说明运行环境被重新创建 | 停止前必须复制到持久存储。该资源区暂不能由平台自动挂载个人存储和项目存储，此时不要停止唯一保存数据的机器 |
| 资源区5 | **当前会保留**，实测文件哈希一致 | `/root` 所在云盘适合环境和临时工作；重要数据仍建议放 `/personal_fast_storage` |
| 资源区6 | **当前会保留**，实测文件哈希一致，个人存储会重新挂载 | 长期数据以 `/personal_fast_storage`、项目存储或已分配的挂载盘为准 |

这里只验证普通的“停止→启动”。**重建、换镜像、删除或迁到另一台机器都可能清空 `/root`**。

## 新同学第一次创建

### 1. 准备账号

1. 确认学校邮箱已在钉钉个人资料或组织通讯录中填写。两处邮箱可能不同，组织通讯录中的邮箱不一定随扫码登录返回。
2. 重新扫码登录并完成授权。若仍未显示邮箱，请平台管理员检查应用的个人信息、成员信息及邮箱读取权限，以及组织通讯录可见范围；使用组织邮箱还需启用平台的组织通讯录邮箱读取功能。平台管理员也可以核实后补录邮箱。
3. 在右上角头像菜单 **账号设置 → 个人资料** 确认邮箱。平台管理员补录后可点击邮箱提示中的 **刷新状态**，无需再次退出。新账号的个人存储标识优先使用邮箱 `@` 前的部分，例如：

```text
s-gj24@bza.edu.cn   →  s-gj24
teacher@zgci.ac.cn  →  t-teacher
teacher@bza.edu.cn  →  t-teacher
```

`@zgci.ac.cn` 邮箱，以及邮箱前缀不是 `s-` 开头的 `@bza.edu.cn` 邮箱，都会建议使用 `t-` 开头的存储标识；已有 `t-` 时不重复添加。学生的 `s-` 前缀保持不变。新账号按该规则分配标识；已有目录需要平台管理员核对数据与挂载后再修改，不会自动改名。这个标识便于辨认目录，资源权限与配额仍由平台管理员分配。

已有账号的个人存储标识不会因补录邮箱自动改变，需要调整时请联系平台管理员迁移。缺少邮箱的钉钉账号只作为访客（只读），不能新建或启动资源；平台管理员账号不受此限制。

### 2. 确认组织与权限

- 打开 **协作与支持 → 我的用量**，在“组织与配额”中确认已加入学院学生组织或学院研究员组织。
- 没有项目也可以创建 1 卡开发机。
- 如果新建按钮仍不可用，请平台管理员确认平台角色是“普通用户”，并确认组织已分配 1 卡规格。

### 3. 登记 SSH 公钥

进入 **账号设置 → SSH 密钥**，登记自己的公钥。私钥只保存在自己的电脑，不要上传或发给他人。

### 4. 新建开发机

进入 **工作台 → 我的开发机 → 新建开发机**：

1. 选择 GPU 型号和 **1 卡**；
2. “所属项目”可以留空；
3. 选择资源区，或保留自动分配；
4. 能看到“个人存储”时保持开启；
5. “公共存储”仅在该资源区已就绪时出现，按需开启；
6. 提交后等待状态变为“运行中”。

SSH 连接由平台自动配置：

- 资源区5自动开通公网 SSH；
- 资源区6自动分配 Zenith 安全中继；
- 资源区1–4使用厂商提供的公网连接端点。

### 5. 首次验收

连接后运行：

```bash
hostname
df -hT /
df -hT /personal_fast_storage 2>/dev/null || true
```

如果新建时开启了个人存储，再做一次持久存储读写检查：

```bash
mkdir -p /personal_fast_storage/.zenith-check
date -Is > /personal_fast_storage/.zenith-check/first-write.txt
sync
ls -l /personal_fast_storage/.zenith-check/first-write.txt
```

## 从旧开发机迁移

### 个人存储准备失败或提示等待迁移

资源区5 为每人启用独立个人存储后，存储数量不足、配额或挂载权限设置失败都会阻止新建，
不会改用旧目录或无配额目录。请联系平台管理员解决存储问题后重试；已经分配的个人盘不会因此删除。

如果提示“个人存储尚未完成 Fileset 迁移”，需要平台管理员先停止相关写入、复制并校验数据、
切换旧机挂载后解除限制。新机只挂载正式个人盘，不再自动附加旧目录；旧机不会自动变更。
不要自行把同名 `/personal_fast_storage` 当成数据已经迁完的证据。

### 1. 先判断是否真的需要复制

- 旧机和新机在**同一资源区**，且都挂载同一个 `/personal_fast_storage`：个人文件本来就是同一份，无需复制。
- 页面提示新旧机器的个人存储不一致：先联系平台管理员迁移旧卷，不能自行假设两个同名挂载点内容相同。
- 迁往另一个资源区：必须显式复制；不同资源区不会自动同步。

### 2. 把旧机 `/root` 中的重要内容放到个人存储

推荐只复制项目代码、数据、脚本和必要配置，不要整盘复制缓存、驱动和系统文件：

```bash
OLD_HOST="$(hostname)"
TARGET="/personal_fast_storage/migrations/${OLD_HOST}/root"
mkdir -p "$TARGET"

# 按实际目录逐项复制，示例：
rsync -aHAX --info=progress2 /root/work/ "$TARGET/work/"
rsync -aHAX --info=progress2 /root/projects/ "$TARGET/projects/"
```

如果确实要复制整个 `/root`，先检查个人存储剩余额度，再排除缓存和已经挂载的目录：

```bash
rsync -aHAX --numeric-ids --info=progress2 \
  --exclude='.cache/' \
  --exclude='personal_fast_storage/' \
  --exclude='public_fast_storage/' \
  /root/ "$TARGET/"
```

Conda、Python 环境建议同时导出清单，避免把与旧镜像强绑定的二进制环境直接搬过去：

```bash
conda env export --no-builds > "$TARGET/conda-environment.yml" 2>/dev/null || true
python -m pip freeze > "$TARGET/requirements-freeze.txt" 2>/dev/null || true
```

### 3. 校验旧机备份

```bash
du -sh /root/work /root/projects 2>/dev/null
du -sh "$TARGET/work" "$TARGET/projects" 2>/dev/null
rsync -aHAXn --itemize-changes /root/work/ "$TARGET/work/"
rsync -aHAXn --itemize-changes /root/projects/ "$TARGET/projects/"
```

最后两条命令没有列出差异，才表示这两项已同步。不要为了“看起来一致”随意加 `--delete`。

### 4. 创建并验收新机

1. 在同一资源区新建开发机，开启个人存储；
2. 确认迁移目录存在：

```bash
ls -la /personal_fast_storage/migrations/
```

3. 直接在个人存储中工作，或复制少量运行文件回 `/root`：

```bash
mkdir -p /root/work
rsync -aHAX /personal_fast_storage/migrations/<旧主机名>/root/work/ /root/work/
```

资源区1–4不要把复制回 `/root` 的内容当成唯一副本；下次停止仍会丢失。

### 5. 旧机冷静期

- 新机连续使用并核对数据至少 7 天；
- 确认 SSH、环境、个人存储和任务均正常；
- 再删除旧开发机；
- 删除前最后运行一次 `rsync -n` 校验。

## 平台管理员：把旧存储标识改成邮箱前缀

存量用户可能仍使用 `u<用户ID>` 目录。平台管理员进入 **账号与组织 → 用户管理**：

1. 确认用户邮箱正确；
2. 空目录且没有在线机器：直接点击“存储标识改为 `<邮箱前缀>`”；
3. 有数据：先在对应资源区把旧目录移动/同步到新目录；
4. 停止或重建仍引用旧路径的机器；
5. 再在确认框中完成改名；
6. 新建一台 1 卡机器，验证 `/personal_fast_storage` 指向新目录。

平台只修改目录标识，不会自动搬运云端数据。

## 公共存储当前状态

公共存储统一挂载为 `/public_fast_storage`，与项目无关，每个资源区 512 GiB：

- 资源区6：已就绪，创建 H100 开发机时可选（RTX 5090 在另一个地域，没有共享文件存储，不提供个人存储和公共存储）；
- 资源区5：已就绪（2026-09-07 起，挂在共享文件存储的 `test/public_fast_storage` 子目录）；
- 资源区1–4：暂不能由平台自动挂载。

公共存储也不会跨资源区同步。个人资料、未公开数据和唯一副本不要放入公共存储。

## 迁移完成的验收标准

- [ ] 钉钉邮箱已获取，个人存储标识是邮箱前缀；
- [ ] 新机属于预期资源区、规格为 1 卡；
- [ ] 无项目用户可以正常创建；
- [ ] SSH 可连接；
- [ ] `/personal_fast_storage` 已挂载且可读写；
- [ ] 旧机重要数据已复制并用 `rsync -n` 校验；
- [ ] 资源区1–4的 `/root` 不保留唯一数据；
- [ ] 新机稳定使用 7 天后再删除旧机。

## 开发机停机后管理文件

资源区5 开启平台服务后，可直接进入 **我的存储 → 文件** 浏览和下载个人存储、访问已授权的公共存储，自己的开发机可以保持关机。页面显示“经平台服务访问”时，文件操作由平台的专用机器完成；不会向你开放该机器的终端或其他用户的个人存储。

使用共用目录的个人存储超额时，仍可删除不需要的文件、重命名，以及下载后编辑并上传同名文件进行覆盖修改。新增上传和新建目录会暂时禁用；用量重新统计并回到额度内后恢复。覆盖修改需要足够的临时空间，空间不足时请先删除不需要的数据。网页传输和单次递归删除有上限，大目录批量迁移或清理请联系平台管理员。

只有用户自己的运行机器可用的资源区，继续使用原来的文件访问方式。平台服务不可用时页面会提示，不会自动启动你的开发机。

已有独立存储空间的个人存储由云端配额限制实际容量，不会因为超过平台默认个人额度而暂停开机、新增上传或新建目录。页面显示云端实际配额；云端空间不足时，仍需清理文件或由平台管理员调整云端配额。迁移核验、目录隔离和挂载权限检查继续生效。

每个人只能操作自己的个人存储；平台服务的专用机器同时挂载多个目录，也不会给用户其他人的文件权限。迁移后的旧目录作为只读副本保留，请在当前个人存储中继续整理文件。
