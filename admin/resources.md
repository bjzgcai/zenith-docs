# 资源全局监控与纳管资源

本页面向运维和平台管理员。Zenith 将“能够从厂商看到的资源”和“当前组织确认拥有或可管理的资源”分开呈现，避免把只读可见资源误认为可操作资源。

::: warning 先区分两种口径
“资源全局监控”展示当前账号能够读取的较大范围厂商清单；“纳管资源”是管理员确认的实际可管清单。全局监控中出现一项资源，不代表组织拥有它，也不代表可以对它执行变更。
:::

## 页面范围

运维和平台管理员可以从左侧导航访问：

- **存储管理：** 查看和管理文件存储、对象存储、授权、挂载盘、个人存储与跨区传输（见下文）。
- **队列管理：** 查看队列可用区、资源配额、工作负载、共享情况和用途；队列详情中可看到所属资源组。原「资源组」页已并入这里，旧链接会自动跳转。
- **纳管资源**（侧栏「算力」组，仅平台管理员）：维护由平台管理的队列、资源池或区域记录。
- **算力规格**（侧栏「算力」组，仅平台管理员）：把平台管理的资源映射为面向组织用户的 GPU 型号和卡数，并配置平台顺序。

这些页面主要用于观察、筛选和治理。厂商侧的购买、续费、资源组变配和队列创建等高风险操作，只有在控制台明确开放时才可执行；未开放时应按组织流程在对应厂商侧完成。

## 开发机公网带宽限制

运维管理员和平台管理员可在已启用此能力的火山 MLP 开发机详情中展开 **公网带宽限制**，
核对当前内网 IP，分别设置 **下载（入带宽）** 和 **上传（出带宽）** 的 Mbps 上限。
未勾选的方向不限速；取消所有带宽限制请使用 **取消带宽限制**。普通用户和项目管理员不显示此入口，
百度等尚未适配的资源区也不显示。

该功能需要部署人员先配置开发机实际使用的公网 NAT 网关并开放相应云端权限。它只限制经过该网关的
公网流量，不调整共享带宽包容量，也不保证最低带宽。若已有默认规则、网段规则或已识别的连接数限制，
请在云平台核对处理。

限速调整会立即影响网络，可能造成已有连接波动。规则绑定当前 IP：开发机重启、停止、删除或地址变化后，
需要重新检查并在云平台处理旧 IP 规则，防止地址复用后影响其他机器。**取消带宽限制会保留云端 IP 规则**，
以免删除连接数限制，因此仍占用规则配额。若保存超时或提示状态变化，先刷新确认结果，再决定是否重试。

## 存储管理

平台管理员和运维从左侧导航 **存储管理** 进入唯一的存储管理入口。页面顶部的资源区筛选写入链接，
**刷新** 只刷新当前标签页。运维只看到「概览」「文件存储」「对象存储」，并且只能查看。

存储清单和用量由平台定时采集（文件系统约每 5 分钟、Fileset 约每 2 分钟、存储桶约每 5 分钟）。在「概览」和「文件存储」点 **刷新**，会请平台尽快重新采集当前资源区的文件系统、Fileset 和存储桶列表；采集期间工具栏显示“采集中”，完成后自动更新，最长等待约 1 分钟。工具栏的“更新于”是数据的采集时间，“数据可能过期”表示超过两个采集周期没有更新。刚请求过采集时 **刷新** 会暂时禁用，鼠标悬停可看到剩余秒数。

| 标签页   | 内容                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| 概览     | 平台管理存储单元、已用合计、超额用户、待审批扩容四个指标，以及用途分布和云盘配额       |
| 文件存储 | 平台管理的文件系统下的全部存储单元（科研文件、Fileset、存储卷），可调整配额、授权、登记挂载盘 |
| 对象存储 | 存储桶（含公共存储桶、启用与用户目录挂载开关、文件浏览、临时凭据）与分享记录           |
| 授权     | 公共存储桶、项目绑定、用户目录授权、挂载盘分配和 Fileset 授权合并成一张表              |
| 挂载盘   | 已登记卷的分配、启用与删除登记                                                         |
| 个人存储 | 每位用户在各资源区的用量与额度，以及清理时段、统计承载机和公共存储清理策略             |
| 跨区传输 | 迁移任务与数据快传（预览）                                                             |

「平台管理」指由平台分配和操作的存储；「仅监控」只能查看。「未使用」表示存储单元没有被任何
用户、项目或挂载盘引用。待审批的云盘扩容在 **工单受理 → 云盘扩容审批** 中处理。

### 对象存储

存储桶表按资源区列出全部桶。点击桶名或「浏览」打开文件浏览：可按名称前缀搜索当前目录、逐页翻看，
也可以切换到「未完成分片」批量清理。停用桶、关闭用户目录挂载、移出平台管理和清空公共存储桶前都会
确认，并写明受影响的项目绑定和用户授权。

管理员浏览对象时应遵循最小必要原则：不要下载与任务无关的数据，不要在截图或工单中暴露对象内容、签名链接或个人目录信息。

### 文件存储

文件存储表的数据来自存储清单快照，不会自动刷新；配额或新建操作完成后，相关行会立即显示云端的最新值。
容量和用量以厂商返回值为准；没有容量字段不等于容量为零。缩小或取消配额前会二次确认。

「新建 Fileset」只对平台管理员开放。从 Zenith 新建火山 Fileset 时，会自动为平台云端账户配置读写挂载权限。
若提示「挂载授权结果未知」，目录已经存在，不要重复新建；请按提示核对后在火山 MLP 补齐平台账户权限。
直接在火山控制台创建的 Fileset 需先纳管并完成云端授权。

在 **存储管理 → 文件存储** 中，对资源区5 的 Fileset 点「挂载授权」，可为整体或已有子目录授权用户或项目，已有项目绑定继续保留。
按[Fileset 共享与个人授权图文指南](/data/fileset-access)完成路径核对、读取和保存；此操作不会创建目录或自动修改云端权限。

### GPU 卡池

GPU 卡池按厂商返回的数据汇总 GPU 型号和容量。它与实例列表中的 GPU 占用、项目配额和计费用量使用不同口径，数字不应直接相减或当作实时可创建数量。

判断是否能创建资源时，还需同时检查队列、可用区、规格、个人/项目配额和厂商库存。

## 队列页面

队列页面可以查看：

- 队列名称、ID、状态和可用区。
- CPU、内存、GPU 和存储的总量、已分配量及共享量。
- GPU 型号等更细的配额明细。
- 当前队列关联的实例或训练负载。

共享队列中“已分配”可能大于“自有总量”，这可能是共享或超卖口径，不一定是数据错误。进入详情查看各组成部分，再与厂商侧口径核对。

管理员可修改纳管队列的 **每人标准训练 GPU 上限**，默认 64 卡。该值仅控制标准任务的后续启动，
降低上限不会停止已运行的标准任务。百度和火山的低优训练单独按用户分享空闲容量：需求充足时均分，
以 32 卡为一人的基础份额，需求不足时按实际需求，不足以安排后来用户时按本轮需求顺序等待。
收回超额份额会停止整个低优任务并按原申请卡数重新排队；再次启动会重新执行命令，程序须自行处理检查点恢复。
详见[训练等待队列](/workloads/training#每人并发卡数与等待队列)。

队列创建或变配通常涉及购买、划拨和资源组归属。当前控制台没有开放相关按钮时，请在厂商控制台按审批流程处理，不要把只读页面当成变配入口。

### 按开发机和训练用途分池

平台管理员可在「队列管理」的火山队列表中直接设置「用途」列，无需展开整机训练预留：

1. 先确认队列为「平台管理」，属于预付费队列，且只有一种 GPU 型号。
2. 完成或停止该队列的现有负载，等待运行占用和未完成调度全部释放；状态不明时先核对处理。
3. 在该队列的「用途」列选择“开发机 / 小卡训练（1 / 2 卡）”、“训练（每工作节点 4 卡或 8 卡）”或“训练（每工作节点 8 卡）”，然后保存。
4. 刷新核对结果。若其他管理员同时修改，页面会读取最新配置，再由你决定是否继续修改。

随后在「算力规格 → 配置路由」中分别绑定目标队列：1/2 卡规格绑定开发机池，4/8 卡规格绑定另一条训练池队列。
1/2 卡路由的“承接训练任务”默认关闭，必须明确开启才会成为训练候选；旧路由缺少此设置时也按关闭处理。
首批仅开放一个队列时，只对该队列的 1 卡和 2 卡路由开启训练，其他 1/2 卡路由一律关闭训练（包括以前已开启的路由），
仍可保留开发机能力。关闭唯一的小卡训练路由后，新任务不会回退到未开启训练的开发机路由。4/8 卡路由的默认行为不变。
队列用途只限制准入，不会自动新建或启用规格路由。目标资源组由所选队列在云端的归属决定；若路由填写了资源组 ID，
必须与该队列匹配。平台不按队列名称或资源组显示名称猜测分流，也不会移动队列的物理资源组归属。

开发机池接受单台 1 或 2 卡开发机，也可接收每节点 1 或 2 卡训练任务，并共享容量。小卡训练须确认
云端队列同时支持开发机和训练，且已配置启用训练的规格路由与训练镜像。训练按每节点卡数分池，
例如 2 卡 × 4 节点仍走开发机池。大卡训练池按每个工作节点检查，允许多个工作节点。例如，
两份 8 卡工作节点可使用 8 卡训练池，八份 1 卡工作节点则不可以。“4 卡或 8 卡”档同时接受每工作
节点 4 卡与 8 卡，因此 8 卡节点上要么跑一份 8 卡工作负载，要么跑两份 4 卡工作负载，空闲卡数
始终是 4 的整数倍，不会剩下 1~3 卡无法使用。队列的 GPU 总数不是该档位最小卡数的整数倍时，
保存会被拒绝，需要先按厂商侧实际配额核对。训练任务仍不受开发机每人 2 卡上限约束，但需要
足够卡时和可用容量。普通与低优任务都遵守用途限制。

**“4 卡或 8 卡”档按 8 卡节点设计**，4 卡工作节点占用半个节点。平台当前纳管的火山计算资源均为
整台 8 卡节点，且纳管队列由 Zenith 独占、不在火山控制台直接提交任务，因此这一前提成立。需要
注意这是运维约定而非平台校验：平台不核对节点构成，也不会察觉绕过平台的提交。该档还需要目录里
存在 4 卡规格，并已分配给对应组织、绑定了启用训练且已登记训练镜像的路由，否则 4 卡不会出现在
创建页。

表格同时显示每个平台管理队列在厂商侧的标记（开发机 / 训练任务 / 开发机 + 训练），便于按云端
声明来选择用途；云端的工作负载标记不包含具体卡数，4 卡还是 8 卡始终由管理员决定。尚无用途
配置的队列显示“未配置（按通用准入）”，页面会提示有多少训练队列仍未配置——这些队列仅接受
每节点 4 或 8 卡训练任务。实时队列清单无法覆盖的队列显示“未知”，平台不会用其他队列的标记去猜测。

原有队列从未设置用途时显示“未设置（按通用处理）”，沿用原有准入规则；只有管理员明确选择“通用（不按用途分池）”后才显示为通用。队列表的「负载类型」列显示云端队列支持的开发机 / 训练任务；点「修改」时，只支持开发机的队列默认选中“开发机 / 小卡训练（1–2 卡）”，只支持训练任务的队列默认选中“训练（每节点 4 或 8 卡）”，并标注「建议」。切回通用不会取消个人额度、权限或
开发机限制。配置失败不会自动停止或迁移负载。此功能只约束通过 Zenith 提交的资源；在厂商
控制台直接操作仍需管理员协调。

**无论 4 卡还是 8 卡档，训练规格都不等于已获得物理整节点预留保障。** 用途配置不会购买资源
或确认付费预约，也不能将零散 GPU 配额变成可随时使用的完整节点。具体预留规则见[学生额度与
预留制度](/projects/student-resource-policy)。

## 资源组

原「资源组」页已并入「队列管理」（`/resource-groups` 自动跳转），队列详情显示所属资源组。核对资源组时关注：

- 当前状态和状态说明。
- 计算资源与卷资源的已分配量和总量。
- 到期时间、即将到期和容量紧张提示。
- 工作负载网络、存储网络和文件系统配置摘要。
- 关联队列及其状态。

看到“即将到期”“已到期”“容量紧张”或“容量耗尽”时，应先确认厂商侧真实状态和组织续费计划，再通知受影响项目。不要仅凭一个汇总数字直接删除或迁移用户资源。

## 纳管资源

纳管资源清单是管理员对厂商原生资源做的第一层管理边界：它定义平台可用于放置的队列、资源池和区域；普通用户不直接看到这些原生对象。管理员资源监控仍保留厂商原生全量。每条记录包含厂商、类型、资源 ID、展示名、备注、启用状态和排序。

### 添加纳管资源

1. 在侧栏「算力」组进入「纳管资源」。
2. 点击“添加纳管资源”。
3. 选择厂商和资源类型。
4. 优先从实时候选中选择资源；需要手工填写时，先在厂商页面核对完整 ID。
5. 使用用户能够理解的展示名，并在备注中记录用途或归属，不要写入密钥、账号密码或私有地址。
6. 保存后在管理员视图确认名称、状态和容量是否符合预期。无问原生池按该 `pool_id` 自身的总卡数与余卡展示，`type:H100` 等卡型聚合只用于监控，不能作为创建位置。

### 启用、停用和移除

- **停用**会让记录退出平台放置和创建范围，适合临时维护或待核验资源。
- **移除**只删除 Zenith 中的纳管记录，不会删除厂商侧真实资源。
- 为某个厂商显式纳管队列后，实例连接和终端入口可能只对这些队列中的资源开放。修改前应确认是否会影响现有用户连接。

::: warning 纳管记录不是资源购买凭证
添加记录不会在厂商侧创建资源，也不会授予额外权限；移除记录也不会释放厂商资源。任何付费、释放或权限变更都必须在对应操作入口单独确认。
:::

## 算力规格

「算力规格」是纳管资源之上的第二层配置。普通用户只看到 GPU 型号、卡数以及对应的
CPU/内存，不会看到厂商、队列、资源池、可用区或实际规格 ID。

1. 新增一个逻辑规格，例如 `NVIDIA A100 80GB × 2 卡`。
2. 选择 **配置路由**，为它绑定一个平台管理的精确队列或资源池。
3. 填写厂商实际规格 ID、vCPU、内存和平台顺序。数字越小越优先。
4. 如有需要，在创建参数 JSON 中填写区域、盘型、磁盘、RDMA 等附加参数；名称、镜像、
   卡数和队列/资源池由平台控制，不能在 JSON 中覆盖。
5. 在 **组织管理** 中，把逻辑规格分配给组织。

创建时平台只会考虑逻辑规格与纳管资源都启用、厂商连接在线且与所选镜像兼容的路由。
命令一旦发送，不会因超时自动切换到下一平台，以免重复创建并产生双份费用。

### 新队列已纳入平台管理，但训练创建页没有使用它

纳入平台管理只是第一层管理边界，还需要把队列绑定到已有的算力规格。只开启队列的“平台属性”，
不会自动新增训练路由，也不会自动复制默认镜像和存储配置。

1. 在「队列管理」确认新队列为「平台管理」、正在运行，云端工作负载类型支持训练任务，且有对应 GPU 配额。
2. 进入「算力规格」，为需要开放的单 Worker 规格逐一配置新队列路由。
   例如要提供 1、2、4、8 卡的 A100 Worker，这四个规格都需要绑定；“8 卡 × 8 Worker”使用的是 8 卡规格的路由。
3. 核对原生规格、资源组、已登记并启用的默认镜像以及存储所属资源区。TASK 专用路由应启用训练、
   关闭开发机；不要直接把其他资源组的队列 ID 替换进未经核对的配置。
4. 确认逻辑规格及路由已启用，使用者所在组织已分配该逻辑规格，再刷新训练创建弹窗。

创建页按资源区选择，通常不会逐个列出原生队列名。“最佳候选余量”只反映已接入训练路由的
最佳单队列，不把多个队列容量相加。因此，新纳入平台管理的队列有上百张卡、页面却仍显示旧队列的 16 卡时，
应先检查训练路由绑定。容量预检通过后，正式提交仍会检查个人/项目额度、镜像和实际挂载。

## 资源区1–4科研文件分组

在逻辑规格的天翼路由中，可以分别为「个人组」和「公共组」选择平台管理的科研文件。
两组可以先使用同一个科研文件，以后再拆成两个；绑定配置不会自动购买或扩容文件。

| 分组   | 科研文件内的源目录 | 用途                                               |
| ------ | ------------------ | -------------------------------------------------- |
| 个人组 | `/{username}`      | 科研文件根目录下直接按邮箱前缀建目录，每人一个目录 |
| 公共组 | `/public`          | 全员共享文件，不计入个人用量                       |

个人目录沿用火山的存储标识，例如学生为 `<科研文件根目录>/s-alice26`，
老师为 `<科研文件根目录>/t-teacher`，中间不增加 `users` 目录。
承载机的「用户目录子路径」留空；保存配置不会自动创建或搬移已有文件。

**存储管理 → 个人存储 → 统计承载机** 展示科研文件名称、ID、容量和分组路径。
共用一个科研文件时容量只计算一次。「已配置 · 待挂载验证」表示配置已保存，尚未开放挂载。
拆分后还需重新核对承载机的实际挂载和用量采集。

共用目录的个人用量超额后，平台暂停创建、启动和重启开发机；清理后重新采样回到额度内即可恢复。
已有独立 Fileset 的个人存储使用云端配额，不触发平台的超额开机或文件清理限制；页面显示其实际云端容量。
「尚无有效采样」表示还不能确认用量，不代表使用了零空间。

## 常见状态如何处理

| 页面提示   | 建议处理                                             |
| ---------- | ---------------------------------------------------- |
| 连接不可用 | 暂停变更，刷新后再次确认；持续失败时联系平台维护人员 |
| 不支持     | 当前厂商或产品模式没有提供该数据域，以能力提示为准   |
| 未找到     | 核对资源 ID、区域以及资源是否已被厂商侧移除          |
| 无容量数据 | 只能确认记录存在，不能把空值当作零容量               |
| 获取失败   | 记录厂商、页面、时间和完整错误提示后重试或升级处理   |

## 安全操作清单

- 变更前确认厂商、区域、资源类型和完整资源 ID。
- 区分“只读可见”“平台管理”“当前可操作”三个状态。
- 对影响连接入口、费用或大量用户的修改安排变更窗口。
- 不在备注、截图或工单中暴露凭据和私有数据。
- 变更后同时检查首页、相关资源页和实际用户路径。
- 保留操作时间、操作者和变更原因，必要时到审计日志复核。
