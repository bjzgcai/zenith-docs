# 管理员平台操作

本页面向平台管理员和运维，按左侧导航分组介绍管理页面和安全操作原则。环境凭据、私有地址和部署实现不属于公开帮助内容。

::: warning 管理员变更可能立即影响用户
角色、账号状态、配额和平台管理范围会改变用户能看到或执行的操作。保存前请确认目标用户、资源区、项目和影响范围，避免在使用高峰进行未经验证的批量变更。
:::

## 平台运维

### 平台总览

平台管理员和运维的首页，汇总开发机、GPU、训练任务、接入节点、资源区容量、分配与用量和存储摘要。详见[平台总览](/guide/dashboard)。

### 平台状态

仅平台管理员可见，分四个页签：

- **节点状态**：各资源区接入节点的连接、心跳、版本和权限检查，以及最近事件。
- **接口监测**：平台接口、个人 API、资源区命令和厂商接口的请求量、耗时与错误。
- **厂商接入**：各资源区账户余额、天翼云控制台登录和百度 SSH 路由。
- **缓存**：平台定时采集厂商数据的情况。每个资源区一行，显示采集模式、本分钟读取预算的用量、逾期例程数、各类数据（容量、队列负载、文件系统、Fileset、存储桶、镜像目录）的最近结果和最老数据的时间；展开一行可看到每个例程的完成时间、下次运行时间、连续失败次数和对应数据的年龄。服务端版本尚未提供这项数据时，页签只显示一行说明。

“例程采集”表示页面只读取平台保存的数据，厂商数据由平台定时读取；“读时采集”表示定时采集已关闭（应急回退），页面读取会直接查询厂商。“逾期例程”持续大于 0 或某类数据长时间“失败”时，先看节点状态和接口监测，再联系平台维护人员。

“在线”只表示接入节点连接和心跳正常，不表示每个厂商接口都有权限或库存。看到“心跳延迟”“权限受限”时，先看具体的权限标签，再结合平台总览判断受影响的资源。

### 站点维护

平台管理员和运维可用（左侧 **站点维护**）。维护期间全站暂停新提交，已经运行的开发机和训练任务不受影响；登录、查看和维护设置仍可使用。

“当前状态”显示状态、原因、开始时间、预计恢复时间和最后修改时间。可执行的操作取决于当前状态：

| 当前状态 | 操作 | 说明 |
| --- | --- | --- |
| 正常 | **开启维护** | 填写维护原因（所有访问者可见）和预计时长（1–10080 分钟，从现在开始计算），再确认一次后生效 |
| 维护中 | **更新说明** | 修改原因或时长，确认后生效；新说明立即对所有访问者可见，预计恢复时间从保存时重新计算 |
| 维护中 | **结束维护** | 确认后立即恢复所有新提交 |

- 到了预计恢复时间不会自动结束，需要手动点“结束维护”。
- 维护中所有页面顶部会显示一行横幅；运维和平台管理员可以从横幅进入本页。
- 如果其他管理员在你打开页面后修改了维护设置，页面会提示“维护配置已被他人更新”，并禁用所有提交。点“载入最新”后再操作，避免覆盖对方的修改。

### 发版管理

仅平台管理员可见。页面顶部一行显示目标环境、正在执行的操作和已耗时，例如“正在部署 Platform v1.2.3（10:00 开始，已 3 分钟）”。

- **组件**：每个组件的当前版本和备用版本。Platform 的“回滚到 vN”切换到备用版本，没有备用版本时按钮禁用，可在“版本”中部署指定版本。Frontend 和接入节点的“回滚到上一版本”回到主机保留的上一版本，这个版本不会显示在页面上，完成后在“历史”中核对；接入节点只能在“全部接入节点”一行一起回滚。
- **版本**：已上传的版本，可按组件筛选、按版本或 Commit 搜索。比当前版本旧的版本标为“降级”，部署确认会单独标红提示。
- **历史**：最近 20 次部署与回滚的结果、耗时和日志；“在审计中查看”打开对应的审计记录。

提交部署或回滚后：

1. 发版服务一次只执行一个操作。提交后所有部署和回滚按钮都会锁定，直到页面看到这次操作开始执行并结束。
2. 执行期间页面每 5 秒更新一次状态；切到其他标签页时暂停。
3. 操作结束时页面会提示成功或失败；失败的日志在“历史”中查看。
4. 状态读取失败时显示“状态未知”，按钮保持锁定。先点“刷新”确认当前状态，不要重复提交。

升级属于高风险操作，执行前应：

1. 核对组件、版本、Commit 和变更说明；
2. 确认目标环境和接入节点的连接状态；
3. 评估正在运行的任务、终端和文件传输；
4. 按组织变更流程审批，必要时先开启站点维护；
5. 完成后检查接入节点恢复、健康状态和关键用户路径。

### 审计日志

仅平台管理员可见，记录平台写操作和被拒绝的请求，可用于核对操作者、请求目标、结果和时间。

- 可按时间范围、用户、动作、方法、结果（成功 / 请求被拒 / 服务端错误）和关键词（路径、动作或用户）筛选，条件写在网址里，复制链接即可分享同一视图。
- 表格在服务端分页和排序，搜索覆盖全部记录。
- 点击一行打开详情：认证方式（控制台会话、API Token 或后台任务）、资源区和格式化后的请求参数。

审计日志是调查线索，不是业务状态的唯一依据。资源最终状态仍以资源列表和厂商返回为准。导出或转发前应隐藏用户标识、资源地址等敏感字段。

## 算力

开发机管理、训练任务管理、队列管理、镜像、纳管资源和算力规格的说明见[资源全局监控与纳管资源](/admin/resources)。

### 资源配额

“资源配额”只有一张“实例与 GPU 配额”表：

- **默认行**置顶，对没有单独配置的用户生效。
- **用户行**覆盖默认值；留空表示该项不限。
- 配额同时限制“运行中”和“总提交”（运行中加上启动中、排队中的请求）两个水位的实例数和 GPU 数。

超出上限时无法新建或启动，不会停止已经运行的资源。修改前先查看当前用量，并向受影响用户说明新规则。个人存储额度在“存储管理 › 个人存储”中设置，个人月度卡时额度在“额度策略”中设置。

## 账号与组织

用户管理、组织管理和项目的详细说明见[组织与项目](/account/organization)和[项目](/projects/overview)。安全要点：

- 平台角色分为平台管理员、运维、普通用户和访客（只读）。按最小权限分配，平台管理员数量应严格控制。
- 改角色、启用或禁用账号都会二次确认并立即生效，对方需要重新登录；不能修改本人的角色或启用状态。
- 禁用账号前，先确认其运行中的资源、项目职责、API Token 和交接安排。
- 批量操作逐个账号执行，部分失败不会回滚已成功的修改。结果不明确时先刷新核对，再决定是否重试。
- 不要通过聊天、工单截图或公开文档发送初始密码。

### 运维账号

把账号角色改为“运维”后，该账号默认进入运维视图，可以维护项目和普通成员、查询全平台资源、开关开发机、处理工单和站点维护。运维账号保留普通用户能力，可通过右上角视图切换使用本人的开发机、终端、文件和任务；如果同时是项目负责人或项目管理员，还能切换到项目管理员视图。

运维不能修改平台管理员权限、已有账号密码或平台凭据。个人 API Token 不继承运维权限。详见[角色、身份与权限](/reference/permissions)。

### 页面视图预览

平台管理员可在右上角切换到运维、项目管理员或用户视图，验收对应角色看到的页面。预览只改变页面显示，不改变真实权限，因此不要用预览测试服务端越权防护。

## 卡时

### 额度策略

组织额度、项目额度和个人月度额度集中在“额度策略”中配置。“不限额”表示不按卡时限制新建，额度只约束新的新建或启动请求，不会停止已经运行的资源。规则说明见[配额、卡时与费用](/projects/quotas-billing)。

### 额外卡时审核

在“额外卡时审核”处理项目的额外卡时申请（原「入账」），逐笔填写核验卡时、到期时间和核验说明。平台不处理真实金额或支付；已确认的记录只能追加更正，不能覆盖。

### 卡时监控 {#gpu-卡时使用监控}

“卡时监控”比较用户和项目当前周期的有效额度、已扣卡时和使用率。使用率 = 本周期已扣 ÷ 有效额度（已含调整与分配）。这是额度记账，不是 GPU 硬件利用率，也不是厂商账户余额。项目与用户可能重复统计同一份工作负载，不要相加。

低消耗提醒：

1. 在设置中选择是否启用、观察天数（1–365 天）和使用率阈值；默认关闭，默认参数为 7 天和 20%。
2. 可以为单个项目保存单独设置，或关闭该项目的提醒；没有单独设置的项目使用默认值。
3. 当前额度周期内已经过观察天数，且使用率低于阈值时，平台管理员会在铃铛收到提醒。

观察天数从当前额度周期内开始计算，不跨周期。例如每周重置的额度无法完成 30 天观察，页面会提示周期不足。提醒只在站内展示，不会改变额度或停止任务；同一对象、同一周期只提醒一次。平台每小时检查一次。

## 存储与数据

存储管理和数据集的说明见[存储与文件](/data/storage)和[数据集](/data/datasets)。

### 跨区传输审批

在“存储管理 › 跨区传输”打开“迁移需审批”后，新的迁移任务先进入“待审批”，管理员可以通过或拒绝。审批前至少核对：

- 申请人是否有权访问源和目标资源；
- 源和目标的资源区、开发机是否正确；
- 迁移路径是否符合组织的数据分类和跨区政策；
- 数据量、执行时间和中转成本是否合理；
- 目标位置是否已有同名文件，覆盖会有什么影响。

拒绝时填写不含敏感信息的明确原因，便于申请人修改。审批开关只影响之后新建的任务，已有的待审批记录仍需逐条处理。

## 服务台

### 工单受理

“工单受理”汇总用户从控制台或钉钉机器人提交的工单。运维可以处理的问题在平台内改状态并回复；需要改代码的问题“转交研发”，转交后工单时间线会出现带链接的记录，提交人可在“我的工单”中看到。

- 不要把密钥或未脱敏数据写进回复或转交内容。
- 平台管理员可以在页面上查看钉钉渠道状态。“已连接”只代表通道连通，不代表用户消息已经收到；是否收到以用户实际看到的回复为准。
- “云盘扩容审批”页签仅平台管理员可见。

用户侧说明见[工单与钉钉帮助](/account/feedback)。

### 公告管理

“公告管理”用于新建、编辑、发布、撤回为草稿和删除公告。公告级别分为通知、警告和严重。

- 草稿只有管理员可见。
- 发布前检查标题、时间范围、受影响的功能和给用户的行动建议。
- 不在公告中发布密码、Token、内网地址或未脱敏的故障信息。
- 撤回为草稿会停止展示；删除前确认不再需要保留内容。

## 管理员日常检查

- 账号和角色是否仍符合最小权限原则。
- 纳管资源、算力规格和配额是否与实际可用资源一致。
- 卡时额度是否需要提前通知用户调整。
- 是否有待审批的迁移、云盘扩容，或失败的操作、离线的接入节点。
- 公告内容与当前版本是否一致；维护结束后是否已手动结束维护。
- 是否有待处理或已转交研发的工单需要跟进。
- 高风险操作是否保留了审批、审计和回退依据。
